- perf(container): `container.New` no longer snapshots the process environment up front. The environment is read once, on the first provider build, so a container on the legacy config path starts without reading `.env` files, the working directory, or the process environment (the constructor dropped from ~21 us to ~1.4 us and from 45 to 7 allocations on a 220-variable environment).
- fix(container): the legacy-config warning (`zever.yaml found in working directory: ignored`) now prints when the environment is read — the first provider build — instead of at `container.New`. An app that resolves its own environment through `config.FromEnv()` still sees the warning there, and no longer sees it twice.
