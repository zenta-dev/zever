- **Breaking:** `config`: the legacy config-file probe is gone. `config.FromEnv()` no longer looks for a leftover `zever.yaml`/`zever.yml`/`zever.json`/`zever.toml` in the working directory and no longer prints the "found in working directory: ignored" warning. Service configuration comes only from `.env`, `.env.local` and the process environment, so a leftover legacy file is now completely inert: translate its stanzas into `.env` (the migration guide in `config/README.md` shows the mechanical mapping) and delete the file.
- fix(config): the config package no longer names the legacy config files anywhere — a guard test fails the build if it does — so the framework can neither stat such a file nor warn about it.
