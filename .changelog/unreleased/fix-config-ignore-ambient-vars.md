- **Breaking:** `config`: an unknown key under a wired service prefix no longer fails resolution when it is close to no known field — it is an unrelated ambient variable (`AI_AGENT`, `LOG_LEVEL`, `DB_URL`, `CACHE_DIR`) and is ignored, the same way `AGENT` and `FOO_BAR` already were. A key that is close to a known field still fails with the did-you-mean hint (`DB_MAXCONN` → `did you mean "max_conns"?`). Set `ZEVER_CONFIG_STRICT=1` to restore the v0.8 behavior of rejecting every unknown key under a wired prefix.
- fix(config): `config.Resolve`/`config.ApplyEnv` stop rejecting unrelated ambient environment variables (the flat `<SERVICE>_<FIELD>` namespace collided with `AI_AGENT`, `LOG_LEVEL`, `DB_URL` and `CACHE_DIR`, so `zever` refused to start in a noisy environment).
- feat(config): add `config.UnresolvedKeys`, which lists the env keys that were ignored so a caller (for example `zever doctor`) can report them; a key with a non-empty `Suggestion` is a near-miss typo.
