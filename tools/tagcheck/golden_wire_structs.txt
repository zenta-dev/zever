# golden_wire_structs.txt — v0.7.2 wire-struct registry for tagcheck.
#
# Format: <repo-relative package dir><TAB><struct name><TAB><v0.7.2 source file>
# Blank lines and # comments are ignored.
#
# A struct listed here carried json tags on EVERY exported field at tag
# v0.7.2, the last release before the v0.8.0 env-only config migration
# stripped them. tagcheck requires every exported field of these structs to
# keep a json tag, and fails if a listed struct disappears from the tree (a
# removal or move must update this list with a justification comment —
# deliberate and reviewable). Structs that were only partially tagged at
# v0.7.2 (intentional Go-API-only fields such as Logger or Store handles)
# are not pinnable by this list and are excluded.
#
# How this list was derived (reproducible):
#   git worktree add /tmp/zever-v072 v0.7.2 --detach
#   # AST scan of the worktree: struct types whose exported fields ALL carry
#   # a json tag, skipping _test.go files and DO-NOT-EDIT generated files
#   # (one-off helper program; the procedure is documented here so the
#   #  derivation can be re-run and audited)
#
# Reconciled against the current tree:
#   - cmd/zever/cmd/tinker-shim/* (16 structs) re-homed to cmd/zever when
#     the tinker shim merged into generate_tinker.go / tinker_protocol.go.
#   - cmd/zever/dbExecResult removed: the tinker shim is now generated into
#     user projects (tinkerShimTemplate in cmd/zever/generate_tinker.go);
#     the struct exists only as emitted template text, and the in-repo
#     protocol mirror cmd/zever/tinker_protocol.go declares the other 15
#     shim types. Its wire key ("rows_affected") is pinned by the template.
#   - cmd/zever/projectFile removed: config.Load and file discovery were
#     deleted in the v0.8.0 env-only migration, so the struct is
#     intentionally gone.
#   - cmd/zever/wiringRow and serve/doctorBattery added: both are wire
#     structs created after v0.7.2 (the CLI rewrite and the serve library),
#     so they were not in the v0.7.2 derivation. They are registered here
#     so the unregistered-wire rule can pin their keys too.
#   - shared/retry.Policy added: the retry policy is a config option that
#     the outbox and resilience batteries embed, so it reaches the
#     `zever config show --json` envelope. It gained snake_case json tags
#     (and a json:"-" on the Go-API-only OnRetry hook) so the envelope
#     shows the same key style as every other option.
#   - core/payment.Options and core/webhook.Options moved here from
#     golden_wire_exceptions.txt: their Go-API-only Idempotency store
#     handle and Logger handle gained the json:"-" tag, so both structs are
#     fully tagged now and the registry can pin their keys (the dropped
#     fields are pinned with the "-" key, like core/storage.Options.Logger).
#
# How to extend: when a NEW struct becomes a wire type (JSON request or
# response, MCP payload, doctor envelope, ...), add a line here and give
# it json tags from birth. A struct that mixes json-tagged fields with a
# Go-API-only field cannot be registered: list it in
# golden_wire_exceptions.txt with a justification instead. When a wire
# struct is removed, delete its line and say why here or in the commit
# message.
