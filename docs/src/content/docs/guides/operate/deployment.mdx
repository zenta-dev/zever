The production checklist for a tested checkout. Build once, configure per environment, run one container per process, and close it on SIGTERM. There is no build-time codegen: the `.zen` compiler runs explicitly (`zever compile`, `zever generate`) during development, never at container start.

## Build one binary

```sh
make build                                              # go build ./..., CI check
go build -o myapp ./cmd/myapp                           # one artifact per service
GOOS=linux GOARCH=amd64 go build -o myapp ./cmd/myapp   # cross-compile
```

| Target | Shape | Pick it for |
|---|---|---|
| Systemd | `ExecStart=/usr/local/bin/myapp` with `EnvironmentFile` | VMs and bare metal. |
| Kubernetes | Image plus `env:` secrets and a mounted `zever.yaml`. | Orchestrated rollouts. |
| Container image | `docker build -f examples/showcase/Dockerfile .` | Multi-stage: `golang:1.27.1-bookworm` builder (`CGO_ENABLED=0`, `-trimpath`, `-ldflags="-s -w"`), final `gcr.io/distroless/static-debian13:nonroot` with an absolute `ENTRYPOINT ["/server"]`. |
| Compose | `DB_PASSWORD=... docker compose up --build` | Scaffolded `compose.yaml` when `zever new` picks `db=postgres` or `*=redis`. Health-gated startup. |

Static builds work because sqlite is pure Go (no cgo) and the distroless static base carries CA certificates for Stripe and cloud TLS. Build from the repo root; the builder runs with `GOWORK=off`. The worker follows the same pattern with `./cmd/worker`. Build from a clean tree at a tag and keep the SBOM. Tagged releases build static binaries and SBOMs with SLSA provenance; verify before deploy:

```sh
gh attestation verify dist/zever-linux-amd64 --repo zenta-dev/zever
gh attestation verify sbom/cmd_zever.json --repo zenta-dev/zever
```

## Configure and inject secrets

Ship a strict file for structure and set secrets and per-environment deltas through env. Layering stays `defaults < file < env`, and `config.Default()` never reaches production because its crypto key is deterministic and public. See [Configuration](../configuration/).

```yaml title="/etc/myapp/zever.yaml"
db:
  adapter: postgres
  options:
    dsn: postgres://app:secret@db:5432/app
    max_conns: 20
    min_conns: 2
cache:
  adapter: redis
  options:
    addr: redis:6379
log:
  adapter: slog
observability:
  adapter: otlp
  options:
    endpoint: otel:4317
    service_name: myapp
```

```sh
DB_DSN='postgres://app:${DB_PASSWORD}@db:5432/app'
AUTH_JWT_SECRET='prod-secret-at-least-32-bytes-long'
```

Load with an explicit path (`config.Load("/etc/myapp/zever.yaml")`) so a wrong working directory cannot fall back to sqlite. Keep secrets in env or mounted files, and prefer [Secrets](../../security/secrets/) with Vault for payment credentials (SOC2 and PCI expect a real secrets manager). The `env` adapter cannot rotate at runtime: rotate by restarting with new values. Print only `cfg.RedactedServices()` at boot.

## Shut down in order

Build one container per process, resolve services in handlers, and close on SIGINT or SIGTERM:

```go title="main.go"
cfg, err := config.Load("/etc/myapp/zever.yaml")
if err != nil {
	log.Fatal(err)
}
c := container.New(cfg)

srv := &http.Server{Addr: ":8080", Handler: routes(c)}
go func() {
	if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
		log.Fatal(err)
	}
}()

<-sigCh // SIGINT or SIGTERM
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
_ = srv.Shutdown(ctx)
if err := c.Close(ctx); err != nil {
	log.Fatal(err)
}
```

`Close(ctx)` closes only resolved services, dependents first and `cache`/`queue` leaves last, joining failures with `errors.Join`. Panics surface as `container.ClosePanicError` and timeouts as `container.CloseTimeoutError`. Both are value types, so match them with value `errors.As` targets or the match never fires. A timeout parent also flushes buffered spans through `Shutdown(ctx)`. Order details: [Container](../../../concepts/container/).

The generated server (`zever generate server`) does this already: it traps SIGINT and SIGTERM, flips gRPC health to `NOT_SERVING`, calls `GracefulStop()`, runs `httpServer.Shutdown`, then closes the container on a timeout context. Load balancers stop routing before in-flight RPCs drop.

## Wire health probes

| Endpoint | Behavior | Use as |
|---|---|---|
| `GET /healthz` | Always 200, no dependency checks. | Liveness. |
| `GET /readyz` | 200 when the DB ping (3s timeout) and gRPC health succeed, else 503. | Readiness. |

```yaml
livenessProbe:
  httpGet: {path: /healthz, port: 8080}
readinessProbe:
  httpGet: {path: /readyz, port: 8080}
```

## Scale across replicas

Process-local defaults break when you add a second instance. Switch these adapters before scaling out:

| Battery | Production setting | Why |
|---|---|---|
| [Resilience](../resilience/) | `redis` | Replicas share one breaker per dependency (unique `redis.prefix` per environment). |
| [Rate limiting](../../security/ratelimit/) | `redis` | Per-instance buckets multiply the limit. |
| [Locks and idempotency](../../security/lock-idempotency/) | `redis` (idempotency also `db`) | `memory` allows double booking and duplicate effects. |
| [Outbox](../../background/outbox/) | `db` on postgres, with a `Publisher` wired through the adapter constructor | Relay claims with `FOR UPDATE SKIP LOCKED`, so any number of replicas can relay one table. A container-opened store records but cannot `Start` its relay. `cdc` needs `wal_level=logical`. Consumers dedupe through `outbox.Inbox` (delivery is at least once). |
| [Workflows](../../background/workflows/) | `postgres` | `memory` loses in-flight runs on restart. Lease-based recovery lets a second replica reclaim after a crash. Set `DSN` (empty selects sqlite for dev). |
| [Feature flags](../flags/) | `firebase` if flags change live | `static` is per-process. |

Postgres: set `max_conns` and `min_conns` (and `max_conn_lifetime`, `max_conn_idle_time`) so the summed `MaxConns` across `db`, `search`, and `vectorstore` pools stays below the server `max_connections`. TLS has a 1.2 floor when enabled, and the DSN is never logged. Use `sslmode=disable` only in ephemeral environments.

Outbound gRPC: `c.GRPCClient(target, opts...)` caches one `*grpc.ClientConn` per target and closes it with the container. Credentials fail closed (`ErrNoCredentials`). Use `WithTLS` with a CA bundle in production; `WithInsecure` is for loopback and dev only.

## Harden for production

- Set `log` to `slog` or `zerolog`, not `pretty`.
- Set `observability` to `otlp` with `endpoint: host:port` and `service_name`. The default `stdout` keeps traces on the box. The OTLP adapter sets W3C `TraceContext` and `Baggage` propagators globally, and `middleware.Tracing` makes one path-only span per request.
- Replace the `noop` permission adapter. See [Authorization](../../security/authz-permissions/).
- Set `ratelimit` `rate` and `burst` for public routes and choose a fail mode per endpoint. Generated servers chain `Recover`, `RequestLogger`, `Tracing`, then `middleware.RateLimit` when the schema enables it.
- Run `govulncheck` (blocking on `main`, informational on PRs).

<Aside type="caution" title="Never run dev tools in production">
`zever dev` is a local watcher and `zever tinker` evaluates arbitrary Go against a live container. Run the compiled binary behind your supervisor only.
</Aside>

## Run the rollout

<Steps>
1. Review the migration plan against the live database. `migrate.Plan` has no side effects, and `ComputeRollback` gives a rollback plan to keep with the release.
2. Roll out one process per container. New pods must pass `/readyz` before receiving traffic.
3. Apply migrations (`zever db migrate`, or `migrate.Apply` in code) before or with the rollout, never after traffic shifts to code that needs the new schema.
4. Verify:

   ```sh
   curl -fsS http://localhost:8080/healthz
   curl -fsS http://localhost:8080/readyz
   zever db migrate --dry-run schema/*.zen --adapter=postgres --dsn="$DB_DSN"   # expect: no DDL statements
   ```

5. Confirm `/healthz` and `/readyz` return 200 (503 means a failing DB ping or non-serving gRPC health, so hold the rollout), the release checksum is recorded in migration bookkeeping (a re-run is a no-op), and traces reach the collector.
6. Drill secret rotation: stage the new value (`DB_DSN`, `AUTH_JWT_SECRET`) in the supervisor, restart one replica, and confirm `/readyz` is 200 with the old value revoked.
7. Drill `SIGTERM`: confirm `Shutdown` and `Close` finish inside the grace period and buffered spans flush.
</Steps>

## Troubleshooting

<details>
<summary>The process starts on sqlite despite a postgres file</summary>

`Load("")` probed the wrong directory, or env overrode the adapter. Pass the explicit path and check that `DB_ADAPTER` is unset or correct.
</details>

<details>
<summary>`Load` fails with an unknown field at deploy</summary>

The file uses a pre-rename key (`maxconns`) or a typo. Rename to snake_case (`max_conns`) and check the [config reference](../../../reference/config/).
</details>

<details>
<summary>SIGTERM hangs past the grace period</summary>

`Close(ctx)` has no deadline, or an adapter blocks. Wrap shutdown in `context.WithTimeout` (about 10s) and check the blocking adapter's `Close`.
</details>

<details>
<summary>Traces never arrive in the collector</summary>

`observability` is still on the `stdout` default. Set `otlp` with `endpoint` as `host:port` (no scheme) and a `service_name`.
</details>

<details>
<summary>Secrets appear in supervisor logs</summary>

Raw options were printed at boot. Print `cfg.RedactedServices()` only, and audit `log.Fatal(err)` paths for echoed values.
</details>
