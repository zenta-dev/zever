Build once, configure per env, run one container per process, close on SIGTERM. The `.zen` compiler runs explicitly (`zever compile`, `zever generate`) in development, never at container start.

## Build one binary

```sh
make build                                              # go build ./..., CI check
go build -o myapp ./cmd/myapp                           # one artifact per service
GOOS=linux GOARCH=amd64 go build -o myapp ./cmd/myapp   # cross-compile
```

| Target | Shape | Pick it for |
|---|---|---|
| Systemd | `ExecStart=/usr/local/bin/myapp` with `EnvironmentFile` | VMs. |
| Kubernetes | Image plus `env:` secrets and `.env` ConfigMap. | Rollouts. |
| Container image | `docker build -f examples/showcase/Dockerfile .` | Multi-stage: `golang:1.27-trixie` builder (`CGO_ENABLED=0`, `-trimpath`, `-ldflags="-s -w"`), final `gcr.io/distroless/static-debian13:nonroot` with an absolute `ENTRYPOINT ["/server"]`. |
| Compose | `DB_PASSWORD=... docker compose up --build` | Scaffolded `compose.yaml` when `zever new` picks `db=postgres` or `*=redis`. Health-gated. |

Static builds work: sqlite is pure Go (no cgo). Distroless carries CA certs. Build from the repo root with `GOWORK=off`. Worker uses `./cmd/worker`. Build from a clean tagged tree and keep the SBOM. Tagged releases ship static binaries and SBOMs with SLSA provenance. Verify before deploy:

```sh
gh attestation verify dist/zever-linux-amd64 --repo zenta-dev/zever
gh attestation verify sbom/cmd_zever.json --repo zenta-dev/zever
```

## Configure and inject secrets

Ship an `.env` for structure. Set secrets and per-env deltas via env. Layering: `defaults < .env < .env.local < process env`. `config.Default()` never reaches production (deterministic public crypto key). See [Configuration](../configuration/).

```sh
DB_DSN=postgres://app:secret@db:5432/app
DB_MAX_CONNS=20
DB_MIN_CONNS=2
CACHE_ADDR=redis:6379
OBSERVABILITY_ENDPOINT=otel:4317
OBSERVABILITY_SERVICE_NAME=myapp
```

```sh
DB_DSN='postgres://app:${DB_PASSWORD}@db:5432/app'
AUTH_JWT_SECRET='prod-secret-at-least-32-bytes-long'
```

Resolve via `config.FromEnv()` so a wrong working directory cannot fall back to sqlite. Keep secrets in env or mounted files. Prefer [Secrets](../../security/secrets/) with Vault for payment credentials (SOC2 and PCI expect a real secrets manager). The `env` adapter cannot rotate at runtime: restart. Print only `cfg.RedactedServices()` at boot.

## Shut down in order

Build one container per process, resolve services in handlers, and close on SIGINT or SIGTERM (same boot and shutdown sequence as above):

```go title="main.go"
env, err := config.FromEnv()
if err != nil {
    log.Fatal(err)
}
cfg, err := config.Resolve(env)
if err != nil {
    log.Fatal(err)
}
c := container.New(cfg, app.Providers()...)

srv := &http.Server{Addr: ":8080", Handler: routes(c)}
go func() {
    if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
        log.Fatal(err)
    }
}()

<-sigCh // SIGINT or SIGTERM
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
_ = srv.Shutdown(ctx)
if err := c.Close(ctx); err != nil {
    log.Fatal(err)
}
```

## Health probes

Wire `/healthz` and `/readyz`:

```go
r.HandleFunc("/healthz", func(w http.ResponseWriter, _ *http.Request) {
    w.WriteHeader(http.StatusOK)
})
r.HandleFunc("/readyz", func(w http.ResponseWriter, r *http.Request) {
    if err := c.DB().Ping(r.Context()); err != nil {
        http.Error(w, "db", http.StatusServiceUnavailable)
        return
    }
    w.WriteHeader(http.StatusOK)
}
```

Liveness on `/healthz` (no deps). Readiness on `/readyz` (3s db timeout). In Kubernetes, the `readinessProbe` timeout must exceed the db timeout.

## Graceful shutdown

On SIGTERM the generated server flips gRPC health to `NOT_SERVING`, calls `GracefulStop()`, shuts HTTP down, and closes the container within a 10s grace. Keep `terminationGracePeriodSeconds` above that plus any `preStop` delay.

A short `preStop` delay lets endpoint removal propagate before SIGTERM. The distroless image has no shell. The example uses the native `sleep` lifecycle handler (Kubernetes 1.30+). On older clusters, add a tiny static sleep binary.

## Config reload

Log level and rate limiter swap on SIGHUP. Everything else needs a rollout (`kubectl rollout restart deployment/myapp-server`).

## Scaling

Run >1 replica only with shared-state adapters (`redis`, `db`) for cache, queue, session, lock, rate-limit. `memory` state splits per pod. With >1 scheduler replica, wire a locker so a cron slot fires once, else run scheduler in one replica. Scale workers on queue depth (`queue.Length`) with KEDA, not CPU. See [Choosing batteries](../../extend/choosing-batteries/).

## Migrations

Run `zever db migrate` as one Kubernetes Job per release before rollout (or pipeline init step), never in every pod. A failed migration blocks rollout.

## Profiling and debugging

Generated server exposes pprof on a loopback-only listener (`--pprof-addr`). In a cluster, set `PPROF_ADDR=127.0.0.1:6060` and reach via port-forward:

```sh
kubectl port-forward deploy/myapp-server 6060:6060
go tool pprof http://127.0.0.1:6060/debug/pprof/heap
```

See [Profiling with pprof](../observability/#profiling-with-pprof). Never run `zever tinker` against production.

## Hardening checklist

- [ ] Distroless, non-root
- [ ] Read-only rootfs, drop ALL capabilities
- [ ] Secrets in Secret (not ConfigMap), rotate by restart
- [ ] Readiness probe with db timeout
- [ ] Liveness on `/healthz` (no deps)
- [ ] `preStop` delay + `terminationGracePeriodSeconds`
- [ ] NetworkPolicy: deny all egress except db, redis, otel, allowed APIs
- [ ] `PodDisruptionBudget` with `minAvailable`
- [ ] Rolling restart for config changes (SIGHUP only reloads log/ratelimit)
- [ ] Migrations as separate Job before rollout
