`resilience` stops one failing dependency from taking down the process: a `Manager` hands out `Guard` values wrapping every call in a fixed chain (timeout, bounded retries, circuit breaker, bulkhead), one per dependency to isolate failures.

## Quick start

```go title="main.go"
import (
    "context"
    resilienceinproc "github.com/zenta-dev/zever/adapters/resilience/inproc"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/resilience"
)

c := container.New(config.Default(), container.Provide(resilience.DefaultRef(), resilienceinproc.New))
m, err := c.Resilience()
if err != nil {
    panic(err)
}
defer m.Close()

g, err := m.Guard("payments")
if err != nil {
    panic(err)
}
v, err := resilience.Do(context.Background(), g, func(context.Context) (string, error) {
    return "ok", nil
})
fmt.Println(v, err)
```

Output:

```text
ok <nil>
```

`Guard(name)` creates guards lazily from the template `Options`, returning the same guard per name. `resilience.Do` wraps `Guard.Execute`. `Guard.Close` and `Manager.Close` are idempotent.

## Understand the policy chain

Policies compose outermost to innermost (`Timeout -> Retry -> Breaker -> Bulkhead -> fn`). The timeout bounds everything including retries.

Match sentinels with `errors.Is`:

| Error | Meaning |
|---|---|
| `ErrOpenState` | Breaker open. |
| `ErrTooManyRequests` | Half-open probe limit hit. |
| `ErrBulkheadFull` | No slot in wait budget. |
| `ErrTimeout` | Overall budget exceeded. |
| `ErrClosed` | Closed guard or manager. |
| `ErrNoSharedState` (`adapters/resilience/redis`) | Shared breaker state unreadable. |

`context.Canceled`/`context.DeadlineExceeded` skip breaker counts and retries, so a client hangup never trips the circuit. Classify business errors that must not trip the breaker (e.g. validation rejections) as success with `BreakerOptions.IsSuccessful`.

## Configure the guards

`Default()` enables every policy with bounded values (5s timeout, 3 attempts, 100 concurrent, 1s wait): a safe start, not a tuning endpoint. File durations are integer nanoseconds. Keys: [resilience config reference](../../../reference/config/#resilience).

```sh
RESILIENCE_TIMEOUT=5s
RESILIENCE_BREAKER_ENABLED=true
```

`retry` is a `retry.Policy` with snake_case json tags. Its env keys match case-insensitively (`RESILIENCE_RETRY_BASEDELAY` and `RESILIENCE_RETRY_BASE_DELAY` both set `BaseDelay`). `Validate` rejects negative timeouts and bulkhead budgets, retry jitter outside [0,1], breaker ratios outside [0,1], and bad Redis prefixes. Template options apply to every guard a manager creates. Open one manager per dependency class when thresholds differ.

## Share breaker state

`memory` (default) is process-local: each replica trips alone. Use `redis` when replicas on the same dependency should trip together. Only breaker state is shared. Timeout, retry, and bulkhead stay process-local.

```sh
RESILIENCE_BREAKER_ENABLED=true
RESILIENCE_REDIS_ADDR=127.0.0.1:6379
RESILIENCE_REDIS_PREFIX=resilience
```

The redis adapter pings at construction (3s budget), failing closed when Redis is unreachable. Live redis tests need `REDIS_ADDR`. Adapters: `memory` (`adapters/resilience/inproc`, default), `redis` (`adapters/resilience/redis`, distributed state).

## Production checklist

- `Manager.Close() error` takes no context. The container joins errors via `errors.Join`. Panics surface as `*ClosePanicError`.
- Guard names and options carry no credentials. Never log raw option maps (use `cfg.RedactedServices()`).
- Feed breaker transitions to [Observability](../observability/) via `OnStateChange`.

## Troubleshooting

<details>
<summary>The breaker never opens under load</summary>

`failure_ratio`/`min_requests` assume meaningful volume. Low-traffic dependencies trip on `consecutive_failures` (lower it).
</details>

<details>
<summary>Calls fail with `ErrTimeout` before the dependency deadline</summary>

The guard timeout wraps retries: keep `timeout` above `Retry.BaseDelay * Retry.MaxAttempts` plus dependency latency, or lower `Retry.MaxAttempts`.
</details>

<details>
<summary>`ErrBulkheadFull` under burst</summary>

`max_concurrent` is too low, or `max_wait` shorter than a slot takes to free. Raise `max_concurrent` before `max_queue`: an unbounded queue turns a burst into a latency bomb.
</details>

<details>
<summary>The redis adapter fails to open</summary>

The constructor pings Redis (3s budget) and fails closed. Check `addr`. Use one prefix per environment: shared prefixes share breaker state.
</details>
