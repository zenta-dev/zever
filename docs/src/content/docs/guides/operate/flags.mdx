`flag` is a typed switch safe in hot handlers: `Bool`, `String`, `Int`, `JSON` lookups against per-request context from `WithEvalContext`. A missing key returns your fallback with a nil error.

## Quick start

`static` (default) loads a JSON file once, with no per-evaluation network cost: tests, offline dev, rollouts shipped with a deploy.

```sh
FLAG_STATIC_PATH=data/flags.json
FLAG_STATIC_RELOAD=false
```

```go title="main.go"
import (
    "context"
    flagstatic "github.com/zenta-dev/zever/adapters/flag/static"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/flag"
)

c := container.New(config.Default(), container.Provide(flag.DefaultRef(), flagstatic.New))
f, err := c.Flag()
if err != nil {
    panic(err)
}
defer f.Close()

ctx := flag.WithEvalContext(context.Background(), flag.EvalContext{
    RandomizationID: "user-123",
    Signals:         map[string]any{"plan": "pro"},
})
on, err := f.Bool(ctx, "new_checkout", false)
fmt.Println(on, err)
```

Output (empty set, fallback applies):

```text
false <nil>
```

An empty static `path` is valid and means an empty flag set. A `false` fallback keeps old behavior through a missing key or outage.

## Flip flags without a deploy

Use `firebase` to change a flag live: a real dependency, 30s default operation timeout (`DefaultTimeout`). File durations are integer nanoseconds.

```sh
FLAG_FIREBASE_PROJECT_ID=my-project
FLAG_FIREBASE_SERVICE_ACCOUNT=/run/secrets/firebase.json
FLAG_FIREBASE_TIMEOUT=30s
```

`Validate` rejects only a negative `firebase.timeout` (zero means the default). Adapters: `static` (default, `adapters/flag/static`), `firebase` (Remote Config, `adapters/flag/firebase`, needs `project_id` and `service_account`). See [flag config reference](../../../reference/config/#flag).

## Production checklist

- `Flag.Close() error` takes no context. The container probes it during `Close(ctx)`, joining errors and surfacing panics as `*ClosePanicError`.
- `static` is per-process: changes land only where the file lands (plus `reload` when enabled). `firebase` is the shared source of truth: design fallbacks so every replica degrades the same way when unreachable.
- Never log raw option maps (use `cfg.RedactedServices()`). The service account is a file path, not key material. Keep it out of logs.

## Troubleshooting

<details>
<summary>A flag always returns the fallback</summary>

Check the static file `path` against the working directory (empty or missing means an empty set by design) and the key spelling. Hierarchies such as `billing.checkout_v2` avoid collisions.
</details>

<details>
<summary>Type mismatch error on an existing key</summary>

Stored JSON type and accessor disagree (`String` on a bool key returns the fallback plus an error). Align the file value with the call, or read `JSON`.
</details>

<details>
<summary>Firebase open fails or times out</summary>

Verify `project_id`, the `service_account` JSON path, and egress to the Remote Config endpoint. Only a negative timeout fails `Validate`, so a hang is a network problem.
</details>
