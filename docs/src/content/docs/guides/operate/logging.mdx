Every service logs through `log.Logger`. Swapping the wired backend changes every line with no call-site changes (`noop` tests, `slog` stdlib, `zerolog` high-throughput JSON, `pretty` local dev). Resolve one logger per process and inject it.

## Quick start

`min_level` is the only option. `Options.Validate()` accepts the zero value. The backend comes from `container.Provide` in `internal/app/wiring.go`, never config.

```go title="main.go"
import (
    logslog "github.com/zenta-dev/zever/adapters/log/slog"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/log"
)

c := container.New(config.Default(), container.Provide(log.DefaultRef(), func(o log.Options) (log.Logger, error) {
    return logslog.New(o), nil
}))
logger, err := c.Log()
if err != nil {
    return err
}
handler := middleware.RequestLogger(logger)(mux)
```

No `Close`. Logging probes as a no-op in `c.Close(ctx)`. Keys: [log config reference](../../../reference/config/#log).

## Write typed fields

`Event` has one typed method per kind.

```go title="handler.go"
logger.Info().Str("user_id", userID).Dur("duration", elapsed).Msg("request handled")
logger.Error().Err(err).Msg("failed to process order")

if logger.Enabled(log.LevelDebug) {
    logger.Debug().Any("payload", expensiveToCompute()).Send()
}
```

```text
level=INFO msg="request handled" user_id=u_123 duration=12ms
```

Prefer `Str`/`Int`/`Dur` over `Any` for hot fields (`Any` uses reflection). Reserve `Any` for dynamic payloads. Never pass request bodies, headers, or config maps. `RequestLogger` emits one line per request (method, path, status, fractional `duration_ms`, plus `request_id`). `Recover` logs panics with value and stack, then responds 500. Emit one line per failure, with no duplicates.

API: `Logger` exposes Debug/Info/Warn/Error/Fatal/With/WithContext/Enabled/Sync/Name. `Event` exposes Str/Int/Int64/Float64/Bool/Dur/Time/Err/AnErr/Any/Msg/Msgf/Send. Helpers: `log.ContextWithLogger`, `log.FromContext`, `container.Provide(log.DefaultRef(), logslog.New)`, `middleware.RequestLogger`.

`log.ContextWithLogger(ctx, logger)` carries only the logger value. `log.FromContext(ctx, fallback)` returns it or the fallback, so attached fields survive the call chain.

## Keep secrets out of logs

Never pass raw config or headers into `Any` (may print DSNs and keys). Use `cfg.RedactedServices()` and fixed field names, including in error text. See [Configuration](../configuration/).

## Production checklist

- One process, one backend: `slog` stdlib-only, `zerolog` high-throughput JSON, `pretty` local shells, `noop` tests.
- Buffered providers flush via their own `Shutdown(ctx)`, probed by `c.Close(ctx)`. Never exit before `Close` returns or trailing lines drop.
- Shutdown never blocks past 5s per service (or the parent deadline). Keep log I/O fast. No unbounded payloads.

## Troubleshooting

<details>
<summary>No log output in tests</summary>

Wired backend is `noop` for hermetic tests. Assert behavior, not lines, or wire `slog` explicitly.
</details>

<details>
<summary>`request_id` is missing from lines</summary>

Context logger never attached. Wrap the context with `log.ContextWithLogger` in middleware.
</details>

<details>
<summary>Secrets in log files</summary>

Raw config or headers passed into `Any`. Use `cfg.RedactedServices()` and fixed field names.
</details>

<details>
<summary>Expensive debug work on hot paths</summary>

Fields compute even when the level is off. Gate with `logger.Enabled(log.LevelDebug)`.
</details>

<details>
<summary>Trailing lines lost at exit</summary>

Process exited before `c.Close(ctx)` finished. Defer `Close` with a timeout parent.
</details>
