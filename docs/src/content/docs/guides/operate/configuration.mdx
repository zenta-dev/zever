Zever reads all service configuration from **environment variables only**. There are **no config files** (`zever.yaml`, `.yml`, `.json` are ignored).

## Quick start

Layers (later wins): `defaults < .env < .env.local < process environment`.

- **defaults**: `config.Default()` — zero-infra adapters (sqlite, slog, stdhttp, memory caches, etc.)
- **`.env`**: project-committed example + local overrides (gitignored)
- **`.env.local`**: machine-local overrides (gitignored, higher priority)
- **process environment**: highest priority, no file I/O

```sh
DB_ADAPTER=postgres
DB_DSN=postgres://app:secret@db:5432/app
DB_MAX_CONNS=20
CACHE_ADAPTER=redis
CACHE_ADDR=redis:6379
AUTH_ADAPTER=jwt
AUTH_JWT_SECRET=prod-secret-at-least-32-bytes-long
```

## Resolve from env

```go
env, err := config.FromEnv()        // reads .env, .env.local, process env
resolved, err := config.Resolve(env) // typed Config
container.New(resolved, app.Providers()...)
```

`config.LoadEnv(files...)` is the explicit-file variant of `FromEnv`: it
parses the dotenv files you name (no `.env`/`.env.local` discovery, no
process environment) and returns an `Env` map, so it feeds `config.Resolve`
the same way.

## Map environment variables to keys

Env names carry no prefix: `<SERVICE>_<FIELD>`, uppercased.

- Default instance: `SERVICE_FIELD` (e.g., `DB_ADAPTER=postgres`)
- Named instance: `SERVICE__NAME__FIELD` (e.g., `DB__ANALYTICS__DSN=...`)

A named instance only reaches the container through a matching named Ref
(`db.Ref("analytics")`) wired with `container.Provide`; the default instance
reads the flat `SERVICE_FIELD` namespace.

Matching ignores case and `_`, so `MAX_RETRIES` matches `MaxRetries` and
`DB_MAX_CONNS` matches `DB_MAXCONNS`. One nesting level splits at the first `_`: `AUTH_JWT_SECRET` sets `Options.JWT.Secret`.

Durations accept `"5s"` strings in env; there is no integer form.

## Migration from v0.7

| v0.7 | v0.8 |
|------|------|
| `zever.yaml` | `.env` + `wiring.go` |
| `config.Load("")` | `config.FromEnv()` + `config.Resolve(env)` |
| `ServiceConfig.Adapter` | wired in `wiring.go` via `container.Provide` |
| `DB_MAXCONNS` | `DB_MAXCONNS` (same) |
| `DB__ANALYTICS__DSN` | `DB__ANALYTICS__DSN` (same format) |
| `zever doctor --config` | `zever doctor` (no flag) |

## Legacy file warning

If `zever.yaml`/`.yml`/`.json` exists in the working directory, `config.FromEnv()` prints a one-line warning:

```
config: zever.yaml found in working directory: ignored; see migration guide in config/README.md
```

The file is **ignored entirely** — no values are read from it.

## Generated env template

`zever new` and `zever add` generate `.env.example` with every env key, default value, and comment. This is the authoritative source for what env vars each service accepts.

## Redact config before printing

Raw option maps may hold secrets. `(*Config).RedactedServices` (built on `Redact`) is the sole display path: error text names services and fields only, and `zever config show` prints one `<service>  adapter=<x>` header per service plus its masked options, then a `<service>/<NAME>` section per named instance.

```go title="main.go"
for name, sc := range cfg.RedactedServices() {
    fmt.Println(name, sc.Adapter, sc.Options)
}
```

<Aside type="danger" title="Dev-only keys">
`Default()` belongs in local dev and tests: its crypto key is deterministic and public. Supply `AUTH_JWT_SECRET`, the crypto key, and provider keys from env or a mounted file in production.
</Aside>

## Know the defaults

Defaults pick the zero-infra adapter per service (`db` sqlite, `cache`/`queue`/`session` memory, `storage` local, `log` slog, `observability` stdout, `payment`/`billing` stub, `secrets` env with prefix `ZEVER`). Two need keys: `ai` defaults to `anthropic` and requires an API key, and `mailer` defaults to `log` with a dummy `localhost:25`. The full table is the [adapters matrix](../../../reference/adapters-matrix/).

## Troubleshooting

<details>
<summary>Unknown field error</summary>

The variable's field name matches no option, so `config.Resolve` fails with a did-you-mean hint. Env matching ignores case and `_`, so `DB_MAXCONNS` and `DB_MAX_CONNS` both set `MaxConns`; a real typo such as `DB_MAXCONNX` is the failure case.
</details>

<details>
<summary>Unknown field under a wired service prefix</summary>

`config.Resolve` fails with a did-you-mean hint. Check the service's options struct.
</details>

<details>
<summary>`DB_MAXCONNS=abc` returns `InvalidOptionsError`</summary>

A resolved field failed to parse. Set an integer. Unset variables are ignored, bad values are not.
</details>

<details>
<summary>`AUTH_TOKEN` fails at startup</summary>

`AUTH` is a wired service prefix, so every key under it must name a field. `AUTH_TOKEN` matches none and fails `config.Resolve` with a did-you-mean hint. Set `AUTH_JWT_SECRET` instead.
</details>

<Aside type="danger" title="Dev-only keys">
`Default()` belongs in local dev and tests: its crypto key is deterministic and public. Supply `AUTH_JWT_SECRET`, the crypto key, and provider keys from env or a mounted file in production.
</Aside>
