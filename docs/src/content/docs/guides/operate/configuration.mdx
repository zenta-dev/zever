Zever reads all service configuration from **environment variables only**. `zever.yaml`, `zever.yml`, `zever.json`, and `zever.toml` are never read.

## Quick start

Layers (later wins): `defaults < .env < .env.local < process environment`.

- **defaults**: `config.Default()` with zero-infra adapters (sqlite, slog, stdhttp, memory caches)
- **`.env`**: committed example plus local overrides (gitignored)
- **`.env.local`**: machine-local overrides (gitignored, higher priority)
- **process environment**: highest priority, no file I/O

```sh
DB_DSN=postgres://app:secret@db:5432/app
DB_MAX_CONNS=20
CACHE_ADDR=redis:6379
AUTH_JWT_SECRET=prod-secret-at-least-32-bytes-long
```

## Resolve from env

```go
env, err := config.FromEnv()        // reads .env, .env.local, process env
resolved, err := config.Resolve(env) // typed Config
container.New(resolved, app.Providers()...)
```

`config.LoadEnv(files...)` is the explicit-file variant of `FromEnv`: it parses only the dotenv files you name (no `.env`/`.env.local` discovery, no process environment) and returns an `Env` map for `config.Resolve`.

## Map environment variables to keys

Env names carry no prefix: `<SERVICE>_<FIELD>`, uppercased.

- Default instance: `SERVICE_FIELD` (e.g., `DB_DSN=...` or `DB_MAX_CONNS=20`)
- Named instance: `SERVICE__NAME__FIELD` (e.g., `DB__ANALYTICS__DSN=...`)

A named instance only reaches the container through a matching named Ref
(`db.Ref("analytics")`) wired with `container.Provide`. The default instance
reads the flat `SERVICE_FIELD` namespace.

Matching ignores case and `_`, so `DB_MAXCONNS` and `DB_MAX_CONNS` both set `MaxConns`. One nesting level is supported
(`AUTH_JWT_SECRET` sets `Options.JWT.Secret`). The split point resolves by
matching, not underscore counting, so a segment with its own `_` still works (`WEBHOOK_QUEUE_OPTS_BUFFER` sets `Options.QueueOpts.Buffer`).

Durations accept `"5s"` strings in env, there is no integer form.

## Wired defaults (zero-infra)

| Service | Wired default |
|---------|-----------------|
| db | sqlite |
| cache | memory |
| queue | memory |
| log | slog |
| router | stdhttp |
| ... | (see the `container.Provide` entries in `internal/app/wiring.go`) |

Backends are compiled in: changing a default means changing the wired import plus its `Provide` entry and rebuilding. No adapter key exists in `.env`. Any `*_ADAPTER` key fails resolution.

## Migration from v0.7

v0.8 reads `.env`, `.env.local`, and the process environment, nothing else.

> Adapter selection moved out of config after v0.8: any `*_ADAPTER` key now
> fails resolution. Wire the backend in `internal/app/wiring.go` with an
> import plus a `container.Provide` entry and rebuild.

| v0.7 | v0.8 |
|------|------|
| `zever.yaml` | `.env` + `wiring.go` |
| `config.Load("")` | `config.FromEnv()` + `config.Resolve(env)` |
| `ServiceConfig.Adapter` | `<SERVICE>_ADAPTER` (v0.8 only, removed afterwards -- see below) |
| `DB_MAXCONNS` | `DB_MAXCONNS` (same) |
| `DB__ANALYTICS__DSN` | `DB__ANALYTICS__DSN` (same format) |
| `zever doctor --config` | `zever doctor` (no flag) |

Backends have no env form: any `*_ADAPTER` key fails `config.Resolve`. The container binds the adapter per instance in `wiring.go` with `container.Provide`. See the [Container concept page](../../../concepts/container/).

## Legacy config files

`zever.yaml`, `zever.yml`, `zever.json`, and `zever.toml` are **never read**: no probe, no warning. A stale file is ignored and its values are lost.

Upgrading from v0.7? Move every stanza into `.env` (or the process environment)
and the typed `container.Provide` wiring, then delete the file.
The [migration guide](../migration/) carries the key-by-key map.

## Generated env template

`zever new` and `zever add` generate `.env.example` with every env key, default value, and comment: the authoritative source for service env vars.

## Redact config before printing

Raw option maps may hold secrets. `(*Config).RedactedServices` (built on `Redact`) is the sole display path: `zever config show` prints one `<service>  driver=<x>` header per service plus masked options, then a `<service>/<NAME>` section per named instance. The driver names the code-wired constructor from `internal/app/wiring.go`.

Duration options (`DB_MAX_CONN_LIFETIME`, `AI_TIMEOUT`, ...) print as the env string form (`30s`, `5m`) in the human table and `--json` alike, never as nanoseconds.

```go title="main.go"
for name, sc := range cfg.RedactedServices() {
    fmt.Println(name, sc.Options)
}
```

<Aside type="danger" title="Dev-only keys">
`Default()` belongs in local dev and tests: its crypto key is deterministic and public. Supply `AUTH_JWT_SECRET`, the crypto key, and provider keys from env or a mounted file in production.
</Aside>

## Know the defaults

Defaults pick the zero-infra adapter per service (`db` sqlite, `cache`/`queue`/`session` memory, `storage` local, `log` slog, `observability` stdout, `payment`/`billing` stub, `secrets` env). Two need keys: `ai` defaults to `anthropic` and needs an API key. `mailer` defaults to `log`. Full table: [adapters matrix](../../../reference/adapters-matrix/).

## Troubleshooting

<details>
<summary>Unknown field error</summary>

The field matches no option, so `config.Resolve` fails with a did-you-mean hint. Matching ignores case and `_`, so `DB_MAXCONNS` and `DB_MAX_CONNS` both set `MaxConns`. `DB_MAXCONNX` is the failure case.
</details>

<details>
<summary>Unknown field under a wired service prefix</summary>

`config.Resolve` fails when the key is close to a known field (a typo). The error carries a did-you-mean hint (`DB_MAXCONN` → `did you mean "max_conns"?`).
</details>

<details>
<summary>`DB_MAX_CONNS=abc` returns `InvalidOptionsError`</summary>

A resolved field failed to parse. Set an integer. Unset variables are ignored. Bad values error.
</details>

<details>
<summary>`AUTH_TOKEN` fails at startup</summary>

`AUTH_TOKEN` names no `auth` field and is close to none, so it is ignored as unrelated ambient noise (usually a mistake). Set `AUTH_JWT_SECRET` (or `AUTH_OIDC_ISSUER`, `AUTH_SESSION_SECRET`). Run with `ZEVER_CONFIG_STRICT=1` to fail loudly, or use a near-miss spelling such as `AUTH_JWT_SECRT`, which reports a typo hint.
</details>
