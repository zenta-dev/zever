`tenant` answers "which customer owns this request": `Resolve` maps request metadata to a tenant ID, `Scoped` carries it on the context. Ownership only, never authorization. Pair it with [Authorization](../../security/authz-permissions/).

## Quick start

`single` (default) gives every request one hardcoded ID (`id`, default `"default"`).

```go title="main.go"
import (
    "context"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
)

c := container.New(config.Default())
t, err := c.Tenant()
if err != nil {
    panic(err)
}
defer t.Close()

ctx := context.Background()
id, err := t.Resolve(ctx, map[string]string{"tenant": ""})
fmt.Println(id, err)
scoped, err := t.Scoped(ctx, id)
fmt.Println(scoped != nil, err)
```

Output:

```text
default <nil>
true <nil>
```

## Resolve tenants from a header or subdomain

Use `header` for multi-tenant SaaS APIs where a gateway or client sets a header (default `X-Tenant-ID`, `DefaultHeader`). With `X-Tenant-ID: acme` metadata, `Resolve` returns `acme`. The header wins. Otherwise `subdomain_regex` matches the first capture group against the lowercased `Host` metadata. With neither, `Resolve` returns `tenant.ErrNotFound`. Meta keys match case-insensitively. ReDoS-prone patterns are rejected at `Open`. Strip or overwrite the tenant header at your edge. The adapter trusts it.

```sh
TENANT_HEADER=X-Tenant-ID
TENANT_SUBDOMAIN_REGEX=^(?P<tenant>[a-z0-9-]+)\.example\.com$
TENANT_ID=default
```

`Validate` rejects a non-printable or overlong `header` and any `subdomain_regex` over 500 characters (`MaxRegexLength`, a ReDoS bound). Empty `header` means the default. Adapters: `single` (fixed ID), `header` (header plus optional subdomain regex). See [tenant config reference](../../../reference/config/#tenant).

## Production checklist

- Resolve once at the middleware edge. Propagate through the `tenant/context.go` helpers. Never re-derive deeper, where an unvalidated value could slip in.
- Fail closed on an unknown tenant: mapping it to a default turns one typo into a cross-tenant leak.
- Both adapters are stateless: replicas agree when they share config. `Tenant.Close() error` takes no context.
- Tenant IDs are customer data. Document the header name and validation rule for API clients since it is public contract. Never log raw option maps.

## Troubleshooting

<details>
<summary>Every request lands on `default` after switching to `header`</summary>

The gateway is not sending the configured header, or the app reads a different name. Confirm `TENANT_HEADER` matches the client (`X-Tenant-ID` vs `X-Tenant`). Proxies must forward it.
</details>

<details>
<summary>`header must be a valid header key`</summary>

The name holds whitespace, a colon, DEL, or non-printable ASCII. Empty means the default. Anything else must be a valid key.
</details>

<details>
<summary>`subdomain_regex exceeds max length`</summary>

The pattern tops 500 characters. Shorten it, or split matching into regex plus code.
</details>
