Zever is pre-1.0: `0.x` releases may break. Undocumented breaks are bugs: open an issue.

| Range | Guarantee |
|---|---|
| `0.x` patch or minor | May break. Breaks are listed under `Changed` in `CHANGELOG.md` with a `**Breaking:**` prefix. |
| `1.0+` (future) | SemVer: majors break, minors add, patches fix. |

Public API changes (exports, config structs or defaults, serialization) get maintainer review with migration notes.

## Bump a version

<Steps>
1. Read `CHANGELOG.md` (`## [Unreleased]`, target) for `**Breaking:**`.
2. Bump each required Zever module, then tidy:

   ```sh
   go get github.com/zenta-dev/zever/config@v0.8.0 github.com/zenta-dev/zever/container@v0.8.0
   go mod tidy
   ```

   Upgrade the CLI (`zever upgrade`) or re-run the [installer](../../../start/installation/).

3. Run `make check` (fmt, vet, tidy-check, test, build, module-graph, dependabot, lint, vulncheck) plus `make test-race`.
4. Smoke-test resolution:

   ```go title="main.go"
   c := container.New(config.Default())
   db, err := c.DB()
   if err != nil {
       panic(err)
   }
   q, err := c.Queue()
   if err != nil {
       panic(err)
   }
   fmt.Println("upgrade ok:", db != nil && q != nil)
   ```

   Output: `upgrade ok: true`. Container construction is stable across bumps (`container.New(nil)` valid, `Close(ctx)` closes only resolved services). The changelog names any fix.
5. Re-validate production config: env resolution is strict about known keys. Renames fail loudly before rollout. Re-check redaction and close wiring (`cfg.RedactedServices()`, `Close(ctx)` with a timeout parent).
</Steps>

Pin the CLI to the bumped version so `zever compile`, `migrate`, `doctor` match backend behavior.

## Upgrade to v0.8.0

**v0.8.0 is env-only: configuration moved from a config file to `.env`.**

A v0.7.x project keeps service configuration in `zever.yaml` (or `.yml`, `.json`, `.toml`). v0.8.0 never reads that file: no probe, discovery, or warning. A leftover file is inert: services fall back to built-in defaults, old values gone without a word. Translate by hand and delete the file.

| v0.7.x | v0.8.0 |
|---|---|
| `zever.yaml` (or `.yml`, `.json`, `.toml`) | `.env`, `.env.local`, process environment |
| `config.Load("zever.yaml")` | `config.FromEnv()` then `config.Resolve(env)` |
| `project.server_entry` | `ZEVER_SERVER_ENTRY` |
| `project.worker_entry` | `ZEVER_WORKER_ENTRY` |
| `project.generated_dir` | `ZEVER_GENERATED_DIR` |
| `project.tinker_entry` | `ZEVER_TINKER_ENTRY` |
| `project.seed_entry` | `ZEVER_SEED_ENTRY` |
| `search.Postgres`, `search.SQLite` | `db` (DSN picks postgres or sqlite) |
| `vectorstore.PGVector`, `vectorstore.SQLite` | `db` (DSN picks postgres or sqlite) |
| `workflow.Postgres` | `db` (DSN picks postgres or sqlite) |
| `--config` file flag | gone from every command |

Env keys carry no prefix: `<SERVICE>_<FIELD>` (default), `<SERVICE>__<NAME>__<FIELD>` (named): `db.options.dsn` becomes `DB_DSN`, `ai.options.api_key` `AI_API_KEY`, `auth.options.jwt.secret` `AUTH_JWT_SECRET`. (Adapter selection was a v0.8 env key, now `internal/app/wiring.go`. See the migration guide.)

Two commands prove the migration: `zever config show` prints resolved values per service. `zever doctor` resolves every wired battery, exiting non-zero on failure. A wrong value is loud: removed adapter aliases fail with `unknown adapter`, misspellings with a did-you-mean hint. The [migration guide](../migration/) has the key-by-key map, a before-and-after example, and the exact errors.

## Fix known breaking changes

| Symptom | Cause | Fix |
|---|---|---|
| App boots but old values are gone | Leftover v0.7.x file never read. | Translate every stanza into `.env`, then delete it (see [Upgrade to v0.8.0](#upgrade-to-v080)). |
| `Load` rejects a previously valid key | Renamed in the bump (`maxconns`, `apikey`, `secretkey`). | Rename to `max_conns`, `api_key`, `secret_key` (env names unaffected). See [Configuration](../configuration/). |
| `CreateCustomer` no longer compiles | `billing.Billing.CreateCustomer` gained a required idempotency key. | Pass `""` for non-idempotent behavior, or a real key for safe retries. |
| `zen/migrate` import fails | Engine moved to `orm/migrate`. | Import `github.com/zenta-dev/zever/orm/migrate`. |
| Custom `search` or `vectorstore` adapter fails to compile | `search.Search` and `vectorstore.VectorStore` gained batch methods (`IndexBatch`, `UpsertBatch`). | Implement them. Bundled adapters already do. |
| Editor highlighting misses new keywords | Grammars derive from `token.Keywords`, `resolver.ScalarTypeNames`. | Run `make generate` (`go run ./tools/gengrammar`). Commit the regenerated files. |

```go
// Before
cust, err := b.CreateCustomer(ctx, name, email)
// After
cust, err := b.CreateCustomer(ctx, "Ada", "ada@example.com", "")
```

Import changes: see [Migrate from v0.7 to v0.8](../migration/).

## What each gate catches

| Step | Command | Catches |
|---|---|---|
| Tidy | `go mod tidy`, `make tidy-check` | `go.mod` and `go.sum` drift. |
| Format and vet | `make fmt`, `make vet` | Formatting and static faults. |
| Lint | `make lint` | Style and guard regressions (`.golangci.yml`). |
| Race tests | `make test-race` | Data races the fast gate skips. |
| Vulnerability scan | `make vulncheck` (`govulncheck` v1.8.0) | Known dependency CVEs. |
| Grammars | `make generate` | Stale editor grammars. |

`go test` runs `-vet=off -count=1` (vet is separate). PRs run `test-race-fast` (no coverage). `test-race-all` (coverage) only on pushes to main and tags. `make check` has no race pass, so run `make test-race` locally before pushing. Keep timeout tests short (parent about 100ms, block about 500ms) so `goleak.VerifyTestMain` stays green.

## Release process (maintainers)

Releases bump every version pin together (file list: `.github/CONTRIBUTING.md` release checklist), then `tools/tag-release.sh vX.Y.Z` tags one `<module-path>/vX.Y.Z` per module in dependency order, plus the bare `vX.Y.Z` release tag the workflow fires on. Both publish in one atomic push. The workflow starts once all module tags are on origin. `dsl` carries no release version (schema `v1`/`v2` are API versions). Add user-facing changes to `CHANGELOG.md` under `## [Unreleased]` per PR: one logical change per commit, Conventional Commits (`feat`, `fix`, `perf`, `refactor`, `test`, `docs`, `ci`, `build`).
