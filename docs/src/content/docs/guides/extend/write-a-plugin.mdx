A plugin is a standalone Go module: an adapter for an existing battery (`zever-adapter-<name>`), or a new battery (`zever-battery-<name>`, dogfooded by `examples/sms`). Run the conformance kit before publishing.

## New adapter

A battery owns an interface plus typed `Options` and a `DefaultRef`. The container is the only resolver. Adapters never self-register (no `init`, no globals). Each adapter lives at `adapters/<battery>/<name>` with `New` taking the battery's `Options`. No adapter registry, `Adapter` type, or `ParseAdapter`: selection is import plus `container.Provide`, never config.

Example `cache` adapter in module `zever-adapter-foo`:

```go title="foo/foo.go"
package foo // import "example.com/zever-adapter-foo"

import (
	"context"
	"time"

	"github.com/zenta-dev/zever/core/cache"
)

// driver implements all 8 cache.Cache methods.
type driver struct{ /* connection state */ }

func (d *driver) Get(ctx context.Context, key string) ([]byte, error) { panic("implement") }
func (d *driver) Set(ctx context.Context, key string, value []byte, ttl time.Duration) error {
	panic("implement")
}
func (d *driver) SetIfAbsent(ctx context.Context, key string, value []byte, ttl time.Duration) (bool, error) {
	panic("implement")
}
func (d *driver) Delete(ctx context.Context, key string) error         { panic("implement") }
func (d *driver) Increment(ctx context.Context, key string) error      { panic("implement") }
func (d *driver) Decrement(ctx context.Context, key string) error      { panic("implement") }
func (d *driver) Exists(ctx context.Context, key string) (bool, error) { panic("implement") }
func (d *driver) Close(ctx context.Context) error                      { panic("implement") }

// New matches cache.Factory.
func New(opts cache.Options) (cache.Cache, error) {
	return &driver{}, nil
}
```

The host (your app, not the adapter package) wires it:

```go title="internal/app/wiring.go"
import foocache "example.com/zever-adapter-foo"

var Cache = cache.DefaultRef()

func Providers() []container.Provider {
	return []container.Provider{
		container.Provide(Cache, foocache.New),
	}
}
```

First `container.Get(c, Cache)` (or `c.Cache()`, once provided) resolves the factory like any core adapter. Switching means changing the import and rebuilding.

Follow these rules:

- Never add methods to a battery interface. Propose a capability interface instead (such as `cache.CompareAndSwapCache`).
- Call `opts.Validate()` first in `New`, fail closed and join all violations.
- Keep errors sentinel-based, `errors.Is`-compatible, `cache:`-prefixed. Never leak secrets or option maps (use `config.RedactedServices`).
- Take `ctx` first for I/O and never store it in a struct.

## Conformance kit

Batteries with a kit expose `Conformance` in `core/<b>/<b>test`. Run it and link the passing run from your README:

```go title="foo/foo_test.go"
import "github.com/zenta-dev/zever/core/cache/cachetest"

func TestConformance(t *testing.T) {
	t.Parallel()
	cachetest.Conformance(t, func(t *testing.T) cache.Cache {
		t.Helper()
		c, err := foo.New(cache.Options{})
		if err != nil {
			t.Fatal(err)
		}
		t.Cleanup(func() { _ = c.Close(t.Context()) })
		return c
	})
}
```

Kits exist for these batteries (import `github.com/zenta-dev/zever/core/<b>/<b>test`):

```text
ai analytics auth authz billing cache crypto db document eventbus flag geo i18n
idempotency job lock log mailer media middleware notification observability
outbox password payment permission queue ratelimit resilience router scheduler
search secrets session storage tenant vectorstore webhook workflow
```

## New battery

Mirror the core shape (interface, validated `Options`, `DefaultRef`, `New`, sentinels): copy `examples/sms/sms.go` (`SMS` interface, `Stub` adapter, `Options{From}`) plus a deterministic stub like `examples/sms/stub`. No registry, no name to claim: `New` wires straight into host providers.

<Steps>

1. Add the config entry under `config.Config.Plugins`: name-keyed raw options the plugin validates itself (`map[string]Service[json.RawMessage]`, nil by default, so initialize first):

    ```go
    cfg.Plugins = map[string]config.Service[json.RawMessage]{
    	"sms": {
    		Options: json.RawMessage(`{"from":"+15550000"}`),
    	},
    }
    ```

    Options only: no adapter key, no env overlay. The build func below picks the backend.

2. Register a validator for `Config.Validate` coverage. Without one, options stay raw, unvalidated, and not env-overridable:

    ```go
    if err := config.RegisterPluginValidator("sms", func(opts jsontext.Value) error {
    	var o sms.Options
    	if err := codec.Unmarshal(opts, &o); err != nil {
    		return err
    	}
    	return o.Validate()
    }); err != nil {
    	return err
    }
    ```

3. Register a versioned build func once at startup, then resolve per container. The build takes the container's `*config.Config` and picks the backend in code:

    ```go
    if err := container.RegisterPlugin[sms.SMS]("sms", container.PluginAPIVersion, func(cfg *config.Config) (sms.SMS, error) {
    	var opts sms.Options
    	if err := json.Unmarshal(cfg.Plugins["sms"].Options, &opts); err != nil {
    		return nil, err
    	}
    	return sms.Open(sms.Stub, opts)
    }); err != nil {
    	return err
    }

    c := container.New(cfg)
    svc, err := container.Resolve[sms.SMS](c, "sms")
    ```

</Steps>

Successes cache per `Container`. Failures retry on next `Resolve`. Wrong types fail `Resolve`. Resolved plugins close with `Container.Close`. Full flow: `examples/sms/app/main.go`.

`zever add <battery>[/<adapter>]` scaffolds `go.mod` and `internal/app/wiring.go`. Plugins add `--module <path[@version]>` (default `v0.1.0`):

```sh
zever add sms/stub --module example.com/zever-battery-sms
```

Flags: `--adapter`, `--force`, `--module`, `--dry-run`. Then run `go mod tidy`. See [CLI reference](../../../reference/cli/).

## Wiring

No manifest file: `go.mod` requires plus `wiring.go` imports/`container.Provide` entries are the manifest (floor: `log`, `router`, plus picks).

As with `database/sql` drivers: bare imports resolve nothing, and wiring without the `go.mod` require does not build. Import the module, add `container.Provide` before first use, require it in `go.mod`. Unwired services fail with `NotWiredError` naming the fix.

## Versioning

`container.PluginAPIVersion` is one integer (`1`), bumped only on breaking host changes. `RegisterPlugin` rejects other versions, empty names, nil builds, and duplicates: mismatches fail at registration, never resolve. Pre-1.0 `0.x` may break the surface with release notes. Pin scaffolds with `--framework-version`.

- Publish from your repo with independent semver (no lockstep Zever tag).
- State the targeted `PluginAPIVersion`. Verify a mismatched `RegisterPlugin` fails pre-publish.
- Link the passing conformance run from your README.
- Record changes in your own `CHANGELOG.md`.

## Plugins and `.zen`

`.zen` cannot reference plugin batteries: the compiler resolves only core batteries (job `queue:` names are never validated against adapters). Model in `.zen`, wire in Go. Syntax: [Zen syntax](../../../reference/zen-syntax/).

<details>
<summary>Why there is no schema-level plugin reference yet</summary>

A proposal (`uses sms;` plus optional `@via(sms)`) was deferred:

- Option A (`uses` declaration, runtime-checked names): touches tokens (`uses` reserved), AST, parser, resolver/IR, formatter, `breaking`, grammars, LSP, fixtures, plus a second manifest.
- Option B (plugin-shipped `.zen` fragment): reuses machinery, but nothing checks the fragment against Go code, and there is no import.
- Option C (typed registry in the resolver): rejected, since `dsl/` must never import runtime code, and it adds global state.

Revisit A when a real plugin needs schema-visible surface (validation, OpenAPI, queue typing). Never choose C.
</details>

<details>
<summary>Why idempotency, lock, and ratelimit do not wrap cache</summary>

None maps onto cache reads/writes: `idempotency.Store` reserves via `Begin`/`Complete`/`Forget`, `lock.Locker` leases with ownership-checked `Extend`/`Unlock`, `ratelimit.Limiter` does token-bucket accounting returning `Decision{Allowed, RetryAfter, Remaining}`. Shared reuse is `shared/cas` and `shared/redisclient`.
</details>
