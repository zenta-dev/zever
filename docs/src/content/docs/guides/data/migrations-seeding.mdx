Zever compiles `.zen` schemas, diffs against the live database, applies missing statements, and records each in `schema_migrations` so `rollback` can undo it and re-running `migrate` is a no-op.

## Quick start

<Steps>

1. Preview DDL without touching the database.

   ```sh
   zever db migrate --dry-run schema/app.zen
   ```

2. Apply it (default wiring is `sqlite`).

   ```sh
   zever db migrate schema/app.zen --adapter=sqlite --dsn=data/app.db
   ```

   ```text
   applied 4 statement(s) via sqlite
   ```

3. Seed the database.

   ```sh
   zever db seed
   ```

</Steps>

With no files, `migrate` discovers `.zen` under the schema directory, `-i` prompts for files/adapter/DSN. `--dry-run` diffs against live `--dsn`, else prints full bootstrap DDL.

## Choose the database

CLI and app share the same `db` settings.

```sh
DB_PATH=app.db
```

sqlite defaults to `app.db`, `:memory:` forces one connection even with `max_conns`. On postgres `min_conns` is a real pool minimum, on sqlite `SetMaxIdleConns`. See [db options](../../../reference/config/#db).

## Plan, review, and apply

| Situation | Statement |
|---|---|
| Table missing | `CREATE TABLE` + `CREATE INDEX IF NOT EXISTS` |
| Field has `@renamed_from("old")` | `RENAME COLUMN` (keeps data) |
| Column missing live | `ALTER TABLE ADD COLUMN` |
| Column type changed | `ALTER COLUMN TYPE` (postgres), sqlite warns and skips |
| Nullability changed | `ALTER COLUMN SET/DROP NOT NULL` (postgres), sqlite warns and skips |
| Declared index / `@unique` missing | `CREATE [UNIQUE] INDEX` |
| Live index no longer declared | `DROP INDEX`, only Zever-named indexes |
| `belongs_to` / `has_one` FK missing | `ADD CONSTRAINT ... FOREIGN KEY` (postgres), sqlite warns and skips |
| Live column no longer declared | `DROP COLUMN`, only with `--drop-columns` |

`--drop-columns` destroys data: snapshot first. Unannotated renames look like drop + add, so use `@renamed_from`. Removed unique constraints/FKs are reported, never dropped. Plan in code/CI with side-effect-free `migrate.Plan`.

```go title="migrate.go"
import "github.com/zenta-dev/zever/orm/migrate"

plan, _ := migrate.Plan(ctx, conn, desired, migrate.PlanOptions{})
for _, stmt := range plan.Statements() { fmt.Println(stmt) }
applied, _ := migrate.Apply(ctx, conn, plan) // transaction where the driver supports it
fmt.Println("applied", applied)
```

`PlanOptions{DropColumns: true}` emits `DROP COLUMN`, `DetectTypeChanges: true` compares live/declared types (CLI always enables it). `Apply` uses `db.WithTx`: failures roll back, nesting returns `ErrNestedTx`. The plan carries them into `Apply`.

## Write safe migrations

On live traffic the risk is locks, rewrites, destroyed data. Prefer expand/contract.

| Instead of | Do this |
|---|---|
| `DROP COLUMN` / `DROP TABLE` | Add replacement, dual-write, backfill, move reads, then drop. |
| `ADD COLUMN ... NOT NULL` without default | Add nullable, backfill, then `SET NOT NULL`. |
| `ALTER COLUMN TYPE` | Add new-typed column, backfill, swap reads, drop old. |
| Plain `CREATE INDEX` on postgres | `CREATE INDEX CONCURRENTLY` (see below). |

`--lint` checks the plan before running, failing on errors. Waive one rule with `-- zever:allow:<code>`, all with bare `-- zever:allow`:

```sql
-- zever:allow:drop_column
ALTER TABLE "public"."users" DROP COLUMN IF EXISTS "legacy_flag";
```

| Rule code | Severity | Flags |
|---|---|---|
| `drop_table`, `drop_column` | error | `DROP TABLE`, `DROP COLUMN` |
| `not_null_without_default` | error | `ADD COLUMN ... NOT NULL` with no `DEFAULT` |
| `type_rewrite` | error | `ALTER COLUMN ... TYPE`, `MODIFY COLUMN` |
| `non_concurrent_index` | warning | postgres `CREATE INDEX` without `CONCURRENTLY` |

```sh
zever db migrate --lint --dry-run schema/*.zen --adapter=postgres --dsn='postgres://localhost/db?sslmode=disable'
```

## Backfill in batches

One-statement `UPDATE ... WHERE new_col IS NULL` on a large table holds locks and bloats it. Migrate the schema first (new column nullable), run a batched backfill with pauses (ideally from a job, not the migration), then add `NOT NULL` once `SELECT count(*) ... WHERE new_col IS NULL` returns zero.

## Build indexes without blocking writes

Plain `CREATE INDEX` on postgres blocks writes for the whole build. Pass `--concurrent-indexes` for `CREATE INDEX CONCURRENTLY`:

```sh
zever db migrate schema/app.zen --adapter=postgres --dsn='postgres://localhost/db?sslmode=disable' --concurrent-indexes
```

Concurrent builds run outside any transaction (postgres forbids `CONCURRENTLY` inside one): each build commits independently, so a failure leaves earlier statements applied for retry. Postgres-only, other dialects render plain `CREATE INDEX`. In code: `migrate.PlanOptions{ConcurrentIndexes: true}` or `atlas.DDLOptions{ConcurrentIndexes: true}`.

## Bound statement time with lock timeouts

Each postgres statement runs in its own transaction, `lock_timeout`/`statement_timeout` bound it via `SET LOCAL`, leaving session/database defaults unchanged:

```sh
zever db migrate schema/app.zen --adapter=postgres --dsn='...' --lock-timeout=10s --statement-timeout=30s
```

Unset flags fall back to `DB_LOCK_TIMEOUT` / `DB_STATEMENT_TIMEOUT`:

```sh
DB_DSN=postgres://app:secret@db:5432/app
DB_LOCK_TIMEOUT=10s
DB_STATEMENT_TIMEOUT=30s
```

In code: `migrate.PlanOptions{LockTimeout: 10 * time.Second, StatementTimeout: 30 * time.Second}`. Zero disables each, negative fails `Plan` with `ErrInvalidTimeout`. Concurrent index builds skip them (no transaction scope for `SET LOCAL`).

## Roll back a migration

`rollback` needs no `.zen` files, it inverts the newest `schema_migrations` rows. `-n` counts statements: undo three with `-n 3`.

```sh
zever db rollback --adapter=sqlite --dsn=data/app.db --dry-run   # print inverses
zever db rollback --adapter=sqlite --dsn=data/app.db -n 2
```

```text
rolled back 2 statement(s) via the sqlite adapter
```

Rollback restores structure, not data.

| Undoing | Result |
|---|---|
| `ADD COLUMN` | Drops column and values |
| `DROP COLUMN` | Recreates column empty |
| `ALTER COLUMN TYPE` | Restores type, not truncated values |
| `RENAME COLUMN`, index/FK changes | Lossless |
| `ALTER ... NOT NULL` | Fails if a NULL was written meanwhile |
| `CREATE TABLE` | Skipped, never dropped |

Lossy statements warn first, rows with no inverse are reported, skipped, and kept.

## Seed deterministically

`zever db seed` runs the entrypoint (`ZEVER_SEED_ENTRY`, default `db/seed`), passing args through. The variable comes from the `zever` process env, seeds read service config from `.env`. Write idempotent ORM Go in one transaction via `OnConflict` upsert.

```go title="db/seed/main.go"
db.WithTx(ctx, conn, nil, func(ctx context.Context, tx db.Tx) error {
    return orm.InsertInto(Users).
        Values(orm.Set(UserName, "alice")).
        OnConflict(UserName.Col()).DoNothing().
        Exec(ctx, tx)
})
```

Regenerate ORM builders after schema edits from the repo root, never hand-edit `generated/`.

```sh
zever compile examples/pagination/schema/pagination.zen --backend=zenorm --out examples/pagination/generated
```

## Troubleshooting

<details>
<summary>Plan shows unexpected DROP statements</summary>

`--drop-columns` set or schema lost a field. Re-check `.zen`.
</details>

<details>
<summary>Type or nullability change ignored on sqlite</summary>

sqlite has no `ALTER COLUMN`. Recreate the table or migrate data manually.
</details>

<details>
<summary>`ErrNestedTx` during seed</summary>

A seed helper opened a transaction inside `WithTx`. Use one `WithTx` unit.
</details>

<details>
<summary>Postgres integration tests are skipped</summary>

Gate is `POSTGRES_DSN`. Export it for the live pass, sqlite runs without it.
</details>

<details>
<summary>Rollback does not restore data</summary>

Rollback reverses schema only. Re-run `zever db seed`.
</details>
