`media.Media` bundles the upload pipeline: `Upload`, `Download`, `DownloadRange`, `Stat`, `Probe`, `Transform`, `Delete`. It validates IDs, caps decode size, probes format. For plain blobs, see [Storage and media](../storage-media/).

## Quick start

`local` (`adapters/media/local`, default) writes under `root` for single instances/tests. `s3` (`adapters/media/s3`) needs `bucket`, `region`, credentials. Transforms call `ffmpeg`/`ffprobe`.

```sh
MEDIA_ROOT=/var/media
MEDIA_MAX_DOWNLOAD_BYTES=67108864
MEDIA_MAX_PIXELS=50000000
MEDIA_PRESIGN_TTL=1h
```

Defaults: `root` `/tmp/media`, `base_url` `/media`, `ffmpeg`/`ffprobe` on `PATH`, `max_download_bytes` 64 MiB, `max_pixels` 52428800, `derived_ttl` 10m, `presign_ttl` 1h (max 7 days), `max_duration` unlimited, `region` `us-east-1`. Durations are nanoseconds, env accepts `"1h"`. See [media options](../../../reference/config/#media).

## Upload and probe an asset

`Upload` generates the ID: use `asset.ID` afterwards. Register the adapter first (container wires nothing). `Media()` is lazy, cached, retried.

```go title="main.go" check
package main

import (
	"context"
	"fmt"
	"os"

	medialocal "github.com/zenta-dev/zever/adapters/media/local"
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
	"github.com/zenta-dev/zever/core/media"
)

func main() {
	ctx := context.Background()
	c := container.New(config.Default(), container.Provide(media.DefaultRef(), medialocal.New))
	defer c.Close(ctx)

	m, err := c.Media()
	if err != nil {
		panic(err)
	}
	raw, err := os.ReadFile("testdata/avatar.png")
	if err != nil {
		panic(err)
	}
	asset, err := m.Upload(ctx, "avatar.png", raw, media.UploadOptions{ContentType: "image/png"})
	if err != nil {
		panic(err)
	}
	info, err := m.Stat(ctx, asset.ID)
	if err != nil {
		panic(err)
	}
	fmt.Println("size:", info.Size)
}
```

```text
size: 48210
```

`Transform` takes `media.TransformOps` (`Width`, `Height`, `Format`, `Quality`, `Bitrate`, `CRF`, `Offset`), returns derived URL plus error. The storage adapter does not affect this.

## Production checklist

- `ValidID` accepts only ASCII letters/digits/hyphens/underscores, rejects empty, `.`, `..`, anything containing `..`. Never build a storage key from a raw caller ID.
- Decoded images capped at `max_pixels`, downloads at `max_download_bytes`: crafted images cannot exhaust memory.
- `presign_ttl` over 7 days fails `Validate()` with `InvalidOptionsError` (rejected, not clamped).
- `Validate` rejects negative bounds on `max_download_bytes`, `max_pixels`, `derived_ttl`, `max_duration`, and `presign_ttl`, each must be `>= 0`.
- Pin `ffmpeg`/`ffprobe` paths, `access_key_id`/`secret_access_key` never logged.

## Troubleshooting

<details>
<summary>`Stat` or `Download` fails on an ID you uploaded</summary>

Bad ID (usually your path, not `asset.ID`). Use the returned ID.
</details>

<details>
<summary>Transforms fail with "binary not found"</summary>

`ffmpeg`/`ffprobe` missing. Install or set absolute paths in config.
</details>

<details>
<summary>Startup fails with `InvalidOptionsError` on `presign_ttl`</summary>

TTL exceeds 7 days. Lower it, the limit is enforced, not clamped.
</details>
