`document.Document` turns a source into a PDF or image with one `Render` call, a typed `OutputFormat` (`pdf`, `png`, `jpg`), and a clamped `Quality`. Callers do not need to know whether a LaTeX toolchain or a remote API does the work.

## Quick start

- `local` (default, `adapters/document/local`) renders in your process.
- `latex` shells out to a fixed, configured compiler. Use it for `.tex` sources.
- `remote` sends the job to a rendering API over HTTP, so you skip installing LaTeX. It needs `endpoint` and `api_key`.

<Tabs>
  <TabItem label="local">
```yaml title="zever.yaml"
document:
  adapter: local
  options:
    quality: 80
    dpi: 150
    tmp_dir: /tmp/zever-doc
    max_output_bytes: 67108864
    timeout: 30000000000   # nanoseconds
```
  </TabItem>
  <TabItem label="env">
```sh
DOCUMENT_ADAPTER=latex
DOCUMENT_LATEX_COMMAND=pdflatex
DOCUMENT_LATEX_PDF_TO_PPM=pdftoppm
DOCUMENT_LATEX_RUNS=2
DOCUMENT_ENDPOINT=https://render.internal/v1
DOCUMENT_API_KEY=...
```
  </TabItem>
</Tabs>

| Key | Rule |
|---|---|
| `quality` | Clamped to 0 to 100. Pass user input through and let `ClampQuality` handle it |
| `dpi` | Must be 0 or more |
| `max_output_bytes` | 0 or more. Caps rendered output (default 64 MiB) |
| `timeout` | 0 or more. File values are nanoseconds, env accepts `30s` |
| `tmp_dir` | Holds intermediate artifacts |
| `latex_command`, `latex_pdf_to_ppm` | Config only, never interpolated from document content (defaults `pdflatex`, `pdftoppm`) |
| `latex_runs` | Bounds compiler passes |
| `endpoint`, `api_key` | For `remote`. `endpoint` must be an absolute URL with scheme and host |

See the [document options](../../../reference/config/#document).

## Render a document

Register the adapter first, because the container wires nothing. `Document()` resolves lazily, caches, and retries after an error.

```go title="main.go"
package main

import (
	"context"
	"fmt"
	"os"

	documentlocal "github.com/zenta-dev/zever/adapters/document/local"
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
	"github.com/zenta-dev/zever/core/document"
)

func main() {
	documentlocal.Register()
	ctx := context.Background()
	c := container.New(config.Default())
	defer c.Close(ctx)

	d, err := c.Document()
	if err != nil {
		panic(err)
	}
	out, err := d.Render(ctx, []byte(`hello`), document.FormatPDF)
	if err != nil {
		panic(err) // out is nil on error, never a partial file
	}
	if err := os.WriteFile("/tmp/hello.pdf", out, 0o600); err != nil {
		panic(err)
	}
	fmt.Println("bytes:", len(out))
}
```

```text
bytes: 1240
```

The byte count varies by adapter and source. Check the error before you write anything to disk.

## Production checklist

- Sources are capped at 10 MiB and output at 64 MiB by default. Raise them deliberately and with a measured reason.
- The `latex` adapter never interpolates a caller-supplied command, so document content cannot reach a shell. Lock down `tmp_dir` permissions too.
- Bound renders with `timeout` and clean up temp artifacts on error paths.
- `api_key` never appears in logs, and `endpoint` is validated before the first request.

## Troubleshooting

<details>
<summary>`Render` returns nil bytes and an error</summary>

Cause: that is the contract, with no partial files. Fix: inspect the error, do not write the output, and check the source against the 10 MiB cap.
</details>

<details>
<summary>LaTeX renders fail with "command not found"</summary>

Cause: `latex_command` or `latex_pdf_to_ppm` is not on `PATH` (or not an absolute path) where the process runs. Fix: install them, or use the `remote` adapter.
</details>

<details>
<summary>Remote renders fail validation before any request</summary>

Cause: `endpoint` is not an absolute URL with scheme and host, or `timeout` is negative. Fix: correct the config. Nothing was sent.
</details>
