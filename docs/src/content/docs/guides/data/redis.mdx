Most stateful services default to memory with a Redis twin: develop server-free, switch configuration (not code) in production. Use Redis for anything shared across instances.

## Quick start

Point each shared service at the same `addr`. `cache`, `queue`, `lock` use flat keys, `session`, `ratelimit`, `eventbus`, `idempotency` nest a `redis` block.

```sh
CACHE_ADDR=redis:6379
CACHE_POOL_SIZE=20
CACHE_MIN_IDLE_CONNS=2
QUEUE_ADDR=redis:6379
LOCK_ADDR=redis:6379
SESSION_REDIS_ADDR=redis:6379
RATELIMIT_REDIS_ADDR=redis:6379
```

```sh
docker run -p 6379:6379 redis:7
# wire the redis backends in internal/app/wiring.go first (container.Provide),
# then run against them:
go run ./cmd/myapp
```

```text
server listening on :8080 (cache=redis queue=redis)
```

Env keys follow `<SERVICE>_<FIELD>` (matching ignores case and `_`), on flat services `url` wins over `addr`. `session`, `ratelimit`, `eventbus`, `idempotency` reject a malformed `redis.addr` in `Options.Validate()`, `cache`, `queue`, `lock` ping Redis (3s limit) on first resolve, so a bad address fails on the first accessor call. Keep `memory` in tests: no Docker, and it passes `goleak.VerifyTestMain`. See [config reference](../../../reference/config/#cache).

## Resolve the services

```go title="main.go"
import (
    cacheredis "github.com/zenta-dev/zever/adapters/cache/redis"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/cache"
)

c := container.New(config.Default(), container.Provide(cache.DefaultRef(), cacheredis.New))
defer c.Close(ctx)

cache, err := c.Cache()
q, err := c.Queue()
locker, err := c.Lock()
sess, err := c.Session()
limiter, err := c.RateLimit()
```

Wire each adapter with `container.Provide` first (`adapters/cache/redis` exposes `New`). Accessors resolve lazily, cache, retry, check `err` per call. `c.Job()` dispatches over `Queue`, `c.Scheduler()` shares it.

## Decide which services use Redis

Switch per service, one service on Redis never drags the rest along.

| Service | Memory adapter | Redis role |
|---|---|---|
| `cache` | `memory` (LRU) | Shared value store through typed codecs |
| `queue` | `memory` | Topic messaging plus due and stale sweeps |
| `session` | `memory` | Server-side session rows |
| `ratelimit` | `memory` (token bucket) | Distributed counters (Lua) |
| `lock` | `memory` | Distributed leases (default `ttl` 30s) |
| `idempotency` | `memory` | Reserve-then-complete store |
| `eventbus` | `memory` (fan-out) | Cross-process publish/subscribe |

With two or more instances use Redis for `session`, `lock`, `ratelimit`, `queue`, on `memory`, users stick to one instance, leases split, counters diverge, jobs duplicate.

## Client ownership and behavior

- Each adapter `New` owns its client, `Close` closes only that one, `c.Close(ctx)` dedups shared instances by pointer.
- `queue/redis` sweeps due/stale claims (`promoteDue`, `reclaimStale`) at most every 250ms (≤250ms recovery latency).
- `ratelimit` denials return 429 JSON with ceiled-seconds `Retry-After`, errors fail open, keys must be non-empty, bounded, control-byte-free, never echoed.
- `eventbus` keeps the memory envelope (`id`, `payload`, `headers`), `SubscribeChan` buffers per subscriber, slow consumers drop newest.
- `cache/redis` and `session/redis` share typed codecs with the memory twins. Redis leases are distributed, memory locks process-local.
- Size `pool_size`/`min_idle_conns` for peak concurrency, pass request contexts so round trips observe deadlines.
- Open directly via `cache.Open`, `queue.Open`, `lock.Open`. `Options.Validate()` rejects negative TTLs and oversize prefixes.

## Troubleshooting

<details>
<summary>Two instances serve different sessions</summary>

Both run `memory`. Point both at the same Redis `addr`.
</details>

<details>
<summary>Rate limits diverge across replicas</summary>

`memory` buckets are per process. Wire `redis` with shared `RATELIMIT_REDIS_ADDR`.
</details>

<details>
<summary>Jobs run twice after a crash</summary>

Redis sweep reclaims stale claims within ~250ms. Make handlers idempotent, keyed by job ID.
</details>

<details>
<summary>Startup rejects the address</summary>

Malformed `redis.addr` or ping failure. Use `host:port`, on flat services `url` wins.
</details>

<details>
<summary>Shutdown hangs on Redis clients</summary>

No parent deadline. Without one each service close is bounded at 5s (`container.DefaultCloseTimeout`). Pass a timeout to `c.Close(ctx)`, overruns report `CloseTimeoutError`, panics `ClosePanicError`, failures join via `errors.Join`.
</details>
