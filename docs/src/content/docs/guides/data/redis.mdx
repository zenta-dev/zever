Most stateful services default to an in-memory adapter and offer a Redis twin. Develop with no server, then switch configuration (not code) in production. Use Redis for any service that two or more instances must share.

## Quick start

Point each service you want shared at the same `addr`. Services differ in where the Redis keys live.

<Tabs>
  <TabItem label="YAML">
```yaml title="zever.yaml"
cache:            # cache, queue, lock: flat keys
  adapter: redis
  options:
    addr: redis:6379
    pool_size: 20
    min_idle_conns: 2
queue:
  adapter: redis
  options:
    addr: redis:6379
lock:
  adapter: redis
  options:
    addr: redis:6379
session:          # session, ratelimit, eventbus, idempotency: nested redis block
  adapter: redis
  options:
    redis:
      addr: redis:6379
```
  </TabItem>
  <TabItem label="env">
```sh
CACHE_ADAPTER=redis
CACHE_ADDR=redis:6379
QUEUE_ADAPTER=redis
LOCK_ADAPTER=redis
SESSION_ADAPTER=redis
RATELIMIT_ADAPTER=redis
```
  </TabItem>
</Tabs>

```sh
docker run -p 6379:6379 redis:7
CACHE_ADAPTER=redis QUEUE_ADAPTER=redis go run ./cmd/myapp
```

```text
server listening on :8080 (cache=redis queue=redis)
```

Env matching ignores case and `_`. When a `url` is set it wins over `addr`. Bad addresses fail `Options.Validate()` at startup, not mid-request. Keep `memory` in unit tests: it needs no Docker and passes `goleak.VerifyTestMain`. See each service in the [config reference](../../../reference/config/#cache).

## Resolve the services

```go title="main.go"
import (
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
)

c := container.New(config.Default())
defer c.Close(ctx)

cache, err := c.Cache()
q, err := c.Queue()
locker, err := c.Lock()
sess, err := c.Session()
limiter, err := c.RateLimit()
```

Check `err` after each call. Each accessor resolves lazily and caches. On error the cache clears so the next call retries. `c.Job()` builds a dispatcher over the resolved `Queue`, and `c.Scheduler()` shares it, resolving `Queue` as a side effect.

## Decide which services use Redis

Switch per service. One service on Redis never drags the rest along.

| Service | Memory adapter | Redis role |
|---|---|---|
| `cache` | `memory` (LRU) | Shared value store through typed codecs |
| `queue` | `memory` | Topic messaging plus due and stale sweeps |
| `session` | `memory` | Server-side session rows |
| `ratelimit` | `memory` (token bucket) | Distributed counters (Lua) |
| `lock` | `memory` | Distributed leases (default `ttl` 30s) |
| `idempotency` | `memory` | Reserve-then-complete store |
| `eventbus` | `memory` (fan-out) | Cross-process publish/subscribe |

One instance may stay on `memory`. With two or more, use Redis for `session`, `lock`, `ratelimit`, and `queue`, or users stick to one instance, leases split, counters diverge, and jobs duplicate.

## Understand client ownership and behavior

- Sharing is configuration, not a client. Every adapter `New` returns its own client, and `Close` closes only that one. `c.Close(ctx)` dedups shared instances by pointer, so each closes once.
- `queue/redis` throttles its due and stale sweep (`promoteDue`, `reclaimStale`) to once per 250ms. That means fewer idle round trips and up to 250ms extra recovery latency.
- `ratelimit` denials return 429 JSON with a `Retry-After` header (ceiled seconds). Limiter errors fail open, so a Redis blip does not take the site down. Keys must be non-empty, bounded, and free of control bytes, and never echo in errors.
- `eventbus` keeps the same wire envelope (`id`, `payload`, `headers`) as memory. `SubscribeChan` gives each subscriber a buffered channel, and slow consumers drop the newest message without affecting others.
- `cache/redis` and `session/redis` use typed codecs, so keys and TTLs behave identically on both twins.
- Redis leases are real distributed locks. Memory locks are process-local.
- To open an adapter without the container, use `cache.Open`, `queue.Open`, or `lock.Open`. `Options.Validate()` also rejects negative TTLs and oversize prefixes.

## Production checklist

- Size `pool_size` and `min_idle_conns` for peak concurrency, and watch for timeout-shaped errors under load.
- Pass request contexts into cache, queue, and lock calls so Redis round trips observe deadlines.
- Give `c.Close(ctx)` a deadline. Without one, each service gets a 5s bound. Failures join with `errors.Join`, panics become `ClosePanicError`, and overruns become `CloseTimeoutError`.
- Display config only through `config.RedactedServices`. Addresses are safe to show. Passwords and option maps are not.

## Troubleshooting

<details>
<summary>Two instances serve different sessions</summary>

Cause: both run `memory` sessions. Fix: point both at the same Redis `addr`.
</details>

<details>
<summary>Rate limits diverge across replicas</summary>

Cause: `memory` token buckets are per process. Fix: set `ratelimit.adapter: redis` for a global quota.
</details>

<details>
<summary>Jobs run twice after a crash</summary>

Cause: the Redis sweep reclaims stale claims within about 250ms. Fix: make handlers idempotent, keyed by job ID.
</details>

<details>
<summary>Startup rejects the address</summary>

Cause: `Options.Validate()` found a malformed endpoint. Fix: use `host:port`. A `url`, when set, takes precedence over `addr`.
</details>

<details>
<summary>Shutdown hangs on Redis clients</summary>

Cause: the parent context has no deadline and a client blocks. Fix: pass a timeout context to `c.Close(ctx)`. Overruns report `CloseTimeoutError`.
</details>
