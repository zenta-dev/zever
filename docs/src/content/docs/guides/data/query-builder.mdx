The `orm` package is a generics-typed SQL builder over `db.DB`, not raw string SQL. Use it for every read and write behind handlers, workers, and seeds. Drop to raw `conn.Exec` only for shapes the DSL cannot express, such as FTS5 virtual-table DDL.

## Quick start

The ORM has no config of its own. It runs on the `db` service. Resolve the connection once and pass it to every call.

<Tabs>
  <TabItem label="sqlite">
```yaml title="zever.yaml"
db:
  adapter: sqlite
  options:
    path: app.db
```
  </TabItem>
  <TabItem label="postgres">
```yaml title="zever.yaml"
db:
  adapter: postgres
  options:
    dsn: postgres://app:secret@db:5432/app
    max_conns: 20
```
  </TabItem>
  <TabItem label="env">
```sh
DB_ADAPTER=postgres
DB_DSN=postgres://app:secret@db:5432/app
DB_MAXCONNS=20
```
  </TabItem>
</Tabs>

`config.Default()` uses sqlite so tests need no server. Postgres requires `dsn`. See the [db options](../../../reference/config/#db).

```go title="main.go"
c := container.New(config.Default())
conn, err := c.DB() // db.DB; the dialect resolves from conn.Dialect() per call
if err != nil {
    return err
}
defer c.Close(ctx)
```

## Define tables and models

A model implements `Scan(orm.Row) error`. Tables and columns are typed handles. `orm.From` infers the pointer-scanner type, so you never write type arguments.

```go title="models.go"
import "github.com/zenta-dev/zever/orm"

type User struct {
    ID   int64
    Name string
}

func (u *User) Scan(row orm.Row) error { return row.Scan(&u.ID, &u.Name) }

var (
    Users    = orm.NewTable[User]("users", []string{"id", "name"})
    UserID   = orm.NewColumn[User, int64]("users", "id")
    UserName = orm.NewColumn[User, string]("users", "name")
)
```

Use `orm.NewNullableColumn` for nullable columns. It adds `IsNull`, `IsNotNull`, `SetValue`, and `SetNull`.

## Select and filter rows

Chain `Where`, `OrderBy` (`Asc` or `Desc`), `Limit`, `Offset`, `Columns` (project a subset), `Distinct`, and `DistinctOn`, then finish with a read method.

```go
users, err := orm.From(Users).
    Where(UserName.Eq("alice")).
    OrderBy(UserID.Desc()).
    Limit(10).
    All(ctx, conn) // []*User
```

| Read method | Returns |
|---|---|
| `All` | all matching rows |
| `First` | one row plus `ok bool` |
| `FirstOrErr` | one row; wraps `db.ErrNotFound` on a miss |
| `Count` | `int64` over the same predicates |
| `Exists` | `bool` without fetching rows |
| `Stream` | `iter.Seq2` for constant-memory scans |

`Stream` holds its connection until you finish, so bound it with `ctx` and close promptly.

## Join, group, and compose queries

Joins run over a `Relation` and return typed composite rows.

```go
rel := orm.NewRelation[User, Booking]("id", "user_id", Bookings)
inner := orm.JoinOn(orm.From(Users), rel, orm.InnerJoin)
left := orm.LeftJoinOn(orm.From(Users), rel)

name, err := orm.NewCTEName("active_users")
cte := orm.With(name, orm.From(Users).Where(Active.Eq(true)))
```

| Feature | API |
|---|---|
| Joins | `JoinOn`, `LeftJoinOn`, `RightJoinOn`, `FullJoinOn`, the `JoinOn3` family, lateral variants |
| CTEs | `With`, `WithRecursive`, `WithJoin`, `WithGrouped`, `NewCTEName`, `CTETable` |
| Windows | `RowNumber`, `Rank`, `DenseRank`, `Lead`, `Lag`, `NTile`, `CountOver`, `SumOver`, `AvgOver`, `MinOver`, `MaxOver`, frame bounds (`Preceding`, `Following`, `CurrentRow`, unbounded variants) |
| Sets | `Union`, `UnionAll`, `Intersect`, `Except` |
| Inspection | `Explain`, `ExplainAnalyze` |

To load children without N+1 queries, use `orm.Preload(ctx, conn, parents, childFK, childBase, parentID, childFKOf)`. It returns `[]orm.ParentWithChildren`.

## Insert, update, and delete

`Values` and `Set` take assignments built with `orm.Set(column, value)`. `Update` and `Delete` return the affected row count.

```go
err := orm.InsertInto(Users).Values(orm.Set(UserName, "alice")).Exec(ctx, conn)

n, err := orm.UpdateTable(Users).
    Set(orm.Set(UserName, "bob")).
    Where(UserID.Eq(1)).
    Exec(ctx, conn)

n, err = orm.DeleteFrom(Users).Where(UserID.Eq(1)).Exec(ctx, conn)
```

- Upserts: `InsertInto(...).OnConflict(cols...).DoNothing()` or `.DoUpdate(sets...)`.
- Merges: `orm.MergeInto(table)`.
- Fetch affected rows in one round trip with `Returning` plus `ExecReturning`, where the dialect allows.

## Run transactions and retries

`db.WithTx` commits on success and rolls back on error or panic (re-panicking after rollback). Nesting it returns `db.ErrNestedTx`. Use `orm.WithNestedTx` for savepoints and `orm.RetryTx` for serialization retries.

```go
err = db.WithTx(ctx, conn, &db.TxOptions{Isolation: db.Serializable},
    func(ctx context.Context, tx db.Tx) error {
        _, err := orm.UpdateTable(Users).Set(orm.Set(UserName, "bob")).Where(UserID.Eq(1)).Exec(ctx, tx)
        return err
    })

err = orm.RetryTx(ctx, conn, orm.RetryOptions{MaxAttempts: 3}, func(ctx context.Context, tx db.Tx) error {
    return transfer(ctx, tx)
})
```

`RetryOptions` defaults to 3 attempts with a 10ms linear backoff. Savepoint names validate as `[_A-Za-z][_A-Za-z0-9]*`, never from user values.

## Paginate results

Offset pagination is 1-based and returns an `orm:` error for `page < 1` or `size < 1`. Keyset pagination stays correct when rows change between loads.

```go
q, err := orm.OffsetPage(orm.From(Users).OrderBy(UserID.Asc()), 2, 25) // LIMIT 25 OFFSET 25
total, err := orm.From(Users).Count(ctx, conn)

key := orm.NewCursorKey(UserID, lastSeenID)
next := orm.NextPage(orm.From(Users).OrderBy(key.OrderTerm()).Limit(25), key)
token := key.Encode()                           // opaque page token
back, ok, err := orm.DecodeCursor(token, UserID)
pred, err := orm.AfterTuple(cols, vals, false)  // multi-column keyset
```

The keyset predicate must mirror `OrderBy` exactly, tie-breaker included, or pages skip or duplicate rows. Run the example to see both styles:

```sh
go run ./examples/pagination/cmd/app
```

```text

  p15 gadget-15     7.49
  p22 gadget-22     7.49
keyset walk (page size 5, ascending price then id):
  page 1 (cursor ): p07:499 p14:499 p21:499 p01:749 p08:749
  page 2 (cursor AQAIcHJvZHVjdHMCaWRzA3AwOA): p15:749 p22:749 p02:999 p09:999 p16:999
```

## Lock rows, query JSON, and search text

Row locks: `ForUpdate`, `ForShare`, `ForNoKeyUpdate`, `ForKeyShare`, `ForUpdateOf`, then `NoWait` or `SkipLocked`.

Store JSON in a TEXT column typed `orm.JSONText`. Predicates come from `orm/json/sqlite` (nested keys, key existence, `json_each` membership, `json_type`) and a postgres twin over jsonb. Full-text search uses `orm/fts/sqlite` (`Match`, `Rank`) and a postgres twin over `tsvector`. The query text is always a bound argument, so FTS5 syntax never reaches the SQL text. Create the FTS5 virtual table with raw DDL in a migration.

```sh
go run ./examples/fts/cmd/app
```

```text
body matches "go": [d1 "Go release" d4 "Go on the web"]
```

More runnable examples: `./examples/json_query/cmd/app` and `./examples/recursive_cte/cmd/app`.

## Handle dialect differences

Features a dialect lacks fail closed with `dialect.ErrUnsupportedByDialect`. There is no silent fallback. `DISTINCT ON` and strong lock modes are postgres-only. Right and full joins and recursive CTEs gate by capability.

```go
rows, err := q.All(ctx, conn)
if errors.Is(err, dialect.ErrUnsupportedByDialect) {
    rows, err = portableQuery.All(ctx, conn)
}
```

All errors carry an `orm:` prefix (`orm/render:`, `orm/dialect:`) and stay `errors.Is` compatible. `ErrUnsupportedByDialect` prints as `orm/dialect: unsupported by dialect`.

## Production checklist

- Develop on sqlite `:memory:`, gate postgres-only features with `errors.Is`, and run the live pass before release:

  ```sh
  go test ./orm/... && POSTGRES_DSN='postgres://user:pass@localhost:5432/test?sslmode=disable' go test ./orm/...
  ```
- SQL text holds placeholders, never values. Display config only through `config.RedactedServices`.
- Pass `ctx` into every call. The ORM holds no pool; `c.Close(ctx)` closes the `db` pool.

## Troubleshooting

<details>
<summary>`ErrUnsupportedByDialect` on sqlite</summary>

Cause: the query uses a postgres-only feature, such as `DISTINCT ON` or a strong lock mode. Fix: match with `errors.Is` and use a portable formulation on sqlite.
</details>

<details>
<summary>Keyset pages skip or duplicate rows</summary>

Cause: the `AfterTuple` columns do not mirror `OrderBy`. Fix: keep `(price_cents ASC, id ASC)` identical in both, including the tie-breaker.
</details>

<details>
<summary>`:memory:` tests see empty tables</summary>

Cause: a second pooled connection opened its own empty database. Fix: sqlite `:memory:` forces one connection, so do not raise `max_conns` for it.
</details>
