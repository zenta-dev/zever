`secrets` returns one named credential on demand, without it sitting in a YAML file or a log line. Use it for API keys, webhook signing secrets, and provider tokens. `config` answers "what value does this field have"; `secrets` answers "give me this one credential". They are deliberately separate services.

## Quick start

```yaml title="zever.yaml"
secrets:
  adapter: env
  options:
    prefix: ZEVER
```

```sh
SECRETS_PREFIX=ZEVER
ZEVER_STRIPE_KEY=sk_live_...
ZEVER_WEBHOOK_SECRET=whsec_...
```

The `env` adapter requires a non-empty `prefix` (default `ZEVER`) that contains no `/`, `..`, or spaces. With prefix `ZEVER`, secret `DEMO_KEY` reads the variable `ZEVER_DEMO_KEY` exactly. See the [secrets config reference](../../../reference/config/#secrets).

## Read a secret

```go title="main.go"
package main

import (
	"context"
	"fmt"
	"os"

	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
)

func main() {
	os.Setenv("ZEVER_DEMO_KEY", "s3cr3t")
	c := container.New(config.Default())
	ctx := context.Background()
	defer c.Close(ctx)

	s, err := c.Secrets()
	if err != nil {
		fmt.Println("resolve error:", err)
		return
	}
	val, _ := s.Get(ctx, "DEMO_KEY")
	fmt.Println("bytes:", len(val))
	names, _ := s.List(ctx)
	fmt.Println("count:", len(names))
}
```

Expected output:

```text
bytes: 6
count: 1
```

Assert on the value length, never the value. `Secrets()` resolves lazily like every accessor. Its `Close(ctx)` takes a context, unlike most services.

## Use Vault for rotation and payments

The `env` adapter cannot write back to the process environment, so `Set` and `Delete` always return `secrets.ErrNotSupported`. Rotation with `env` means restarting with new env values. For anything that handles payment credentials, use the `vault` adapter (KV v2): `Get`, `Set`, `Delete`, and `List` over HTTP with a 5s default timeout, and values never appear in errors.

```yaml title="zever.yaml"
secrets:
  adapter: vault
  options:
    addr: https://vault.internal:8200
    mount: secret
    token_file: /run/secrets/vault-token
```

`addr` (with scheme and host), `mount` (no spaces or `..`), and one of `token` or `token_file` are required. `namespace` is optional. Register the adapter with `vault.Register()` from `adapters/secrets/vault`.

## Choose an adapter

| Adapter | Package | Use when |
|---|---|---|
| `env` | `secrets/env` | Default. Read-only `<PREFIX>_<NAME>` lookup. |
| `vault` | `secrets/vault` | Runtime writes, rotation, SOC2 or PCI scope. |

`ValidateName` rejects names containing `/` or `..`, so a secret name cannot traverse a hierarchical backend.

## Production checklist

- Prefer `secrets` over config env for anything that signs money or auth: `payment` `webhook_secret`, the `auth` JWT secret, provider keys.
- Values never appear in errors, only service and field names, the same discipline as `config.RedactedServices`.

## Troubleshooting

<details>
<summary>`Secrets()` fails at startup with a prefix error</summary>

`prefix` is empty or contains `/`, `..`, or a space. Set `SECRETS_PREFIX` to a plain namespace such as `ZEVER`.
</details>

<details>
<summary>`Get` reports "not found" for an exported variable</summary>

The lookup is `<PREFIX>_<NAME>` exactly, including case. With prefix `ZEVER`, name `DEMO_KEY` needs `ZEVER_DEMO_KEY`.
</details>

<details>
<summary>`Set` always fails</summary>

That is the contract for `env`: read-only by design. Store the value in the environment or process manager, or switch to `vault`.
</details>
