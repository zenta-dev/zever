---
title: Locks and idempotency
description: Guard critical sections with distributed locks and make retried jobs and webhooks take effect once.
---

`lock` gives mutual exclusion, `idempotency` dedupes retries. `Locker` offers `TryAcquire`, blocking `Acquire` (polls `retry_interval`, default 50ms), `Extend`, ownership-checked `Unlock`, `Store` reserves keys with `Begin` and records outcomes with `Complete`, so retries replay stored results.

## Quick start

Both default to `memory` (single-process), register adapters first, the container wires nothing.

```go title="main.go" check
package main

import (
    "context"
    "fmt"
    "time"

    idemmemory "github.com/zenta-dev/zever/adapters/idempotency/memory"
    lockmemory "github.com/zenta-dev/zever/adapters/lock/memory"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/idempotency"
    "github.com/zenta-dev/zever/core/lock"
)

func main() {
    c := container.New(config.Default(),
        container.Provide(lock.DefaultRef(), lockmemory.New),
        container.Provide(idempotency.DefaultRef(), idemmemory.New),
    )
    lk, err := c.Lock()
    if err != nil {
        panic(err)
    }
    idem, err := c.Idempotency()
    if err != nil {
        panic(err)
    }

    ctx := context.Background()
    lease, ok, err := lk.TryAcquire(ctx, "booking:room-1:2026-01-01:2026-01-03", 30*time.Second)
    fmt.Println(ok, err)
    if ok {
        defer lease.Unlock(ctx)
    }
    out, err := idem.Begin(ctx, "booking:req-1", idempotency.BeginOptions{Fingerprint: []byte("guest|room-1")})
    fmt.Println(out.Replay, err)
    if !out.Replay {
        _ = idem.Complete(ctx, "booking:req-1", []byte("guest|room-1"), []byte(`{"status":"confirmed"}`))
    }
}
```

```text
true <nil>
false <nil>
```

Repeated identical `Begin` prints `true <nil>` with stored bytes.

## Guard bookings

Bookings handler runs `RateLimit.Allow`, `Idempotency.Begin` (`booking:<key>`, fingerprint `guest|space|start|end`), then `Lock.TryAcquire` on `booking:<space>:<start>:<end>` (30s TTL) around overlap check, charge, insert.

| Outcome | Status |
|---|---|
| Finished-request replay | Stored bytes. |
| `ErrInProgress` | `409`. |
| `ErrKeyMismatch` | `400`. |

Key the lock on the contended range, idempotency on a stable external ID (webhook event ID, job dedupe key), never raw payload bytes. Idempotency fails closed.

## Share across replicas

`memory` is per-replica, so instances can double-book or duplicate webhook effects. Move both to `redis` (or `idempotency` to `db`).

```sh
LOCK_TTL=30s
LOCK_RETRY_INTERVAL=50ms
LOCK_PREFIX=bookings:
IDEMPOTENCY_TTL=24h
```

Lock Redis keys are top-level (`addr`, `url`, `password`, `db`, `tls`), `idempotency` nests them under `redis:` (`redis.addr`, `redis.prefix`). Lock `Validate` is a no-op, each adapter validates its own fields. Idempotency rejects negative `ttl` (zero is 24h) and bad Redis `addr`/`prefix`. Keys cap at 255 bytes (`MaxKeyLen`). `adapters/lock/{memory,redis}`, `adapters/idempotency/{memory,redis,db}` (`db` via `dsn`, `dedicated_pool`). See [lock](../../../reference/config/#lock), [idempotency](../../../reference/config/#idempotency).

## Production checklist

- `Lock.Close(ctx)` takes a context, `Store.Close()` none. Neither releases held leases/reservations, locks expire on TTL (default 30s), plan expiry.
- Fingerprints may carry PII, keep them and raw options out of logs (`cfg.RedactedServices()`).

## Troubleshooting

<details>
<summary>`409` without real overlap</summary>

Prior attempt or crashed worker holds the lock until 30s TTL expiry. Wait out the TTL, scope keys tighter, always `defer Unlock`.
</details>

<details>
<summary>`409` never clears</summary>

`Begin` without `Complete` stays pending until TTL. `Complete` every post-reservation path, or `Forget` the key.
</details>

<details>
<summary>`400 idempotency key mismatch`</summary>

Same key, different fingerprint (key reuse across payloads). Key on a per-attempt ID (header/body `idempotency_key`), not guest plus dates.
</details>
