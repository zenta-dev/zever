`password` hashes, verifies, and reports whether a stored hash needs rehashing, all through Argon2id with safe defaults. It issues no tokens and stores nothing: tokens are [Authentication](../auth/), encryption is [Crypto and secrets](../crypto-secrets/). `argon2id` is the only adapter, so the only decision is whether to retune (usually, do not).

## Quick start

```yaml title="zever.yaml"
password:
  adapter: argon2id
  options:
    time: 3
    memory: 65536
    threads: 4
```

```sh
PASSWORD_ADAPTER=argon2id
```

Defaults: `Time` 3 iterations, `Memory` 65536 KiB (64 MiB), `Threads` 4, `SaltLen` 16 bytes, `KeyLen` 32 bytes. Maximum plaintext is 1024 bytes; longer input is rejected, not hashed. See the [password config reference](../../../reference/config/#password).

## Hash at register, verify at login

```go title="login.go"
pw, err := c.Password()
if err != nil {
    return err
}
hash, err := pw.Hash(ctx, "correct horse battery staple")
if err != nil {
    return err
}
ok, err := pw.Verify(ctx, hash, "correct horse battery staple")
if err != nil {
    return err
}
rehash, err := pw.NeedsRehash(ctx, hash)
```

Expected values:

```text
hash:   $argon2id$v=19$m=65536,t=3,p=4$<salt>$<key>
ok:     true
rehash: false (true after a cost-parameter bump)
```

The stored form is PHC. Salts come from `crypto/rand` and comparison is constant-time.

| Verify outcome | Meaning | Action |
|---|---|---|
| `true, nil` | Match. | Proceed, and rehash if flagged. |
| `false, nil` | Mismatch. | Reject with a generic error. |
| `_, ErrInvalidHash` | Stored value corrupt. | Force a password reset. |

Check `ErrInvalidHash` with `errors.Is`, not string comparison.

## Retune costs without a forced reset

1. Benchmark candidate parameters on production-class hardware (a laptop number can be too cheap).
2. Deploy the new parameters. Old hashes keep verifying.
3. On each successful login, `NeedsRehash` flags stale hashes.
4. Hash the presented plaintext with the new parameters and persist it.
5. Track the stale-hash ratio until it reaches zero.

## Production checklist

- Hashing cost makes each guess expensive but does not limit attempts. Rate-limit login separately, see [Rate limiting](../ratelimit/).
- Never log plaintext passwords or hashes. Error text names the failure, never the value.

## Troubleshooting

<details>
<summary>`ErrInvalidHash` on a known account</summary>

The stored value is truncated or corrupted. Confirm with `errors.Is`, then force a password reset.
</details>

<details>
<summary>Logins slow to a crawl</summary>

Cost parameters exceed what the fleet sustains. Benchmark, lower toward the defaults, and scale horizontally first.
</details>

<details>
<summary>`NeedsRehash` is true for every user</summary>

Parameters changed since the hashes were minted. Rehash on each account's next successful login.
</details>

<details>
<summary>Password rejected for length</summary>

The plaintext exceeds 1024 bytes. Reject it at the boundary with a clear validation error before hashing.
</details>
