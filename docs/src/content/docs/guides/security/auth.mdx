`auth` answers who is calling, never what they may do, via `jwt` (`auth/jwt`), `session` (`auth/session`), `oidc` (`auth/oidc`). See [Password hashing](../password-hashing/) and [Authorization](../authz-permissions/).

## Quick start

Set a 32+ byte JWT secret, then resolve, `Open` refuses shorter, `config.Default()` ships none.

<Tabs>
  <TabItem label="YAML">
```sh
AUTH_JWT_SECRET=change-me-to-at-least-32-bytes
```
  </TabItem>
  <TabItem label="env">
```sh
AUTH_JWT_SECRET=prod-secret-at-least-32-bytes-long
```
  </TabItem>
</Tabs>

```go title="main.go"
c := container.New(cfg)
a, err := c.Auth()
if err != nil {
    return err // secret too short, or adapter unavailable
}
```

`AUTH_JWT_SECRET` maps to `options.jwt.secret` (env splits at the first underscore). Full key list: `AUTH_JWT_ISSUER`, `AUTH_JWT_AUDIENCE`, `AUTH_JWT_MAX_TTL`, `AUTH_JWT_LEEWAY`, `AUTH_OIDC_ISSUER`, `AUTH_OIDC_CLIENT_ID`, `AUTH_OIDC_TIMEOUT`, `AUTH_OIDC_ALLOW_INSECURE`. See [auth config reference](../../../reference/config/#auth).

## Key rotation

List accepted keys by `kid`, `active_kid` signs. New tokens carry `kid`, verification selects by `kid`, still accepting kid-less tokens signed with legacy `secret`. Unknown kids fail closed, keep retired keys until expiry. HS256 only, asymmetric needs custom adapter, `alg: none` rejected.

```sh
AUTH_JWT_SECRET=previous-secret-at-least-32-bytes-long
AUTH_JWT_LEEWAY=30s
```

`jwt.keys` has no string form, wire it in Go via `auth.Options.JWT.Keys` or `container.WithOptions`. `AUTH_JWT_ACTIVE_KID` is rejected without keys.

Future `nbf` rejected, `exp` required. Both honor `leeway` (default `0`, strict).

## Log in and call with a bearer token

Log in, then reuse the token:

```sh
curl -s -X POST localhost:8080/api/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com","password":"correct horse battery staple"}'
curl -s localhost:8080/api/spaces -H "Authorization: Bearer $TOKEN"
```

Login returns `200` with JWT in `token`, register `201`, missing/invalid `401`. `Issue` mints, `Verify` checks, `Revoke` invalidates. `jwt` keeps revoked `jti`s per-process, `session` uses its store. `Verify` returns `ErrInvalidToken` vs `ErrTokenExpired`, map both to one `401`. Log details server-side, never token values.

## Production checklist

- CSPRNG secret (32+ bytes) in env or mounted file, never source. See [Secrets](../secrets/).
- Rotate with overlap: add key, flip `jwt.active_kid`, remove old key after expiry.
- Prefer `session` for cross-instance revocation. JWT revocation is per-process by default, multi-instance must inject the shared `revocation/redis` store via `auth.JWTOptions.RevocationStore`.
- Rate-limit login, hashing cost is not an attempt limit. See [Rate limiting](../ratelimit/).
- Display config only via `cfg.RedactedServices()` or `config.Redact`.

## Troubleshooting

<details>
<summary>`Open` rejects the JWT secret</summary>

Shorter than 32 bytes (`MinSecretLen`). Set a longer `AUTH_JWT_SECRET`.
</details>

<details>
<summary>Logins return 401 after rotation</summary>

Old-secret tokens fail: retired `kid` left `jwt.keys` early, or `active_kid` points at missing key. Restore old key, fix `active_kid`, or log in again.
</details>

<details>
<summary>Session adapter fails at startup</summary>

Needs injected `session.Store` (Go-only, not config). Wire a shared store for multiple instances.
</details>

<details>
<summary>OIDC login loops</summary>

Redirect URL and callback disagree. Align app registration with deployed callback URL.
</details>
