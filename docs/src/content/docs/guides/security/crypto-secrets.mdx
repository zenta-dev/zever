---
title: Crypto and secrets
description: Encrypt and sign data with one key service, and read named credentials from env or Vault.
---

`crypto` encrypts/signs payloads and fields at rest or in transit, `secrets` looks up credentials such as API keys and connection strings. Independently resolved, passwords never encrypted (see [Password hashing](../password-hashing/)).

## Quick start

`config.Default()` ships a deterministic dev key for tests, it is public, so anything encrypted under it is recoverable. Local adapter accepts it only with `CRYPTO_ALLOW_DEV_KEY=true` or `ZEVER_ENV=dev`, `test`, `development`, otherwise set a real key.

```sh
CRYPTO_KEY=MDEyMzQ1Njc4OTAxMjM0NTY3ODkwMTIzNDU2Nzg5MDE=
CRYPTO_ALLOW_DEV_KEY=true
SECRETS_PREFIX=ZEVER
```

```sh
CRYPTO_KEY=MDEyMzQ1Njc4OWFiY2RlZjAxMjM0NTY3ODlhYmNkZWY=
export ZEVER_STRIPE_KEY=sk_test_example
```

```go title="main.go"
cr, err := c.Crypto()   // key missing, malformed, or dev key without allow
sec, err := c.Secrets() // prefix invalid
```

`sign_key` optional, must decode to 64 bytes. `STRIPE_KEY` resolves to `ZEVER_STRIPE_KEY`. Without env, `config.Default()` still resolves on the dev key. Keys: [crypto](../../../reference/config/#crypto), [secrets](../../../reference/config/#secrets).

## Pick an adapter

`crypto`: `local` (default, AES-256-GCM) or `kms` (envelope: `key_id`, `key_ids`, `region`, `endpoint`, `use_envelope`, real client via `NewWithClient`). Encrypt uses `key_id`, decrypt accepts `key_id` or any `key_ids` entry. `secrets`: `env` (default, `<PREFIX>_<NAME>`, `prefix` defaults to `ZEVER`) or `vault` (KV v2, [Secrets](../secrets/)). Vault escapes each `/` segment of the mount, so nested mounts work and reserved chars cannot shift path segments.

## Rotate the crypto key

1. Generate a CSPRNG key into env.
2. Dual-read: decrypt old, re-encrypt new, persist.
3. Track old-key rows to zero.
4. Remove old key, verify decrypts.

Record encrypted fields and key generation in the runbook.

## Production checklist

- Real CSPRNG key in env or mounted file, via secret manager.
- `allow_dev_key` unset (or false) and `ZEVER_ENV` not dev/test/development, else `Open` fails with `DevKeyError`.
- Audit both `crypto` and `secrets`.
- Never log raw option maps, use `cfg.RedactedServices()` or `config.Redact`, errors name services/fields, never values.

## Troubleshooting

<details>
<summary>Old rows decrypt to garbage</summary>

Wrong-key rows, often dev key. Re-encrypt during migration.
</details>

<details>
<summary>Secrets lookup misses</summary>

Name lacks prefix or boundary underscore (`STRIPE_KEY` vs `ZEVER_STRIPE_KEY`).
</details>

<details>
<summary>`Open` rejects the secrets prefix</summary>

Empty or has slash, `..`, spaces, use a plain prefix such as `ZEVER`.
</details>

<details>
<summary>`Open` rejects the dev key with DevKeyError</summary>

Public dev key without explicit allow. Set a real `crypto.options.key`, or `allow_dev_key: true` / dev `ZEVER_ENV`.
</details>

<details>
<summary>Key material appears in logs</summary>

Some path logs raw options, display via `cfg.RedactedServices()`/`config.Redact`.
</details>
