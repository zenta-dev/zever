`.zen` shape rules plus handler checks, failing with field-named errors, never silent coercion. No config.

## Validate

Shape rules ([Zen syntax](../../../reference/zen-syntax/)):

```zen
rpc CreateUser(email: string @validate(format: "email")) -> User {
  http: POST "/v1/users"
  errors: { already_exists }
}

// on an entity field:
title: string @validate(min_len: 1, max_len: 200)
```

The resolver checks every expression at compile time, `@validate` reaches generated code and OpenAPI.

Parse and validate before `db`, `queue`, or payment, failures never open transactions or side effects.

```go title="handlers.go"
func createUser(w http.ResponseWriter, r *http.Request) {
    var in struct {
        Email string `json:"email"`
        Name  string `json:"name"`
    }
    if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
        writeError(w, http.StatusBadRequest, "invalid body")
        return
    }
    if !strings.Contains(in.Email, "@") {
        writeError(w, http.StatusUnprocessableEntity, "email: must be a valid address")
        return
    }
    if strings.TrimSpace(in.Name) == "" {
        writeError(w, http.StatusUnprocessableEntity, "name: required")
        return
    }
    writeJSON(w, http.StatusCreated, map[string]string{"email": in.Email})
}
```

```sh
curl -s -X POST localhost:8080/v1/users -d '{"email":"a@example.com","name":"Ada"}'
```

```text
{"email":"a@example.com"}
```

Invalid input is 422 (`writeJSON`/`writeError`: [Requests and responses](../requests-responses/)).

## Split rules

| Kind | Owner | Example |
|---|---|---|
| Shape | `.zen` `@validate` | `email`, lengths |
| Transport | Handler | JSON/headers |
| Business | Handler/store | unregistered (409) |
| Config | Startup `Validate` | Options/DSN |

Bookings: format rules on entities (`User.email`, `Space.title`), flow rules in `internal/api`, `core/flag` gates 404, `ErrConflict` -> 409, OpenAPI covers schema only.

## Config

`config.Resolve(env)` is strict: unknown keys under wired prefixes fail fast with did-you-mean hints, unparsable values return `InvalidOptionsError` naming service/field, never the secret. Unknown service heads and bare names are ignored.

## Checklist

- Name field/rule, never rejected secret, validate before I/O, RPC error-set changes are API changes (`breaking`).

## Troubleshooting

<details>
<summary>`zever check` rejects a rule the handler accepts</summary>

Typo or unsupported constraint, the resolver is authoritative and `zever check` reports each bad rule with its file position.
</details>

<details>
<summary>400 for business errors</summary>

400 is unparsable, 422 is invalid.
</details>

<details>
<summary>Missing 409s</summary>

RPC lacks `errors: { already_exists }`, or handler misses conflict.
</details>

<details>
<summary>Boot fails on a typo</summary>

Strict decoding rejects unknown fields, use snake_case (`max_conns`).
</details>
