Stay close to `net/http`: decode, run logic, encode JSON, no binding or config.

## Handle

Container: services, not I/O:

```go title="main.go"
c := container.New(config.Default())
db, _ := c.DB()
r, _ := c.Router()
r.Handle("POST", "/v1/users", createUser(db))
```

```go title="handlers.go"
func createUser(db db.DB) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        var in struct {
            Email string `json:"email"`
            Name  string `json:"name"`
        }
        if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
            writeError(w, http.StatusBadRequest, "invalid body")
            return
        }
        if strings.TrimSpace(in.Email) == "" {
            writeError(w, http.StatusUnprocessableEntity, "email: required")
            return
        }
        writeJSON(w, http.StatusCreated, map[string]string{"email": in.Email})
    }
}

func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    _ = json.NewEncoder(w).Encode(v)
}

func writeError(w http.ResponseWriter, status int, msg string) {
    writeJSON(w, status, map[string]string{"error": msg})
}
```

```sh
curl -s -X POST localhost:8080/v1/users -H 'Content-Type: application/json' -d '{"email":"a@example.com","name":"Ada"}'
```

```text
{"email":"a@example.com"}
```

Success returns the resource (`200`/`201`), failures use a stable `{"error": "..."}`. Set `Content-Type` before `WriteHeader`.

## Read

| Source | How |
|---|---|
| Path | `router.Param(req, name)`, `router.ParamNames(req)` |
| Query | `r.URL.Query().Get(key)` |
| Headers | `r.Header.Get(key)` |
| Body | `json.NewDecoder(r.Body).Decode(&v)` |
| Cap | `http.MaxBytesReader(w, r.Body, n)` |
| Tests | `router.WithParams(ctx, params)` |
| Cancellation | `r.Context()` into DB/cache/queue |

Cap public bodies (413), thread `r.Context()` downstream.

## Paginate

`paginated: true` RPCs expose cursors, not offsets:

```sh
GET /v1/orders?cursor=eyJpZCI6NDJ9&limit=50
```

Synthesized requests carry both fields (gRPC included), RPCs never declare them. Service methods: opaque `cursor string`, `limit int32`. Transports bound: zero means 20, over 100 clamps, negatives fail `InvalidArgument`. Response `<Op>Response` holds `items` and `next_cursor` (empty when last).

```go
key := orm.NewCursorKey(UserID, lastSeenID)
users, err := orm.NextPage(
    orm.From(Users).OrderBy(UserID.Asc()),
    key,
).Limit(50).All(ctx, conn)
```

`orm.OffsetPage(q, page, size)` applies 1-based `LIMIT`/`OFFSET`, returning `(Query, error)`, `CursorKey.Encode()`, `orm.DecodeCursor(token, col)`, and `orm.AfterTuple` cover keyset cursors and multi-column predicates.

## Troubleshooting

<details>
<summary>Empty body, no error</summary>

`r.Body` consumed or nil, use `httptest.NewRequest` with `strings.Reader`.
</details>

<details>
<summary>Empty params under test</summary>

Test requests lack context, seed with `router.WithParams`.
</details>

<details>
<summary>Huge uploads exhaust memory</summary>

Cap with `MaxBytesReader` (413).
</details>

<details>
<summary>JSON arrives without a content type</summary>

Set `Content-Type` before `WriteHeader` since headers written after are dropped.
</details>

<details>
<summary>Deadlines have no effect</summary>

Thread `r.Context()` everywhere downstream.
</details>
