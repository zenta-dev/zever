Zever handlers stay close to `net/http`: decode the request, run your logic, and encode a consistent JSON envelope. There is no magic binding and no config block. Use this pattern for hand-written routes beside generated `.zen` services (the bookings server does both).

## Quick start

Handlers need the container only for services, never for I/O:

```go title="main.go"
// Once at startup: dbsqlite.Register(); routerstdhttp.Register()
// (aliases for adapters/db/sqlite and adapters/router/stdhttp)
c := container.New(config.Default())
db, err := c.DB()
if err != nil {
    return err
}
r, err := c.Router()
if err != nil {
    return err
}
r.Handle("POST", "/v1/users", createUser(db))
```

```go title="handlers.go"
func createUser(db db.DB) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        var in struct {
            Email string `json:"email"`
            Name  string `json:"name"`
        }
        if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
            writeError(w, http.StatusBadRequest, "invalid body")
            return
        }
        if strings.TrimSpace(in.Email) == "" {
            writeError(w, http.StatusUnprocessableEntity, "email: required")
            return
        }
        writeJSON(w, http.StatusCreated, map[string]string{"email": in.Email})
    }
}

func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    _ = json.NewEncoder(w).Encode(v)
}

func writeError(w http.ResponseWriter, status int, msg string) {
    writeJSON(w, status, map[string]string{"error": msg})
}
```

```sh
curl -s -X POST localhost:8080/v1/users -H 'Content-Type: application/json' -d '{"email":"a@example.com","name":"Ada"}'
curl -s -X POST localhost:8080/v1/users -H 'Content-Type: application/json' -d '{"email":""}'
```

```text
{"email":"a@example.com"}
{"error":"email: required"}
```

Success returns the resource with `200` (`201` on create). Errors use `{"error": "<stable message>"}`, the same envelope `middleware.Recover` uses for 500s and rate limiting uses for 429s (plus `Retry-After`). Set `Content-Type` before `WriteHeader`. Accessors resolve lazily and `c.Close(ctx)` closes what you resolved ([container](../../../concepts/container/)).

## Read the request

| Source | How |
|---|---|
| Path params | `router.Param(req, name)`, `router.ParamNames(req)` |
| Query string | `r.URL.Query().Get(key)` |
| Headers | `r.Header.Get(key)` |
| JSON body | `json.NewDecoder(r.Body).Decode(&v)` |
| Body size cap | `http.MaxBytesReader(w, r.Body, n)` |
| Test params | `router.WithParams(ctx, params)` |
| Cancellation | `r.Context()`, passed into DB, cache, and queue calls |

Cap the body on public endpoints and return 413 past the limit. Always pass `r.Context()` downstream so `middleware.Timeout` deadlines propagate. Keep stdout clean: write diagnostics and errors to stderr.

## Paginate lists

`.zen` RPCs flagged `paginated: true` generate cursor scaffolding. Expose opaque cursors, not offsets:

```sh
GET /v1/orders?cursor=eyJpZCI6NDJ9&limit=50
```

```go
key := orm.NewCursorKey(UserID, lastSeenID)
users, err := orm.NextPage(
    orm.From(Users).OrderBy(UserID.Asc()),
    key,
).Limit(50).All(ctx, conn)
```

The pagination example also shows `orm.OffsetPage(q, page, size)` with `Count`, and keyset pages via `orm.AfterTuple` with `orm.NewCursorKey(...).Encode` and `orm.DecodeCursor`. Return the next cursor beside the page so clients never build keyset predicates.

## Troubleshooting

<details>
<summary>An empty body decodes without error</summary>

`r.Body` was consumed or is nil in a test. Use `httptest.NewRequest` with a `strings.Reader` body and set `Content-Type`.
</details>

<details>
<summary>Params are always empty under test</summary>

Plain test requests carry no driver context. Seed with `router.WithParams`.
</details>

<details>
<summary>The client sees `Content-Type: text/plain`</summary>

`WriteHeader` ran before the header was set. Set `Content-Type`, then status, then body.
</details>

<details>
<summary>Huge uploads exhaust memory</summary>

The route has no `MaxBytesReader`. Wrap `r.Body` and return 413 past the cap.
</details>

<details>
<summary>Deadline middleware has no effect</summary>

A handler or ORM call uses `context.Background()`. Thread `r.Context()` through.
</details>
