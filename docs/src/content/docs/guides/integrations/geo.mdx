One `Geo` interface covers `Geocode`, `ReverseGeocode`, and `Distance` (meters between two points), so callers stay fixed while the backend changes between tests and production.

## Quick start

`static` (the default) serves a file-backed list from memory, offline and deterministic. `path` points at a JSON fixture.

```yaml title="zever.yaml"
geo:
  adapter: static
  options:
    path: data/cities.json
```

```go title="main.go"
package main

import (
    "context"
    "fmt"

    "github.com/zenta-dev/zever/adapters/geo/static"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/geo"
)

func main() {
    static.Register() // container wires nothing
    c := container.New(config.Default())
    g, err := c.Geo()
    if err != nil {
        panic(err)
    }
    defer g.Close()

    ctx := context.Background()
    locs, err := g.Geocode(ctx, "Berlin")
    fmt.Println(len(locs), err)
    d, err := g.Distance(ctx, geo.Point{Lat: 52.52, Lng: 13.40}, geo.Point{Lat: 48.85, Lng: 2.35})
    fmt.Println(d, err)
}
```

Expected output with a seeded-cities fixture (the distance depends on the data; the shape is a count, then meters as a float):

```text
1 <nil>
878000 <nil>
```

The bookings example pins `geo.adapter: static`, and its tests point `cfg.Geo.Options.Path` at `testdata/cities.json`. `ValidCoord` checks WGS84 range and finiteness before coordinates reach a provider, catching swapped lat/lng or NaN early.

## Use OSM or Google in production

Use `osm` for free OpenStreetMap geocoding when Google-grade accuracy is not needed. It requires a `user_agent` per the Nominatim usage policy. Use `google` when accuracy matters and you have an API key budget.

```yaml title="zever.yaml"
geo:
  adapter: osm
  options:
    endpoint: https://nominatim.openstreetmap.org
    user_agent: bookings-demo/1.0
```

```yaml title="zever.yaml"
geo:
  adapter: google
  options:
    api_key: ${GEO_API_KEY}
    base_url: https://maps.googleapis.com
```

```sh
GEO_ADAPTER=osm
GEO_USERAGENT=bookings-demo/1.0
GEO_APIKEY=secret-key
GEO_ALLOWINSECURE=false
```

`Validate` rejects negative `timeout` or `max_response_body`, and any `base_url` or `endpoint` that is not a valid `https` URL unless `allow_insecure` is set. See the [geo config reference](../../../reference/config/#geo).

| Adapter | Package | Notes |
|---|---|---|
| `static` | `adapters/geo/static` | Default. File-backed, offline, deterministic. |
| `osm` | `adapters/geo/osm` | OpenStreetMap. Requires `user_agent`. |
| `google` | `adapters/geo/google` | Needs `api_key`. |

## Production checklist

- `Geo.Close() error` takes no context. The container closes only resolved services in dependency order and joins errors with `errors.Join`.
- `static` is per-process memory, so every replica needs the same fixture. `osm` and `google` are remote and slow relative to a request handler, so put them behind a [cache](../../data/cache/) or a job. Coordinates per address rarely change.
- `api_key` is secret. Never log raw option maps (use `config.RedactedServices`).

## Troubleshooting

<details>
<summary>`zever doctor` reports FAIL on geo</summary>

Expected with zero-infra defaults when `cities.json` (or any `path` fixture) is missing. The bookings README records it. Seed the fixture or point `path` at committed test data. It is a fixture gap, not a framework bug.
</details>

<details>
<summary>`base_url must use https` error</summary>

External adapters require `https`. `allow_insecure` exists only for tests with `httptest` servers. Never enable it in production.
</details>

<details>
<summary>OSM rejects requests</summary>

The `user_agent` is missing or generic. Set a real app-identifying `User-Agent` per Nominatim policy, and cache results to stay inside usage limits.
</details>
