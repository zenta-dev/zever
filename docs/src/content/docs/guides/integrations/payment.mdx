`payment.Payment` creates, refunds, fetches, and decodes webhooks identically across `stub`, `stripe`, `paddle`, customers and subscriptions live in [Billing](../billing/).

## Quick start

`stub` is default, `auto_approve: true` marks payments `succeeded` immediately (test success without webhook).

```sh
PAYMENT_AUTO_APPROVE=true
PAYMENT_MAX_WEBHOOK_BYTES=1048576
```

Provider keys from `shared/providersopt`: `secret_key` (Stripe), `api_key` (Paddle), `endpoint`, `sandbox`. Plus `webhook_secret` (keep in env), `auto_approve`, `max_webhook_bytes` (default 1MiB, negatives rejected). See [payment config reference](../../../reference/config/#payment).

```go title="main.go" check
package main

import (
	"context"
	"fmt"

	paymentstub "github.com/zenta-dev/zever/adapters/payment/stub"
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
	"github.com/zenta-dev/zever/core/payment"
)

func main() {
	c := container.New(config.Default(), container.Provide(payment.DefaultRef(), paymentstub.New,
		container.WithOptions(func(o *payment.Options) { o.AutoApprove = true }),
	))
	ctx := context.Background()
	defer c.Close(ctx)

	p, err := c.Payment()
	if err != nil {
		panic(err)
	}
	res, _ := p.CreatePayment(ctx, payment.Request{Amount: 2500, Currency: "usd"})
	fmt.Println("payment:", res.ID, string(res.Status))

	got, _ := p.GetPayment(ctx, res.ID)
	fmt.Println("fetched:", got.ID, string(got.Status))
	_ = p.Close()
}
```

Expected output:

```text
payment: stub_1 succeeded
fetched: stub_1 succeeded
```

`auto_approve: false` prints `pending` until a webhook flips it.

## Amount semantics

Every amount in `payment.Request`, `payment.Result`, `payment.Event` is `int64` minor units (cents), adapter-independent.

- `stripe` reports native minor-unit integers, passed through untouched.
- `paddle` reports major-unit decimal strings (e.g. `"10.00"`), normalized to minor units: `"10"` and `"10.00"` become `1000`, `"10.99"` becomes `1099`.
- Sub-cent precision rounds half away from zero: `"10.005"` becomes `1001`, `"-10.005"` becomes `-1001`.
- Scaled totals that overflow `int64` fail with `ErrAmountOverflow`, never wrap.
- Reverse direction agrees: partial-refund adjustments format back to major-unit decimals (`1000` sent as `"10.00"`).

## Verify webhooks

Decoding verifies the provider signature against `webhook_secret` under `max_webhook_bytes`, failures and oversized payloads never reach your handler as a trusted `Event`. Pass raw body plus signature header to `WebhookEvent(ctx, raw, signature)` unmodified. `stub` verifies nothing, holds no funds (test-only).

## Choose an adapter

| Adapter | Package | Notes |
|---|---|---|
| `stub` | `adapters/payment/stub` | Default. No network, no real money. |
| `stripe` | `adapters/payment/stripe` | Needs `secret_key`. |
| `paddle` | `adapters/payment/paddle` | Needs `api_key`. |

## Production checklist

- `payment` initiates and reacts, never stores card data, never a ledger (PCI scope stays with provider).
- Never log `SecretKey`, `APIKey`, `WebhookSecret`, hold them in [Secrets](../../security/secrets/).
- `Refund(ctx, id, amount, key)` takes an idempotency key, retries cannot double-refund.

## Troubleshooting

<details>
<summary>Stub payments stay `pending` in tests</summary>

`auto_approve` is false, set `auto_approve: true` (or `PAYMENT_AUTO_APPROVE`).
</details>

<details>
<summary>The webhook handler never fires</summary>

The signature check runs first, confirm `PAYMENT_WEBHOOK_SECRET` matches and the raw body reaches `WebhookEvent` unmodified.
</details>

<details>
<summary>`max_webhook_bytes` rejects large events</summary>

Payload over the bound, raise it deliberately after checking legitimacy.
</details>
