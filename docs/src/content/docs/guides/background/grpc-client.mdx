`shared/grpcclient` dials outbound gRPC between Zever services. `New(ctx, target, opts...)` returns a `*grpc.ClientConn` with round-robin balancing, optional per-method retry, W3C trace propagation, metadata, per-RPC timeout, and optional `resilience.Guard`. Natural backing for generated saga `SagaCaller` ([saga](../saga/)), `container.GRPCClient` caches one connection per target. No `config` entry: a helper, not a battery. Build in code or via the container.

## Quick start

```go title="main.go" check
package main

import (
	"context"
	"fmt"

	"github.com/zenta-dev/zever/shared/grpcclient"
)

func main() {
	conn, err := grpcclient.New(context.Background(), "static:///users",
		grpcclient.WithInsecure(),
		grpcclient.WithStaticResolver(map[string][]string{
			"users": {"127.0.0.1:50051", "127.0.0.2:50051"},
		}))
	if err != nil {
		panic(err)
	}
	defer conn.Close()

	fmt.Println("client created")
}
```

```text
client created
```

`New` performs no IO, connection establishes lazily on first RPC (`pb` = generated protobuf package):

```go
client := pb.NewUsersClient(conn)
resp, err := client.GetUser(ctx, &pb.GetUserRequest{Id: "u-1"})
```

## Choose credentials and a target

Credentials are explicit and fail closed: `New` returns `ErrNoCredentials` without `WithInsecure`/`WithTLS`, `ErrInsecureAndTLS` with both. `WithInsecure` is dev/loopback only.

| Target | Resolves through |
|---|---|
| `dns:///host:port` | gRPC's built-in DNS resolver. Multiple addresses spread load with `round_robin`, no sidecar. |
| `static:///name` | The `WithStaticResolver` address map. Unknown/empty names fail fast. Per connection, never global, for in-process and test setups. |

Production uses TLS: `WithTLS(TLSOptions{CertFile, KeyFile, CAFile, ServerName})` loads an optional client pair (both/neither, mTLS), CA bundle, server-name override. TLS 1.2 floor, read/parse failures error, never falls back to insecure.

```go title="dial.go"
import (
	"context"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/grpc/codes"

	"github.com/zenta-dev/zever/shared/grpcclient"
)

func dial(ctx context.Context) (*grpc.ClientConn, error) {
	return grpcclient.New(ctx, "dns:///users:443",
		grpcclient.WithTLS(grpcclient.TLSOptions{CAFile: "/etc/ssl/ca.pem"}),
		grpcclient.WithMetadata(map[string]string{"x-tenant": "acme"}),
		grpcclient.WithTimeout(2*time.Second),
		grpcclient.WithRetryPolicy(grpcclient.RetryPolicy{
			MaxAttempts:          5, // capped at DefaultMaxAttempts (5)
			InitialBackoff:       10 * time.Millisecond,
			MaxBackoff:           500 * time.Millisecond,
			BackoffMultiplier:    2,
			RetryableStatusCodes: []codes.Code{codes.Unavailable},
		}),
	)
}
```

## Retry failed calls

`WithRetryPolicy` merges a per-method policy into the gRPC service config for every method. Invalid policies error:

- `MaxAttempts` must be at least 2 and is capped at `DefaultMaxAttempts` (5, gRPC's own client limit).
- Backoffs and `BackoffMultiplier` must be positive.
- `RetryableStatusCodes` must not be empty. Keep it minimal (typically `UNAVAILABLE`): retrying every failure multiplies load on a struggling server. Code names are mapped to the canonical form for you.

`WithServiceConfigJSON` overlays raw keys (for example a custom `loadBalancingConfig`) on the `round_robin` default.

## Resolve the connection from the container

```go title="main.go"
conn, err := c.GRPCClient("static:///users", grpcclient.WithInsecure())
```

`GRPCClient(target, opts...)` caches one connection per target: repeat calls return the same connection, later calls with different options keep the first build. The container closes cached connections in `Close(ctx)`, otherwise the caller closes. See [the container](../../../concepts/container/).

## Know the interceptor order

Every connection chains unary and stream interceptors in this order, outermost first:

1. Observability span (when `WithObservability` is set), covering the whole call including guard execution.
2. W3C trace context injection from `shared/traceprop` into outgoing metadata.
3. `WithMetadata` keys, never overwriting keys already in the outgoing context.
4. `WithTimeout` deadline (must be positive, or `New` errors), governing the whole call including guard retries, without it only the caller's context applies.
5. `WithGuard`, wrapping the call in the `resilience.Guard` breaker, bulkhead, and retry composition.

For streams, the guard wraps establishment only, later messages are unguarded.

## Production checklist

- `WithTLS` + CA bundle, never `WithInsecure`.
- `round_robin` + `redis` resilience adapter when replicas share one circuit per downstream.
- Metadata can carry tenant/user context, never log raw metadata maps (`config.RedactedServices`).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `ErrNoCredentials` | Neither `WithInsecure` nor `WithTLS` passed, pick one |
| `ErrInsecureAndTLS` | Both passed, mutually exclusive, remove one |
| `static resolver: unknown name` | Target not in `WithStaticResolver` map, add name + addresses |
| Calls hang past dependency deadline | No `WithTimeout`, add it (bounds whole call incl. guard retries) |
| Retries never trigger | `RetryableStatusCodes` empty, list them (e.g. `codes.Unavailable`) |
