`job.Dispatcher` handles deferred/retryable work (confirmation mail, push, webhook delivery), wrapping the resolved `Queue`. The scheduler fires registered job names on cron specs through the dispatcher, with per-slot dedup across instances when a locker is set.

## Quick start

```sh
SCHEDULER_CLOSE_TIMEOUT=5s
```

Only `dsn`, `dedicated_pool`, `close_timeout` are env-settable, `Dispatcher`, `Locker`, `Logger` are code-wired (`json:"-"`), injected by the container. Dispatch rides the [queue](../queue/), so its options matter too. All keys: [scheduler config reference](../../../reference/config/#scheduler).

## Dispatch and schedule a job

Register typed jobs, dispatch one, schedule another on cron. Mirrors `go run ./cmd/worker` in `examples/bookings`.

```go title="main.go" check
package main

import (
	"context"
	"time"

	queuememory "github.com/zenta-dev/zever/adapters/queue/memory"
	schedulerembedded "github.com/zenta-dev/zever/adapters/scheduler/embedded"
	"github.com/zenta-dev/zever/core/job"
	"github.com/zenta-dev/zever/core/queue"
	"github.com/zenta-dev/zever/core/scheduler"
)

type ConfirmArgs struct {
	BookingID string `json:"booking_id"`
}

func main() {
	job.Reset()
	defer job.Reset()
	ctx := context.Background()

	_ = job.Register("SendConfirmation", func(_ context.Context, a ConfirmArgs) error { return nil })
	_ = job.Register("SendReminder", func(_ context.Context, _ map[string]string) error { return nil })

	q, _ := queuememory.New(queue.Options{})
	defer q.Close()
	d := &job.Dispatcher{Q: q}

	s, _ := schedulerembedded.New(scheduler.Options{Dispatcher: d})
	defer s.Stop()

	_ = d.Dispatch(ctx, "SendConfirmation", ConfirmArgs{BookingID: "b_123"})
	id, _ := s.Schedule(ctx, "0 9 * * *", "SendReminder", map[string]string{"space_id": "s_42"})
	_ = s.Start()
	time.Sleep(50 * time.Millisecond)
	_ = s.Remove(id)
}
```

`Dispatch` pushes onto the topic for the job priority (`low` default, then `medium`/`high`), the schedule registers `0 9 * * *`, `Start` begins ticks. The bookings worker runs `job.Worker{Queues: []string{"default", "low"}, Concurrency: 4}`, polling in that order.

Set retry/priority at `Register` with `WithRetryPolicy`/`WithPriority`: default 25 attempts, 5s base doubling per attempt (bookings schema overrides to `max_attempts(3)`, 30s exponential base). `job.NewBatch` covers batch enqueue. Singleton jobs use `job.UniqueBy(key)`, needing a `job.UniqueLocker` (`job.NewUniqueLocker(cache)`) the container doesn't wire.

## Resolve the scheduler from the container

`c.Job()` builds a `*job.Dispatcher` over the resolved `Queue` (`d.Q` is the shared instance), `c.Scheduler()` injects it, so resolving the scheduler resolves `Job()` and `Queue` too. Never open a second queue for scheduled work. The scheduler has `Stop() error` (not `Close`), the container stops it and job first, then snapshots, then `cache`/`queue`. See [the container](../../../concepts/container/).

## Choose a scheduler adapter

| Adapter | Package | Use when |
|---|---|---|
| `embedded` | `adapters/scheduler/embedded` | In-process cron ticks. `Stop()` ends ticks. |
| `postgres` | `adapters/scheduler/postgres` | Durable leased slots, safe for multi-instance deploys. Set `dsn` to a postgres URL (empty is a private in-memory sqlite). |

`job` has no adapter registry: topics are priority names, the real choice is the backing queue. `memory` keeps web/worker/ticks in one process, `redis` lets ticks fire in one process while any worker pops. `postgres` borrows the shared pool for its DSN unless `dedicated_pool: true`, prefer a separate database under load.

## Production checklist

- Not a durable timeline: slots firing while down are skipped. Idempotent handlers, `lock`/`idempotency` triggers, consider a catch-up query on boot.
- Guard overlapping ticks with the unique locker, slow run + fast cadence double-fires a slot.
- Small JSON payloads: large blobs inflate every retry and queue read.
- Set `close_timeout` explicitly, not the 5s default. Never log raw option maps (`config.RedactedServices`).

## Troubleshooting

| Symptom | Fix |
|---|---|
| Reminders fire twice from two hosts | No shared locker, wire one cache-backed `job.UniqueLocker` (`Options.Locker`, code only) into both, or run one scheduler replica |
| `scheduler.Open` fails `dispatcher_is_required` | `Dispatcher` is code-only and nil, resolve via `c.Scheduler()` or pass `Options{Dispatcher: d}` |
| Dispatched job never runs, worker idle | Topic mismatch (`PriorityLow` -> `low` vs worker polling `default`), align `WithPriority` with worker `Queues` |
| Shutdown drops a started tick | `close_timeout` too short or queue closed first, raise it (ns in file, `"5s"` env), keep container close order |
