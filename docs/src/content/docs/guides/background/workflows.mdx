Use `workflow` for multi-step runs (onboarding, payouts, provisioning) that survive a mid-run restart: a crash after step 3 resumes at step 3. Lifecycle: `Start` a named workflow with JSON-marshalable input, `Signal` a running channel, `Query` state, `Cancel` a run. Not a cron scheduler: [scheduler](../scheduler-jobs/) for cron firing, `queue`+`job` for plain background tasks, [saga](../saga/) for rollback.

## Quick start

```sh
WORKFLOW_NAMESPACE=bookings
```

```go title="main.go" check
package main

import (
	"context"
	"fmt"

	workflowmemory "github.com/zenta-dev/zever/adapters/workflow/memory"
	"github.com/zenta-dev/zever/core/workflow"
)

func main() {
	wf, _ := workflowmemory.New(workflow.Options{})
	defer wf.Close()

	// A workflow name must have a registered step, or Start fails with an unknown-step error.
	wf.(workflow.StepRegistrar).RegisterStep("booking-confirm", func(_ context.Context, in any) (any, error) {
		return in, nil
	})

	ctx := context.Background()
	id, err := wf.Start(ctx, "booking-confirm", map[string]string{"booking_id": "b-1"}, "wf-b-1")
	fmt.Println(id, err)
	var state map[string]string
	fmt.Println(wf.Query(ctx, id, "state", &state), state)
}
```

```text
wf-b-1 <nil>
<nil> map[booking_id:b-1]
```

Wire the adapter via `container.Provide` before `c.Workflow()`. The only query name is `state`, anything else errors. On `memory`, `Start` runs the step inline and finishes the run, so later `Signal`/`Cancel` returns run-completed (those act on in-flight `db` runs). Empty `workflowID` generates one (`run-N` on memory), a duplicate ID fails with a duplicate-run error. `Workflow()` resolves lazily, caches, retries after errors, `Close() error` takes no context. See [the container](../../../concepts/container/).

## Choose a backend

| Adapter | Package | Use when |
|---|---|---|
| `memory` | `adapters/workflow/memory` | Default. Local dev and tests. In-process, a run holds at most 100 pending signals, then `Signal` returns `ErrPendingFull` instead of blocking. |
| `db` | `adapters/workflow/db` | Durable DB-backed runs, lease-reclaimed steps. Set `dsn` to a postgres URL (empty is sqlite). |

`memory` state dies with the process: replicas see only their own runs, restarts lose all, crash-survival needs `db`. Host-registered steps go through the separate `StepRegistrar` interface, so engines without the concept are unaffected. Input/output must be JSON-marshalable, output becomes queryable state, so keep payloads small and reference-backed.

## Configure the workflow

```sh
WORKFLOW_NAMESPACE=bookings
WORKFLOW_HOST_PORT=127.0.0.1:7233
WORKFLOW_DSN=postgres://app:secret@db:5432/app
```

`namespace` scopes runs, `host_port` names a workflow server address when the backend needs one. Durable keys: `dsn`, `table` (default `workflow_runs`), `dedicated_pool`, all optional for `memory`. `Validate` only rejects a malformed `host_port` when set (must split as host:port). Share one pool per DSN via `NewFromDB` (first opener's `max_conns` wins), `WORKFLOW_DEDICATED_POOL=true` with a separate database under load. All keys: [workflow config reference](../../../reference/config/#workflow).

## Production checklist

- Every step idempotent now (locks + idempotency keys for money-moving steps) so durable backends replay safely. Cap retries, route poison inputs to a dead-letter path.
- Inputs, signals, results become queryable state and may cross processes: no secrets/PII, pass references, never log raw option maps (`config.RedactedServices`).
- Container closes only resolved services, joining errors via `errors.Join`, panics become `*ClosePanicError`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `ErrPendingFull` on signal | Pending-signal buffer (100) full, drain/cancel stuck runs, cap retries, dead-letter poison inputs |
| Query marshal error | On `memory`, values marshal lazily at `Query` (`db` marshals at `Start`), pass only JSON-marshalable values (maps, slices, structs without channels or funcs) |
| Steps re-run side effects after crash | Step not idempotent, gate behind `lock` + idempotency keys, span each step |
