`notification.Notifier` sends non-mail pings: reminders, check-in prompts, fraud alerts. Callers use `Notify` against the interface, so FCM/Twilio is a config change, not a sender rewrite. Stay on `log` until a real channel is wired (writes instead of sending). `twilio` for SMS, `fcm` for push, credentials from file/env, never committed YAML. No queueing/scheduling here: enqueue as jobs for retry/backpressure, never fail the triggering request on channel failure.

## Quick start

```sh
NOTIFICATION_TIMEOUT=30s
```

```go title="main.go" check
package main

import (
	"context"
	"fmt"

	notificationlog "github.com/zenta-dev/zever/adapters/notification/log"
	"github.com/zenta-dev/zever/core/notification"
)

func main() {
	n, _ := notificationlog.New(notification.Options{})
	defer n.Close()

	push := notification.NewNotification("device-token-abc", notification.ChannelPush, "Reminder: check-in at 3pm")
	push.Title = "Booking reminder"
	push.Data = map[string]string{"booking_id": "b_123"}
	_ = push.Validate()
	_ = n.Notify(context.Background(), &push)

	sms := notification.NewNotification("+15551234567", notification.ChannelSMS, "Code 4821")
	_ = sms.Validate()
	_ = n.Notify(context.Background(), &sms)
	fmt.Println("notified push and sms via log adapter")
}
```

Output: two JSON log lines, then `notified push and sms via log adapter`, no network. `notificationlog.New` writes single JSON lines to `os.Stdout`, tests use `NewWithWriter(opts, w)` (e.g. `io.Discard`).

## Choose a channel and validate the target

SMS targets must be E.164 (`+` + 7-15 digits, leading non-zero) or `Validate` returns `InvalidTargetError` without echoing the number. SMS is body-only: `Title`/`Data` on `ChannelSMS` fail as push-only. Wrong-channel calls fail closed with `InvalidNotificationError`, an adapter lacking a channel returns `ChannelNotSupportedError`, never silent drop. All errors `errors.Is`-compatible. `TTL` zero = none (negative fails), priority zero = normal. Types: `ChannelPush`/`ChannelSMS`, `PriorityLow`/`Normal`/`High`.

| Adapter | Package | Notes |
|---|---|---|
| `log` | `adapters/notification/log` | Default, safe sink, writes instead of sending |
| `twilio` | `adapters/notification/twilio` | SMS, E.164 targets, basic-auth by sid and token |
| `fcm` | `adapters/notification/fcm` | Push, project plus service-account key file |

## Configure Twilio or FCM

The `twilio` and `fcm` blocks are nested maps under `options`, beside the top-level `timeout`.

## Resolve the notifier from the container

```go title="main.go"
n, err := c.Notification()
```

`Notification()` resolves lazily and caches, on error the cache clears. `Close() error` is instant, container probes it as a snapshot service. See [the container](../../../concepts/container/).

## Production checklist

- `log` echoes targets (numbers/tokens land in logs): switch to `twilio`/`fcm` before deploy or gate log output.
- `InvalidTargetError` carries reason only, log channel + reason, never number/token.
- Never `Notify` inline for slow channels, dispatch a job (bookings `SendReminder` on `low`) so provider latency/retries never gate the write.
- Missing push token/phone: skip quietly at the job layer, don't fail the batch. Never log raw option maps (`config.RedactedServices`).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `sms target must be E.164` on valid-looking numbers | Missing `+`, spaces, or dashes, normalize with an E.164 formatter before `Validate`, reject the rest at the API boundary |
| `title/data is push-only` | SMS built with push fields, `Title`/`Data` only for `ChannelPush`, body only for `ChannelSMS` |
| Dev pushes work, production silent | Still on `log`, or FCM points at dev project, set `notification.adapter=fcm` with prod project/key path, confirm mount |
| `ChannelNotSupportedError` after switch | Adapter serves one channel but code sends both, one notifier per channel or route by channel at the job layer |
