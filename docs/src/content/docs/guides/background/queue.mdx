`queue.Queue` is the durable transport behind `job.Dispatcher` and the scheduler: work that must outlive the request, survive restart, retry, or fan out. Messages carry UUIDv7 ids.

## Quick start

```sh
QUEUE_VISIBILITY_TIMEOUT=30s
QUEUE_POLL_TIMEOUT=1s
QUEUE_BUFFER=100
```

```go title="main.go" check
package main

import (
	"context"
	"fmt"

	queuememory "github.com/zenta-dev/zever/adapters/queue/memory"
	"github.com/zenta-dev/zever/core/queue"
)

func main() {
	q, _ := queuememory.New(queue.Options{})
	defer q.Close()
	ctx := context.Background()

	headers := queue.NewHeaders(map[string]string{"job_name": "SendConfirmation"})
	_ = q.Push(ctx, "default", queue.NewPayload([]byte(`{"booking_id":"b_123"}`)), headers)

	msg, err := q.Pop(ctx, "default")
	if err != nil { // queue.ErrEmpty when the topic is empty
		panic(err)
	}
	_ = q.Ack(ctx, msg)
	fmt.Println("popped and acked", msg.ID)
}
```

Output: `popped and acked <id>`. `Ack` on success, `Nack(ctx, msg, true)` requeues at once (attempts +1), `Nack(ctx, msg, false)` drops. Unacked messages reappear after `visibility_timeout`. `Pop` returns `ErrEmpty` on empty. `Length`/`IsEmpty` are autoscaling signals, `Name()` reports the adapter.

## Choose an adapter

| Adapter | Package | Use when |
|---|---|---|
| `memory` | `adapters/queue/memory` | Default, one process, no infra. |
| `redis` | `adapters/queue/redis` | Multiple workers or split web/worker tiers, keyed by `prefix`. |
| `db` | `adapters/queue/db` | Shared queue on postgres/sqlite you already run. |

Only `redis` and `db` share across hosts. `db` is polling, not Kafka/SQS: `Pop` polls every `poll_interval` (10ms default, adapter code only, not an env key), claims serialize on the topic head, stale claims recover on sweep. Do not copy `OUTBOX_POLL_INTERVAL` (1s) here, that key belongs to the outbox relay only. Expect low thousands of jobs/s/topic, use a separate queue DB, 3-5 connections per worker, and `dedicated_pool: true` under load. Not an event log or pub/sub bus, for live fan-out use the [event bus](../events/).

Wire via `container.Provide(Queue, queueredis.New)`:

```sh
QUEUE_ADDR=localhost:6379 QUEUE_VISIBILITY_TIMEOUT=30s
```

Env keys are strict snake_case, durations take Go strings (`"30s"`). Empty `dsn` selects a private in-memory-style database, the backend is compiled in. `visibility_timeout`: how long a popped message stays invisible, `poll_timeout`: how long `Pop` waits before empty, `buffer`: caps buffered ready messages per topic. db-backed batteries share one pool per exact DSN via `NewFromDB` (first opener's `max_conns` wins, differing nonzero cap warns). All keys: [queue config reference](../../../reference/config/#queue).

## Resolve the queue from the container

`c.Queue()` resolves lazily, caches, and retries on error, `c.Job()` builds a `*job.Dispatcher` over it. `Close() error` takes no context, the queue closes last, after scheduler and job, and container `Close(ctx)` never opens an untouched queue. See [the container](../../../concepts/container/).

## Production checklist

- At-least-once redelivery: idempotent handlers or `lock`/`idempotency` guards.
- `visibility_timeout` above slowest handler, low `poll_timeout` for request pops, higher for workers.
- No cross-topic ordering, priority is poll order. Small versioned JSON payloads, no PII, `config.RedactedServices` for config.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Same job runs twice in seconds | `visibility_timeout` < runtime, raise above p99 + backoff or defer slow I/O |
| Hot poll, `ErrEmpty` floods logs | Raise `poll_timeout` (workers 1s), back off after consecutive empties |
| Host B never sees host A pushes | `memory` is per-process, use `redis` (shared `addr`/`db`/`prefix`) or `db` |
| Strict load rejects `visibilitytimeout` | Pre-rename spelling, use `visibility_timeout`/`poll_timeout` (integer ns). Env ignores `_` |
