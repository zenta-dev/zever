A saga fits multi-resource operations that don't fit one transaction (reserve a seat, charge a card, issue a ticket). Each `SagaStep` has forward `Execute` plus optional reverse `Compensate`, on failure the runner compensates executed steps in reverse, or rolls forward with retries after a pivot. Crashes resume from persisted position, a persisted step never re-executes. Sagas ride the `workflow` battery, no separate saga config.

## Quick start

```sh
WORKFLOW_NAMESPACE=bookings
```

```go title="main.go" check
package main

import (
	"context"
	"fmt"

	workflowmemory "github.com/zenta-dev/zever/adapters/workflow/memory"
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
	"github.com/zenta-dev/zever/core/workflow"
)

func main() {
	c := container.New(config.Default(), container.Provide(workflow.DefaultRef(), workflowmemory.New))
	wf, _ := c.Workflow()

	wf.(workflow.SagaRegistrar).RegisterSaga("booking", []workflow.SagaStep{
		{Name: "reserve-seat", Execute: func(context.Context, any) (any, error) { return "seat-7", nil },
			Compensate: func(_ context.Context, result any) (any, error) { fmt.Println("released", result); return nil, nil }},
		{Name: "charge-card", Execute: func(context.Context, any) (any, error) { return "ch-1", nil },
			Compensate: func(_ context.Context, result any) (any, error) { fmt.Println("refunded", result); return nil, nil }},
	})

	ctx := context.Background()
	id, _ := wf.(workflow.SagaRunner).RunSaga(ctx, "booking", map[string]string{"booking": "b-1"}, "b-1")
	st, _ := wf.(workflow.SagaInspector).SagaStatus(ctx, id)
	fmt.Println(id, st.Status)
}
```

```text
b-1 completed
```

If `charge-card` fails, the run prints only `released seat-7` (the failed step itself is never compensated) with status `failed`. `Pivot: true` on `reserve-seat` rolls forward with retries instead. Type-assert the resolved workflow to `workflow.SagaRegistrar`/`SagaRunner`/`SagaInspector`, both `memory` and `db` implement all three.

## Understand steps, pivots, and replay

- `SagaStep{Name, Execute, Compensate, Pivot}`: forward action + optional rollback (nil = none). Input/output must be JSON-marshalable.
- `RegisterSaga(name, steps)`: registers/replaces the definition. Definitions are in-memory (steps are funcs), only run progress is durable.
- `RunSaga(ctx, name, input, workflowID)`: starts or resumes. Empty `workflowID` generates one, a matching ID resumes (terminal runs return unchanged, others continue from persisted `current_step`).
- `SagaStatus(ctx, runID)`: returns `Status`, `CurrentStep`, `FailedStep`, `Err`.

Statuses: `pending`, `running`, `completed`, `compensating`, `failed`, `compensation_failed`.

**Pivot.** A failed step with an earlier executed `Pivot=true` step commits to completing: retries remaining steps forward, never compensates. Otherwise compensates executed steps in reverse, skipping nil `Compensate` and (on db) already-compensated steps. Failed compensation marks the run `compensation_failed`, may need manual fix.

**Replay.** Same `workflowID` never re-executes a completed step: on db via persisted `current_step` + `run_id:step_index` guard, on memory via the `executed` index.

## Declare a saga in .zen

A saga over existing `service` RPCs is schema, not wiring:

```text title="schema/app.zen"
saga CheckoutSaga {
  step reserve {
    execute: InventoryService.Reserve
    compensate: InventoryService.Release
  }
  step charge {
    execute: PaymentService.Charge
    compensate: PaymentService.Refund
    pivot: true
  }
}
```

`execute` is required per `step`, `compensate`/`pivot` optional (`pivot` defaults `false`). Step names are unique per saga, at most one step sets `pivot: true`. `execute`/`compensate` reference `<Service>.<RPC>` across every schema service, so sagas compose RPCs across modules.

For each module with a saga, the `gogen` backend emits `<module>/saga.go` with per-step typed input/output structs, a `SagaCaller` interface, and `RegisterSagas`:

```go title="app/saga.go"
package app

import (
	"context"

	"github.com/zenta-dev/zever/core/workflow"
)

// CheckoutSagaReserveInput is the typed input for saga "CheckoutSaga" step "reserve".
type CheckoutSagaReserveInput struct {
	ItemId string `json:"item_id"`
}

// CheckoutSagaReserveOutput is the typed output for saga "CheckoutSaga" step "reserve".
type CheckoutSagaReserveOutput struct {
	Id string `json:"id"`
}

// SagaCaller invokes the saga steps declared in this module; wire it to
// shared/grpcclient or an in-process dispatcher. One method per step keeps
// every call typed: no untyped payloads cross this seam.
type SagaCaller interface {
	CheckoutSagaReserve(ctx context.Context, in CheckoutSagaReserveInput, out *CheckoutSagaReserveOutput) error
	CheckoutSagaReserveCompensate(ctx context.Context, in CheckoutSagaReserveCompensateInput, out *CheckoutSagaReserveCompensateOutput) error
	CheckoutSagaCharge(ctx context.Context, in CheckoutSagaChargeInput, out *CheckoutSagaChargeOutput) error
	CheckoutSagaChargeCompensate(ctx context.Context, in CheckoutSagaChargeCompensateInput, out *CheckoutSagaChargeCompensateOutput) error
}

// RegisterSagas registers every saga declared in this module.
func RegisterSagas(reg workflow.TypedSagaRegistrar, caller SagaCaller) {
	reg.RegisterTypedSaga("CheckoutSaga", []workflow.TypedStep{
		workflow.NewTypedStep("reserve", checkoutSagaReserveExecute(caller), checkoutSagaReserveCompensate(caller), false),
		workflow.NewTypedStep("charge", checkoutSagaChargeExecute(caller), checkoutSagaChargeCompensate(caller), true),
	})
}

// checkoutSagaReserveExecute adapts SagaCaller.CheckoutSagaReserve to a typed workflow step function.
```

## Wire generated sagas at boot

`SagaCaller` is the one seam the host supplies, `RegisterSagas` is deliberately not called from `RegisterModule`. Implement one method per step with [`shared/grpcclient`](../grpc-client/) (dial, marshal `in`, invoke `<Service>/<Method>`, unmarshal `out`) or an in-process dispatcher (no gRPC, generated file depends only on `core/workflow`). Resolve `c.Workflow()`, assert to `workflow.TypedSagaRegistrar` (both `memory`/`db` implement it), call `app.RegisterSagas(reg, caller)` once at boot. `workflow.NewTypedStep` converts inputs/outputs via encoding/json, keep structs JSON-marshalable.

## Recover crashed runs

Use `db` for durability: persists `current_step` after each successful step in `workflow_saga_runs`, extends a lease while running, creates `workflow_saga_runs`/`workflow_saga_compensations` when missing. Recovery is explicit and caller-driven (no background goroutine), call `RecoverStuckSagas` to resume `running`/`compensating` runs with expired leases:

```go title="recover.go"
type sagaRecoverer interface {
	RecoverStuckSagas(ctx context.Context, olderThan time.Duration) (int, error)
}

rec, ok := wf.(sagaRecoverer)
if ok {
	n, err := rec.RecoverStuckSagas(ctx, time.Minute)
	// n runs resumed; runs whose definition is no longer registered are skipped
}
```

| Adapter | Package | Notes |
|---|---|---|
| `memory` | `adapters/workflow/memory` | Default. In-process saga state, non-durable. A restart loses all runs. |
| `db` | `adapters/workflow/db` | Durable runs, lease-based crash recovery, `RecoverStuckSagas`. |

Switching `memory` to `db` needs no call-site change, only a different `container.Provide`. The db adapter shares one pool per DSN via `NewFromDB` (first opener's `max_conns` wins), use `dedicated_pool: true` with a separate database under load. Keys: [workflow config reference](../../../reference/config/#workflow).

## Production checklist

- Every step idempotent (locks + idempotency keys for money-moving steps). `memory` replicas each see only their own runs.
- Compensation is best-effort: idempotent and retryable. db retries with bounded backoff, recording attempts in `workflow_saga_compensations`.
- Inputs/results become persisted state: no secrets/PII, pass references, never log raw option maps (`config.RedactedServices`).
- `Workflow.Close() error` takes no context, container joins errors via `errors.Join`, panics become `*ClosePanicError`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `ErrUnknownSaga` | Definitions are in-memory, register the same ones on every replica at boot or `RecoverStuckSagas` skips those runs |
| Step re-runs after crash | Step not idempotent, gate side effects behind `lock` + idempotency keys |
| Runs stay `running` after crash | Nobody called `RecoverStuckSagas`, call at worker boot with a lease window above worst-case step latency |
| `compensation_failed` | A compensation failed, inspect `workflow_saga_compensations`, fix cause, re-drive manually |
| `ErrSagaNotFound` | Unknown run ID, or `memory` restarted, use `db` for durability |
