Use `outbox` to fix dual-write: booking row + `booking.created` event are two writes, and the row can commit while the event is lost. `Store.Record(ctx, tx, msg)` persists inside the caller's `db.Tx`, so both commit or neither does. A relay publishes at-least-once, `Inbox` makes consumers idempotent. For domain events, webhook fan-out, cache invalidation, audit trails.

## Record an event and consume it once

One transaction, one event, one idempotent consumer side effect:

```go title="main.go" check
package main

import (
	"context"
	"fmt"

	outboxdb "github.com/zenta-dev/zever/adapters/outbox/db"
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
	coredb "github.com/zenta-dev/zever/core/db"
	"github.com/zenta-dev/zever/core/outbox"
)

func main() {
	cfg := config.Default()
	cfg.DB.Options.Path = ":memory:"
	c := container.New(cfg)

	conn, err := c.DB()
	if err != nil {
		panic(err)
	}

	ob, err := outboxdb.OpenFromDB(conn, outboxdb.Options{
		Publisher: outbox.PublisherFunc(func(_ context.Context, msg outbox.Message) error {
			fmt.Println("published", msg.Topic, string(msg.Payload))
			return nil
		}),
	})
	if err != nil {
		panic(err)
	}
	defer ob.Close()

	ctx := context.Background()
	err = coredb.WithTx(ctx, conn, nil, func(ctx context.Context, tx coredb.Tx) error {
		if _, err := tx.Exec(ctx, `CREATE TABLE bookings (id TEXT PRIMARY KEY)`); err != nil {
			return err
		}
		if _, err := tx.Exec(ctx, `INSERT INTO bookings (id) VALUES (?)`, "b-1"); err != nil {
			return err
		}
		return ob.Record(ctx, tx, outbox.Message{
			ID:      "b-1",
			Topic:   "booking.created",
			Payload: []byte(`{"id":"b-1"}`),
		})
	})
	fmt.Println("recorded:", err)

	inbox, ok := ob.(outbox.Inbox)
	if !ok {
		panic("outbox store does not implement outbox.Inbox")
	}
	err = coredb.WithTx(ctx, conn, nil, func(ctx context.Context, tx coredb.Tx) error {
		return inbox.Process(ctx, tx, "b-1", func(ctx context.Context, tx coredb.Tx) error {
			fmt.Println("side effect ran")
			return nil
		})
	})
	fmt.Println("inbox:", err)
}
```

```text
recorded: <nil>
side effect ran
inbox: <nil>
```

The relay is not started here. `Start` publishes stored messages through the same `Publisher`.

`Record` inserts in the caller's transaction (nil `tx` fails with `ErrTxRequired`) and injects trace context from `ctx` into stored headers.

`Inbox.Process` records `eventID` in the caller's transaction and runs the side effect only when the ID is new (`INSERT ... ON CONFLICT DO NOTHING`).

## Understand relay delivery and failure

- Relay claims a batch atomically (`UPDATE ... RETURNING`, postgres adds `FOR UPDATE SKIP LOCKED`, sqlite serializes on a process-local mutex), publishes via `Publisher`, marks successes `processed`, retries failures with `shared/retry` backoff.
- Rows exhausting `max_attempts` are marked `failed`: the dead-letter queue, repaired via `outbox.Admin` (`List`/`Requeue`/`Purge`, plus `Deleter` on `db`), driven by `zever outbox` CLI.
- Processed rows older than `retention` are deleted.
- `Status()` reports `Pending`, `Processed`, `Failed`, `LastError`, `Stalled` (oldest pending waits too long).
- Any replica count relays one table without double-publish. A crash mid-publish returns the row to pending when its `lock_seconds` lease expires.
- With observability wired (`Options.Provider`, injected by `container.Outbox()`), the relay emits `outbox.*` metrics and `outbox.publish`/`outbox.consume` spans (see [Outbox Ops](../outbox-ops/)).

## Configure the outbox

```sh
OUTBOX_DSN=postgres://app:secret@db:5432/app
OUTBOX_TABLE=outbox
OUTBOX_INBOX_TABLE=inbox
OUTBOX_PUBLISHER=eventbus
OUTBOX_POLL_INTERVAL=1s
OUTBOX_BATCH_SIZE=100
OUTBOX_MAX_ATTEMPTS=5
OUTBOX_RETENTION=168h
OUTBOX_LOCK_SECONDS=30
OUTBOX_DEDICATED_POOL=false
```

```sh
OUTBOX_DSN=postgres://app:secret@db:5432/app
OUTBOX_POLL_INTERVAL=1s
```

Keys are strict snake_case, durations take Go strings (`"30s"`, `"168h"`). Zero means adapter default. `Validate` rejects negative intervals/budgets, unsafe table names, and `publisher` outside `{eventbus, queue, ""}`. All keys: [outbox config reference](../../../reference/config/#outbox).

Core never imports `eventbus` or `queue`. Your wiring bridges a transport to `Publisher`, `Options.Publisher` only records which.

## Choose an adapter

| Adapter | Package | Notes |
|---|---|---|
| `db` | `adapters/outbox/db` | Default. Durable sqlite or postgres polling relay, DLQ, retention. Also implements `Inbox`. |
| `memory` | `adapters/outbox/memory` | Dev and tests. Publishes synchronously and keeps nothing, so a crash between `Record` and the publisher's ack loses the event. |
| `cdc` | `adapters/outbox/cdc` | Postgres logical replication via `pg_logical_emit_message`. No polling. Needs `wal_level=logical`. |

The cdc adapter emits inside the caller's transaction, so rollback drops the event. Its consumer tails the WAL via a replication slot and acks the LSN after successful publish.

```sh
OUTBOX_DSN=postgres://app:secret@db:5432/app
OUTBOX_PREFIX=zever_outbox
OUTBOX_SLOT=zever_outbox_slot
OUTBOX_PUBLICATION=zever_outbox_pub
```

The cdc adapter requires non-empty `dsn`, `slot`, `publication`, and `prefix`. Live cdc tests are gated behind `POSTGRES_DSN`.

## Resolve the store from the container

```go title="main.go"
import (
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
)

func openStore() error {
	c := container.New(config.Default())
	ob, err := c.Outbox()
	if err != nil {
		return err
	}
	defer ob.Close()
	return nil
}
```

`Outbox()` resolves lazily and caches, on error the cache clears. It injects the resolved `observability.Provider` into `Options.Provider`, so a container-opened store emits relay metrics/spans from [Outbox Ops](../outbox-ops/) with no extra wiring. A container-opened store records but cannot `Start` its relay (core `Options` carry no `Publisher`), wire one via the adapter constructor (`OpenFromDB` in `adapters/outbox/db`, `New` in `cdc`/`memory`), as above.

## Production checklist

- `Store.Close() error` takes no context. Container joins close errors via `errors.Join`, panics become `*ClosePanicError`.
- The `db` adapter shares one pool per exact DSN (first opener's `max_conns` wins). `dedicated_pool: true` under sustained load.
- Payloads can carry PII: keep them small and reference-backed, never log raw option maps (`config.RedactedServices`).

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `Start` fails: "publisher is nil" | Opened via container/registry, which carries no `Publisher` | Wire one via adapter constructor (`OpenFromDB`/`New`) |
| Messages sit pending | Relay not running, or `Status().Stalled` | Call `Start`, check `LastError` |
| Failed rows accumulate | Destination rejects payload or `Publisher` errors (`max_attempts` default 5) | Inspect row `last_error`, fix cause, re-drive |
| Duplicate side effects | Consumer not idempotent | Stable `ID` + `Inbox.Process` (or own key) in same txn as side effect |
| cdc fails to start | No `wal_level=logical`, or publication/slot name mismatch | Set `wal_level=logical`, align names (`POSTGRES_DSN` for live tests) |
