`eventbus.EventBus` lets producers publish and walk away while zero or more live listeners react. Use it for notify-style fan-out where no reaction is load-bearing, like the bookings worker's `booking.created` signal. It has no durability and no redelivery for offline handlers, so put must-run work on the [queue](../queue/) via `job.Dispatcher`.

## Quick start

```yaml title="zever.yaml"
eventbus:
  adapter: memory
  options:
    buffer_size: 1024
    max_handlers: 128
    handler_timeout: 30000000000 # 30s, integer nanoseconds in files
    close_timeout: 5000000000
```

```go title="main.go"
package main

import (
	"context"
	"fmt"

	eventbusmemory "github.com/zenta-dev/zever/adapters/eventbus/memory"
	"github.com/zenta-dev/zever/core/eventbus"
)

func main() {
	if err := run(); err != nil {
		panic(err)
	}
}

func run() error {
	eventbusmemory.Register()
	bus, err := eventbus.Open(eventbus.Memory, eventbus.Options{})
	if err != nil {
		return err
	}
	defer func() { _ = bus.Close() }()
	ctx := context.Background()

	ch, err := bus.SubscribeChan(ctx, "orders", 16)
	if err != nil {
		return err
	}
	defer func() { _ = bus.Unsubscribe("orders", ch) }()

	unsub, err := bus.Subscribe(ctx, "orders", func(_ context.Context, msg eventbus.Message) {
		fmt.Println("push saw", string(msg.Payload))
	})
	if err != nil {
		return err
	}
	defer unsub()

	if err := bus.Publish(ctx, "orders", eventbus.NewPayload([]byte("hello")), nil); err != nil {
		return err
	}
	msg := <-ch
	fmt.Println("pull saw", string(msg.Payload))
	return nil
}
```

Output: `push saw hello` and `pull saw hello`. Push (`Subscribe`) takes a handler and returns an unsubscribe closure. Pull (`SubscribeChan`) returns a channel. Keep payloads small, versioned JSON.

## Subscribe without leaking goroutines

Every subscription needs an explicit exit path, or leak tests flag the stray goroutine. Defer the unsubscribe closure after `Subscribe`, and `Unsubscribe` after `SubscribeChan`. Closing the bus also ends subscriptions.

Topics must be non-empty and at most 256 bytes (`MaxTopicLen`). Payloads are at most 4 MiB (`MaxMessageSize`). Oversize publishes fail closed. Set `OnPanic` (never validated) where a bad subscriber must not take down the publisher. Cap fan-out with `max_handlers`: unbounded subscribes from request paths leak handlers.

## Fan out across instances with Redis

Use `redis` when a publish on one process must reach a subscriber on another. Call sites do not change when you switch from `memory`.

<Tabs>
  <TabItem label="YAML">
```yaml title="zever.yaml"
eventbus:
  adapter: redis
  options:
    buffer_size: 1024
    redis:
      addr: localhost:6379
      db: 0
      prefix: bookings
      pool_size: 20
      min_idle_conns: 2
      pool_timeout: 5000000000
```
  </TabItem>
  <TabItem label="Env">
```sh
EVENTBUS_ADAPTER=redis
EVENTBUS_BUFFER_SIZE=1024
EVENTBUS_MAX_HANDLERS=128
EVENTBUS_HANDLER_TIMEOUT=30s
EVENTBUS_CLOSE_TIMEOUT=5s
```
  </TabItem>
</Tabs>

Keys are strict snake_case, with Redis pooling under a nested `redis` block. Zero means adapter default (`buffer_size` 1024, `max_handlers` 128, `handler_timeout` 30s, `close_timeout` 5s), and only negative values fail validation. Env is best-effort: unknown variables are ignored, unparsable resolved values error. All keys: [eventbus config reference](../../../reference/config/#eventbus).

| Adapter | Package | Notes |
|---|---|---|
| `memory` | `adapters/eventbus/memory` | Default, process-local, push plus pull, zero infra |
| `redis` | `adapters/eventbus/redis` | Shared fan-out, prefix-keyed, pool-backed |

## Resolve the bus from the container

```go title="main.go"
import (
	eventbusmemory "github.com/zenta-dev/zever/adapters/eventbus/memory"
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
)

func openBus() error {
	eventbusmemory.Register()

	c := container.New(config.Default())
	bus, err := c.EventBus()
	if err != nil {
		return err
	}
	defer func() { _ = bus.Close() }()
	return nil
}
```

`EventBus()` (alias `Eventbus()`) resolves lazily and caches; on error the cache clears so the next call retries. `Open` always returns a bus with pull support: adapters expose the `Pusher` push core and the package wraps it. `Close() error` takes no context. See [the container](../../../concepts/container/).

The bookings worker publishes `booking.created` after persisting. With no subscriber, delivery is skipped quietly. Empty webhook targets skip without error, and private targets stay rejected unless `allow_private_targets` is set for `httptest` flows.

## Production checklist

- The bus is not durable: a handler offline at publish time misses the message, with no replay.
- Backpressure drops newest: a full per-topic buffer (default 1024) drops the newest message for that subscriber only. Size `buffer_size` for burst plus handler latency.
- Bound handler time with `handler_timeout` (default 30s). A stuck handler holds its slot and its buffer fills, causing drops.
- Never put secrets in payloads. Redaction covers logged config, not message bodies.

## Troubleshooting

<details>
<summary>A subscriber on host B never fires for publishes on host A</summary>

Cause: the `memory` adapter in a multi-instance deploy. Delivery is in-process.

Fix: set `eventbus.adapter` to `redis` with a shared `addr` and `prefix`, then confirm every instance resolves the same endpoint through redacted output.
</details>

<details>
<summary>Messages vanish under load with no error</summary>

Cause: the per-topic buffer is full and drop-newest backpressure engaged.

Fix: raise `buffer_size`, shorten handler work (enqueue a job for slow I/O), and look for a slow subscriber starving its channel.
</details>

<details>
<summary>Strict load rejects buffersize or maxhandlers</summary>

Cause: flat pre-rename spellings. Keys are `buffer_size`, `max_handlers`, `handler_timeout`, `close_timeout`.

Fix: rename them and use integer nanoseconds. Env still accepts compact spellings because `_` is ignored.
</details>

<details>
<summary>A leak test fails after adding a subscription</summary>

Cause: no exit path. The unsubscribe func was never called, or the `SubscribeChan` channel never reached `Unsubscribe` or bus `Close`.

Fix: defer the unsubscribe closure and `Unsubscribe` as above.
</details>
