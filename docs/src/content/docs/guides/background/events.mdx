`eventbus.EventBus` lets producers publish while zero or more live listeners react. For notify-style fan-out where no reaction is load-bearing (e.g. `booking.created` signal, the bookings example delivers it via [webhooks](../webhooks/)). No durability or redelivery for offline handlers, must-run work goes on the [queue](../queue/) via `job.Dispatcher`.

## Quick start

```sh
EVENTBUS_BUFFER_SIZE=1024
EVENTBUS_MAX_HANDLERS=128
EVENTBUS_HANDLER_TIMEOUT=30s
EVENTBUS_CLOSE_TIMEOUT=5s
```

```go title="main.go" check
package main

import (
	"context"
	"fmt"

	eventbusmemory "github.com/zenta-dev/zever/adapters/eventbus/memory"
	"github.com/zenta-dev/zever/core/eventbus"
)

func main() {
	bus, _ := eventbusmemory.New(eventbus.Options{})
	defer bus.Close()
	ctx := context.Background()

	ch, _ := bus.SubscribeChan(ctx, "orders", 16)
	defer func() { _ = bus.Unsubscribe("orders", ch) }()

	unsub, _ := bus.Subscribe(ctx, "orders", func(_ context.Context, msg eventbus.Message) {
		fmt.Println("push saw", string(msg.Payload))
	})
	defer unsub()

	_ = bus.Publish(ctx, "orders", eventbus.NewPayload([]byte("hello")), nil)
	msg := <-ch
	fmt.Println("pull saw", string(msg.Payload))
}
```

Output: `push saw hello` and `pull saw hello`. `Subscribe` takes a handler and returns an unsubscribe closure, `SubscribeChan` returns a channel. Keep payloads small, versioned JSON.

## Subscribe without leaking goroutines

Every subscription needs an exit path or leak tests flag it: defer the unsubscribe closure after `Subscribe`, and `Unsubscribe` after `SubscribeChan`. Closing the bus also ends subscriptions. Topics: non-empty, max 256 bytes (`MaxTopicLen`). Payloads max 4 MiB (`MaxMessageSize`), oversize publishes fail. Set `OnPanic` (never validated) so a bad subscriber can't take down the publisher. Cap fan-out with `max_handlers`: unbounded subscribes from request paths leak handlers.

## Fan out across instances with Redis

Use `redis` when a publish on one process must reach another, call sites don't change.

<Tabs>
  <TabItem label="YAML">
```sh
EVENTBUS_BUFFER_SIZE=1024
EVENTBUS_REDIS_ADDR=localhost:6379
EVENTBUS_REDIS_DB=0
EVENTBUS_REDIS_PREFIX=bookings
EVENTBUS_REDIS_POOL_SIZE=20
EVENTBUS_REDIS_MIN_IDLE_CONNS=2
EVENTBUS_REDIS_POOL_TIMEOUT=5s
```
  </TabItem>
  <TabItem label="Env">
```sh
EVENTBUS_BUFFER_SIZE=1024
EVENTBUS_HANDLER_TIMEOUT=30s
```
  </TabItem>
</Tabs>

Keys are strict snake_case, Redis pooling nests under `redis`. Zero means adapter default (`buffer_size` 1024, `max_handlers` 128, `handler_timeout` 30s, `close_timeout` 5s), only negatives fail. Unknown keys under a wired service prefix fail with a did-you-mean hint, unknown service heads are ignored, unparsable values error. All keys: [eventbus config reference](../../../reference/config/#eventbus).

| Adapter | Package | Notes |
|---|---|---|
| `memory` | `adapters/eventbus/memory` | Default, process-local, push plus pull, zero infra |
| `redis` | `adapters/eventbus/redis` | Shared fan-out, prefix-keyed, pool-backed |

## Resolve the bus from the container

```go title="main.go"
c := container.New(config.Default(), container.Provide(eventbus.DefaultRef(), eventbusmemory.New))
bus, err := c.EventBus() // alias c.Eventbus()
```

`EventBus()` resolves lazily and caches, on error the cache clears. `New` always returns a bus with pull support: adapters expose the `Pusher` push core and the package wraps it. `Close() error` takes no context. See [the container](../../../concepts/container/). Publishing to a topic with no subscriber is a quiet no-op.

## Production checklist

- Not durable: offline handlers miss messages, no replay.
- Drop-newest backpressure: full per-topic buffer (default 1024) drops the newest message for that subscriber only. Size `buffer_size` for burst + latency.
- Bound handler time with `handler_timeout` (30s), a stuck handler holds its slot and fills its buffer.
- No secrets in payloads. Redaction covers logged config, not bodies.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Subscriber on B never fires for A publishes | `memory` is in-process, set `eventbus.adapter` to `redis` with shared `addr`/`prefix` |
| Messages vanish under load, no error | Buffer full, drop-newest engaged, raise `buffer_size`, shorten handler work (enqueue a job), find slow subscriber |
| Strict load rejects `buffersize`/`maxhandlers` | Pre-rename spellings, use `buffer_size`, `max_handlers`, `handler_timeout`, `close_timeout` (integer ns). Env ignores `_` |
| Leak test fails after new subscription | No exit path, defer unsubscribe/`Unsubscribe` or bus `Close` |
