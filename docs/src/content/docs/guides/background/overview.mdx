Background work composes via the [container](../../../concepts/container/).

## Parts

```text
HTTP handler / schedule tick
        |
   job.Dispatcher ----> queue.Queue (memory | redis | db)
                           |
                       job.Worker pops, runs handler, acks/nacks
```

| Piece | Role | More |
|---|---|---|
| `queue.Queue` | Push/pop/ack/nack transport | [Queue](../queue/) |
| `job.Dispatcher` | JSON args to priority topic | [Scheduler and jobs](../scheduler-jobs/) |
| `job.Worker` | Polls topics, runs handlers | [Scheduler and jobs](../scheduler-jobs/) |
| `scheduler.Scheduler` | Cron -> dispatcher | [Scheduler and jobs](../scheduler-jobs/) |
| `outbox.Store` | Txn event, at-least-once relay | [Outbox](../outbox/) |
| `eventbus.EventBus` | In-process/Redis fan-out | [Events](../events/) |
| `workflow.Workflow` | Durable multi-step runs | [Workflows](../workflows/) |
| Saga | Compensation/roll-forward | [Saga](../saga/) |
| `webhook.Webhook` | Signed outbound delivery | [Webhooks](../webhooks/) |

`Job()` has no adapter: `c.Job()` builds `*job.Dispatcher` over the resolved queue, shared by `c.Scheduler()`.

## Run

One config, two processes (`cmd/server`, `cmd/worker`, `zever generate worker`, `zever worker`, `zever schedule run`).

- `memory`: one process, lost on restart.
- `redis`/`db`: any worker pops.

Scheduler skips missed ticks, handlers idempotent, locker multi-host ([Scheduler and jobs](../scheduler-jobs/)).

## Pick

| Need | Use | Why |
|---|---|---|
| Deferred/retryable | `job.Dispatcher` + worker | Retries |
| Recurring | Scheduler -> job | Cron |
| Txn event | Outbox | Same txn |
| In-process notify | Event bus | Cheap |
| Multi-day steps | Workflow | Resume |
| Cross-system undo | Saga | Undo |
| Signed webhook | Webhook | HMAC |

When loss matters, prefer queue/outbox over event bus: at-least-once -> idempotent consumers ([idempotency/lock](../../security/lock-idempotency/)) or outbox `Inbox`.
