title: .zen syntax
description: Reference for the Zever schema language: entities, relations, services, RPCs, jobs, schedules, sagas, types, and attributes.
---

`.zen` files describe services once, in a proto-inspired syntax. The compiler turns the schema into database access, routing, and queue plumbing, never business logic. Format with `zever fmt`, validate with `zever check`, generate with `zever compile` (see the [CLI reference](../cli/)).

## Files and modules

The module name comes from the immediate subdirectory, not the file name: `schema/app/app.zen` is module `app`. A directory such as `schema/v1/iam/` also gives the module a version (`v1`), and a warning flags RPC paths that do not start with `/v1/`.

Types in the same module reference each other by bare name, with no import. Cross-module references use the module path, and `zever check-boundaries` reports relations, RPC return types, and permission resources that cross modules. Sagas may reference RPCs across modules by design.

## Declarations

| Declaration | Form | Purpose |
|---|---|---|
| `entity` | `entity Name { fields, relations, indexes }` | Persisted record. |
| `service` | `service Name { rpc ... }` | Group of RPCs. |
| `rpc` | `rpc Name(params) -> Return { options }` | Operation with transport bindings. |
| `enum` | `enum Name { a, b }` | Named closed set of values. |
| `message` | `message Name { fields }` | Non-persisted payload shape. Fields only. |
| `job` | `job Name(params) { queue: q  retry: ... }` | Background job. |
| `schedule` | `schedule Name { cron: "..."  dispatch: Job() }` | Cron trigger for a job. |
| `saga` | `saga Name { step s { execute: Svc.Rpc } }` | Compensatable sequence of RPCs. |

Reserved words are `entity`, `service`, `job`, `schedule`, `rpc`, `index`, `enum`, `has_many`, `has_one`, `belongs_to`, `many_to_many`, `message`, `true`, and `false`. Type names, option labels (`http`, `auth`, `queue`, ...), HTTP verbs, `saga`, `step`, and `join_table` are contextual, not reserved. Comments start with `//`, and a comment directly above a declaration becomes its doc comment.

## Types

| Type | Notes |
|---|---|
| `uuid`, `string`, `bool`, `bytes`, `json` | Scalars. |
| `int32`, `int64`, `float32`, `float64` | Numeric scalars. |
| `timestamp`, `date` | Time scalars. `datetime` is an alias of `timestamp`. |
| `enum(a, b)` | Inline enum with unique values. Use a named `enum` declaration to share one. |
| `Name` | Reference to an entity or message. |

Append `?` after the type to make a field optional: `bio: string?`.

## Entities

```zen
entity User {
  id: uuid @primary
  email: string @unique @validate(format: "email")
  created_at: timestamp @default(now())

  has_many orders: Order @foreign_key(user_id)
  index(email, created_at)
}

entity Order {
  id: uuid @primary
  user_id: uuid
  amount_cents: int64

  belongs_to user: User @foreign_key(user_id)
}
```

Declare both sides of a relation with the same `@foreign_key`.

### Field attributes

| Attribute | Applies to | Meaning |
|---|---|---|
| `@primary` | field | Primary key. |
| `@unique` | field | Unique constraint. |
| `@default(x)` | field, message field | Default. `now()` is valid only on `timestamp`. A bare `true` or `false` suits `bool`. An enum default must name a declared value. A literal must match the field's scalar family. |
| `@validate(...)` | field, RPC param, message field | Validation rules, listed below. |
| `@renamed_from("old")` | field | Previous column name, so `zever db migrate` emits a rename instead of a drop and add. The old name must not still be a declared field. |

### Validation rules

| Rule | Applies to | Value |
|---|---|---|
| `format` | `string` | `"email"`, `"url"`, or `"uuid"`. |
| `min_len`, `max_len` | `string` | Integer length. |
| `gt`, `gte`, `lt`, `lte` | numeric scalars | Numeric literal. |

Combine rules in one attribute: `@validate(min_len: 1, max_len: 100)`. `@validate` is rejected on a field or param whose type is an entity or message. Put it on that type's own fields instead.

Every field of an entity or message used as an RPC parameter must carry at least one applicable `@validate` rule. Types used only as return types are exempt, and so are fields with no applicable rule (`uuid`, `bool`, `timestamp`, `date`, `bytes`, `json`, enums).

### Entity attributes

| Attribute | Meaning |
|---|---|
| `@schema(name)` | Database schema for the entity. Defaults to the module name, or `public` when the module is unnamed. |

### Relations

| Keyword | Form | Notes |
|---|---|---|
| `has_many` | `has_many orders: Order @foreign_key(user_id)` | One to many. |
| `has_one` | `has_one profile: Profile @foreign_key(user_id)` | One to one. |
| `belongs_to` | `belongs_to user: User @foreign_key(user_id)` | Owning side. |
| `many_to_many` | `many_to_many tags: Tag { join_table: post_tags }` | No `@foreign_key`. Names the join table in a block. |

| Relation attribute | Values |
|---|---|
| `@foreign_key(field)` | Required on every relation except `many_to_many`. |
| `@on_delete(x)` | `restrict`, `cascade`, or `set_null`. |

### Indexes

`index(a, b)` declares a secondary index over one or more fields. Index attributes follow the closing parenthesis.

## Services and RPCs

```zen
service UserService {
  rpc GetUser(id: uuid) -> User {
    http: GET "/v1/users/{id}"
    auth: required
  }

  rpc CreateUser(email: string @validate(format: "email")) -> User {
    http: POST "/v1/users"
    auth: required
    errors: { already_exists }
  }

  rpc ListOrders(user_id: uuid) -> Order {
    http: GET "/v1/orders"
    auth: required
    paginated: true
  }
}
```

| Option | Value | Effect |
|---|---|---|
| `http:` | `GET`, `POST`, `PUT`, `PATCH`, or `DELETE`, then `"/path/{param}"` | HTTP binding. Every `{param}` needs a same-named RPC input. |
| `auth:` | `required` or `none` | Authentication requirement. Omit for public routes. |
| `permission:` | `check("action", resource: Entity, owner_field: field)` | Authorization check. `resource` must be an entity and `owner_field` one of its fields. |
| `errors:` | `{ code, code("message") }` | Declared error codes from the table below. Duplicates are rejected. |
| `paginated:` | `true` or `false` | `true` emits cursor and page scaffolding from one RPC. |

Every RPC gets a gRPC transport. Repeating `http:`, `auth:`, `permission:`, or `paginated:` in one RPC silently keeps the last value.

### Error codes

| Code | HTTP |
|---|---|
| `cancelled` | 499 |
| `unknown`, `internal`, `data_loss` | 500 |
| `invalid_argument`, `failed_precondition`, `out_of_range` | 400 |
| `deadline_exceeded` | 504 |
| `not_found` | 404 |
| `already_exists`, `aborted` | 409 |
| `permission_denied` | 403 |
| `unauthenticated` | 401 |
| `resource_exhausted` | 429 |
| `unimplemented` | 501 |
| `unavailable` | 503 |

## Jobs, schedules, and sagas

```zen
job SendWelcomeEmail(user_id: string) {
  queue: default
  retry: max_attempts(3), backoff(exponential, base: 30s)
}

schedule DailyReport {
  cron: "0 9 * * *"
  dispatch: GenerateDailyReport()
}

saga PlaceOrder {
  step reserve {
    execute: StockService.Reserve
    compensate: StockService.Release
  }
  step charge {
    execute: PaymentService.Charge
    pivot: true
  }
}
```

| Option | Block | Value |
|---|---|---|
| `queue:` | job | Queue name. |
| `retry:` | job | `max_attempts(n)` with `n > 0`, and `backoff(exponential, base: <duration>)`. Exponential is the only backoff kind. |
| `cron:` | schedule | Cron expression string. |
| `dispatch:` | schedule | `JobName(args)` naming a declared job. |
| `execute:` | saga step | `Service.Rpc`. Required. |
| `compensate:` | saga step | `Service.Rpc` that undoes the step when a later step fails. |
| `pivot:` | saga step | `true` makes failures after this step roll forward instead of compensating. At most one per saga. |

Step names are unique within a saga. Durations use literals such as `30s`.

## Diagnostics

The parser never panics. Malformed input yields best-effort output plus positioned diagnostics, and the formatter refuses input that fails lexing.

| Symptom | Cause |
|---|---|
| Unknown scalar type | Spelling is not in the type table. The compiler suggests the closest scalar. |
| Unresolved relation target | The target is missing or in another module and not referenced by module path, or the two sides name different `@foreign_key` fields. |
| HTTP param has no RPC input | A `{param}` in the `http:` path has no same-named input. |
| Unknown attribute | Entity attributes allow only `@schema`. Field attributes allow `@primary`, `@unique`, `@validate`, `@default`, `@renamed_from`. RPC params and message fields allow `@validate` (message fields also `@default`). |
