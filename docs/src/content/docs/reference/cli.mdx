## Purpose

`zever` is a flags-only toolkit shell. Bare `zever` (no subcommand, TTY or
not) prints usage to stderr and exits 1 so scripts never hang. Every
command has an exact CLI invocation; run `zever --help` for the grouped
command map.

## Bare-command contract

- Bare `zever` (no subcommand, TTY or not): usage to stderr plus `zever: missing subcommand`, exit 1.
- All errors go to stderr; stdout stays clean for command output.

## Global flags and exit codes

- `--quiet`: suppress hints/tips on stderr; errors still print.
- `--no-color`: disable styled output (also honored via `NO_COLOR` /
  `TERM=dumb` ambient env).
- Exit codes: `0` success, `1` runtime error, `2` flag misuse (bad
  flags print the error to stderr with no usage dump).
- `--help` output goes to stdout; errors and bare-invocation usage go
  to stderr.

## Shell completion and generated docs

- `zever completion <shell>` prints that shell's completion script to
  stdout, e.g. `zever completion bash > /etc/bash_completion.d/zever`.
- `zever docs --dir <dir>` writes one man page plus one markdown file
  per command into `<dir>`.

## Dev and tinker rules

- `zever dev` is local watch-only: it watches the schema dir and server
  entrypoint, restarts on change, and stops on Ctrl-C. Never a deployment
  path.
- `zever tinker` is dev-only: every start prints the development-only warning
  to stderr and evaluates arbitrary Go against a live container via the
  per-project shim (`cmd/tinker-shim`). Never point it at production data.

## Notes

- `zever <command> -h` always prints flags without running anything.
- `-i` / `--interactive` (or `ZEVER_INTERACTIVE=1`) enables guided `huh` prompts for one-shot commands.
- `migrate`/`rollback` mask the DSN (`--dsn ***`) in display and output.
