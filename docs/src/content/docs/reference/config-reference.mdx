## Purpose

Layered typed config resolves as `defaults < file < env`. Defaults are
zero-infra so tests run bare; files are strict YAML/JSON; env is best-effort
`<SERVICE>_<FIELD>` with no prefix.

## File example

```yaml
db:
  adapter: postgres
  options:
    dsn: postgres://app:secret@db:5432/app
    maxconns: 20
log:
  adapter: slog
```

`Load("")` probes `zever.yaml`, `zever.yml`, then `zever.json`; first hit
wins. Unknown services/fields fail fast.

## Env scheme

```sh
DB_ADAPTER=postgres
DB_MAXCONNS=20
AUTH_JWT_SECRET=prod-secret-at-least-32-bytes-long
```

Best-effort: unknown vars ignored, only unparsable resolved fields error.
Field matching is case-insensitive with `_` ignored; one nesting level
splits at the first `_`.

## Notes

- Dev secrets (crypto key) are deterministic and must never reach production.
- Never log raw option maps; display via `RedactedServices`/`Redact`.
