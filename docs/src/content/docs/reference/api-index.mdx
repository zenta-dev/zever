## Purpose

Multi-module monorepo. Battery interfaces live in `core/<b>` with the `Register`/`Open` registry; each adapter lives in its own module at `adapters/<b>/<a>` with a `Register()` call wiring it in; SDK-free helpers live in `shared/*`.
Import the `core` interface plus the adapter modules you need; resolve through `container`.

When to use: find the package, accessor, and close shape for a service.
When not to use: DSL internals (`dsl/*`) are internal-only;
runtime code must not import the compiler.

## Prerequisites

- Go module importing `github.com/zenta-dev/zever`.
- `config.Default()` or `config.Load("")` for the container root.
- `ctx` as first arg for IO; never stored in structs.

## Config

No API-index config: construction is always config plus container:

```go
import (
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
)

c := container.New(config.Default())
db, err := c.DB()
if err != nil {
    return err
}
```

`container.New(nil)` is valid: an untouched container closes cleanly
without opening anything.

## Resolve

Each service resolves on first use and caches the result. On error the
cached state clears so the next call retries.

```go
q, err := c.Queue()
if err != nil {
    return err
}
d, err := c.Job() // d shares the resolved queue instance
if err != nil {
    return err
}
```

`Job()` has no registry of its own: it builds a `*job.Dispatcher` over the
already-resolved `Queue`. `Scheduler()` injects that dispatcher, so the
scheduler shares the same `Queue` connection instead of opening a
redundant one. Resolving `Scheduler()` therefore resolves `Job()` and,
transitively, `Queue` as a side effect.

## Runnable example

```go
ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
db, err := c.DB()
if err != nil {
    return err
}
_ = db
if err := c.Close(ctx); err != nil {
    var te *container.CloseTimeoutError
    var pe *container.ClosePanicError
    _ = te
    _ = pe
    return err
}
```

Expected output:

```text
db resolves on first use; Close shuts down only resolved services, dependents first
exit:0 (non-nil only on per-service close failures, joined via errors.Join)
```

### Close-shape standard

| Shape | Used by | Semantics |
|---|---|---|
| `Close(ctx)` | pooled or network-backed services that may block (`db`, `cache`, `storage`, `lock`, `container` itself) | context-bounded shutdown |
| `Close()` | lightweight handles, iterators, statements, instant-close in-memory adapters (`auth`, `queue`, `session`, `payment`, `eventbus.Pusher`, `ratelimit.Limiter`, `db.Rows`, `db.Stmt`) | instant close |
| `Stop()` | scheduler only | cron lifecycle stop |

Probing (`closeAny`) tries `Close(context.Context) error`, then `Close()
error`, then `Stop() error`, then `Shutdown(context.Context) error`
(observability providers flush buffered spans/metrics), then no-op nil
(`*job.Dispatcher` has no shutdown method). Crypto, log, password,
permission, and router declare no Close/Stop/Shutdown and probe as no-op
nil. Callers never guess: the probe picks the shape.

Close order:

```text
scheduler, job        dependents holding a queue ref, first
snapshots             everything without explicit ordering
cache, queue          leaf dependencies, last
grpcServer            independent GracefulStop/Stop, bounded by ctx
```

Details: per-service bound is 5s only when the parent context carries no
deadline; otherwise the parent deadline bounds each wait. Shared instances
close once (pointer-identity dedup with a `keepAlive` set for the
duration). Failures join via `errors.Join`; panics become
`*ClosePanicError`, timeouts become `*CloseTimeoutError`. Error values name
the service only, never resolved values. `Close` never opens anything:
untouched services stay untouched.

## Production notes

- Start from `config.Default()` + `container.New`, then per-service
  accessors; no globals, no `init()` wiring.
- Keep to documented interfaces; new behavior means new interfaces, never
  new methods on public ones.
- Pass a parent deadline to `Close` in servers so shutdown is bounded end
  to end; inspect `CloseTimeoutError` / `ClosePanicError` with `errors.As`.
- Goroutine-safe types document their exit path; resolve the in-memory
  subset and `Close` it in tests so `goleak` stays clean.

## Troubleshooting

- **Close hangs**: parent context has no deadline and a service blocks;
  pass a timeout context (per-service bound is 5s only without one).
- **Close reports `CloseTimeoutError`**: a service outlived its bound.
  Check which service is named, then its backing store health.
- **Close reports `ClosePanicError`**: a service panicked during shutdown.
  Fix the service; the panic value is captured, not re-thrown.
- **Accessor keeps failing**: cached state clears on error, so each call
  retries fresh. Persistent failure means config or backend, not the
  container; check `Validate` and connectivity.
