Each `core/<b>` package holds one interface plus its `Options` and `DefaultRef`, each adapter is its own Go module at `adapters/<b>/<a>` exposing a `New` constructor, and the container resolves only what is Provided. This matrix maps service to adapter module, constructor, and accessor. Prefer a new interface over adding methods, which break implementers.

## Swap an adapter in code

Backends are compiled in: changing one means changing the import and the `container.Provide` entry in `internal/app/wiring.go`, then rebuilding. There is no adapter env key.

```go
import (
    cacheredis "github.com/zenta-dev/zever/adapters/cache/redis"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/cache"
)

var Cache = cache.DefaultRef()

func Providers() []container.Provider {
    return []container.Provider{
        container.Provide(Cache, cacheredis.New), // was cachememory.New
        // ... one entry per battery
    }
}
```

Options still come from the environment (`CACHE_ADDR=redis:6379`, `DB_DSN=...`); only the backend choice lives in code.

## Resolve through the container

```go
c := container.New(cfg, app.Providers()...)
cache, err := c.Cache()
if err != nil {
    return err
}
q, err := c.Queue()
if err != nil {
    return err
}
```

`New(nil)` is valid; untouched services close cleanly without opening. Accessors resolve lazily and retry on the next call after an error. `Job()` builds over the resolved `Queue`; `Scheduler()` shares both, so resolving `Scheduler()` resolves `Job()` and `Queue` as a side effect. An unwired service fails with `NotWiredError` naming the missing `container.Provide` entry.

All defaults (memory/local/sqlite/log/noop) fit single-process dev. Move shared state to redis/postgres for multi-instance staging by swapping the wired constructors, then rebuilding.

## Adapter reference

Each row is `| service | adapter | module | constructor | accessor |`. The container wires nothing itself: every adapter resolves only after its `container.Provide` entry runs, and only imported adapters link into the binary. `none (no backend)` marks the `job` dispatcher, which builds over the resolved queue instead of opening a backend.

Install every adapter module you resolve (replace `vX.Y.Z` with the lockstep release version):

```sh
go get github.com/zenta-dev/zever/adapters/cache/redis@vX.Y.Z
```

import cacheredis "github.com/zenta-dev/zever/adapters/cache/redis"

container.Provide(Cache, cacheredis.New)

### Single-process vs multi-instance

| Group | Single process | Multi-instance |
|---|---|---|
| cache, lock, ratelimit, idempotency, session, queue, eventbus | `memory` | `redis` (state must be shared) |
| db | `sqlite` | `postgres` |
| storage, media | `local` | `s3` / `r2` |
| auth | `jwt` (stateless) or `session` + shared store | `jwt`, or `session` only with shared store |
| search | `db` | `db` / `meilisearch` |
| vectorstore | `db` | `db` / `qdrant` |
| mailer, notification, analytics | `log` (dev) | `smtp` / `twilio`+`fcm` / `posthog` |
| permission | `noop` (dev) / `rbac` | `rbac` / `casbin` |
| billing, payment | `stub` (dev) | `stripe` / `paddle` |

## Production notes

- `Close(ctx)` closes only resolved services, dependents first; see [API index](../api-index/) for order and close shapes.
- `grpc` has a lazy `*grpc.Server` singleton accessor (`GRPC(opts...)`) with no registry; `EventBus()` keeps an `Eventbus()` alias and `RateLimit()` a `Ratelimit()` alias.
- Do not add methods to public interfaces; prefer new interfaces so external implementers keep compiling.
- Shared redis/postgres endpoints become critical path: monitor, pool (`max_conns`), and bound timeouts per service.

## Troubleshooting

- **State differs per instance**: a `memory` adapter is still in the mix (cache, queue, session, lock). Move each shared-state service to `redis`.
- **Logins lost on restart**: `session` on `memory` does not survive restarts. Use a shared session store for anything beyond local dev.
- **Jobs run twice or not at all**: workers each resolved an isolated `memory` queue. Point all workers at the same shared queue (`redis`, or `db` on one database).
- **Swap did not take effect**: the wiring still binds the old adapter. Check the `container.Provide` line in `internal/app/wiring.go`, rebuild, and make sure no leftover `*_ADAPTER` key sits in `.env` (the resolver rejects it).
