Each `core/<b>` holds one interface plus `Options` and `DefaultRef`. Each adapter is a module at `adapters/<b>/<a>` exposing `New`. The container resolves only Provided entries. Prefer new interfaces over new methods.

## Swap an adapter in code

Backends are compiled in: change the import plus `container.Provide` in `internal/app/wiring.go`, rebuild. No adapter env key.

```go
import (
    cacheredis "github.com/zenta-dev/zever/adapters/cache/redis"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/cache"
)

var Cache = cache.DefaultRef()

func Providers() []container.Provider {
    return []container.Provider{
        container.Provide(Cache, cacheredis.New), // was cachememory.New
        // ... one entry per battery
    }
}
```

Options come from the environment (`CACHE_ADDR=redis:6379`, `DB_DSN=...`). Only the backend choice lives in code.

## Resolve through the container

```go
c := container.New(cfg, app.Providers()...)
cache, err := c.Cache()
if err != nil {
    return err
}
q, err := c.Queue()
if err != nil {
    return err
}
```

`New(nil)` is valid. Untouched services close without opening. Accessors resolve lazily, retrying after errors. `Job()` builds over `Queue`. `Scheduler()` shares both. Unwired services fail `NotWiredError` naming the missing `Provide`.

Defaults (memory/local/sqlite/log/noop) fit single-process dev. Share state via redis/postgres for multi-instance staging.

## Adapter reference

Rows are `| service | adapter | module | constructor | accessor |`. Nothing resolves without `container.Provide`. Only imported adapters link in. `none (no backend)` is the `job` dispatcher over `Queue`.

Install each resolved adapter module (`vX.Y.Z` = lockstep release):

```sh
go get github.com/zenta-dev/zever/adapters/cache/redis@vX.Y.Z
```

### Single-process vs multi-instance

| Group | Single process | Multi-instance |
|---|---|---|
| cache, lock, ratelimit, idempotency, session, queue, eventbus | `memory` | `redis` (state must be shared) |
| db | `sqlite` | `postgres` |
| storage, media | `local` | `s3` / `r2` |
| auth | `jwt` (stateless) or `session` + shared store | `jwt`, or `session` only with shared store |
| search | `db` | `db` / `meilisearch` |
| vectorstore | `db` | `db` / `qdrant` |
| mailer, notification, analytics | `log` (dev) | `smtp` / `twilio`+`fcm` / `posthog` |
| permission | `noop` (dev) / `rbac` | `rbac` / `casbin` |
| billing, payment | `stub` (dev) | `stripe` / `paddle` |

## Production notes

- `Close(ctx)` closes only resolved services, dependents first. See [API index](../api-index/) for order and shapes.
- `grpc` is a lazy `*grpc.Server` singleton (`GRPC(opts...)`) with no registry. `Eventbus()` aliases `EventBus()`, `Ratelimit()` aliases `RateLimit()`.
- Never add methods to public interfaces. Prefer new interfaces.
- Shared redis/postgres endpoints are critical path: monitor, pool (`max_conns`), and bound per-service timeouts.

## Troubleshooting

- **State differs per instance**: a `memory` adapter is still wired (cache, queue, session, lock). Move shared state to `redis`.
- **Logins lost on restart**: `session` on `memory` is ephemeral. Use a shared store beyond local dev.
- **Jobs run twice or not at all**: workers resolved isolated `memory` queues. Point them at one shared queue (`redis`, or `db` on one database).
- **Swap did not apply**: wiring still binds the old adapter. Check `container.Provide` in `internal/app/wiring.go`, rebuild, and drop stale `*_ADAPTER` keys from `.env` (rejected by the resolver).
