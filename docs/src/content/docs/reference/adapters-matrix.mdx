Each `core/<b>` package holds one interface plus a `Register`/`Open` registry, each adapter is its own Go module at `adapters/<b>/<a>`, and the container is the sole resolver. This matrix maps service to adapter module and accessor so swaps stay config-only. Prefer a new interface over adding methods, which break implementers.

## Swap an adapter by config

```yaml
cache:
  adapter: redis
  options:
    addr: redis:6379
queue:
  adapter: redis
db:
  adapter: postgres
  options:
    dsn: postgres://app:secret@db:5432/app
```

```sh
CACHE_ADAPTER=redis
QUEUE_ADAPTER=redis
DB_ADAPTER=postgres
```

## Resolve through the container

```go
c := container.New(cfg)
cache, err := c.Cache()
if err != nil {
    return err
}
q, err := c.Queue()
if err != nil {
    return err
}
```

`New(nil)` is valid; untouched services close cleanly without opening. Accessors resolve lazily and retry on the next call after an error. `Job()` builds over the resolved `Queue`; `Scheduler()` shares both, so resolving `Scheduler()` resolves `Job()` and `Queue` as a side effect.

All defaults (memory/local/sqlite/log/noop) fit single-process dev. Move shared state to redis/postgres for multi-instance staging:

```sh
DB_ADAPTER=postgres CACHE_ADAPTER=redis QUEUE_ADAPTER=redis go run ./cmd/myapp
```

## Adapter reference

Each row is `| service | adapter | module | register | accessor |`. The container wires nothing: every adapter resolves only after its `Register()` runs. `none (no registry)` marks the `job` dispatcher, the `media/ffmpeg` binary helper, and the `session/cookie` stdlib builder.

Install every adapter module you resolve (replace `vX.Y.Z` with the lockstep release version):

```sh
go get github.com/zenta-dev/zever/adapters/cache/redis@vX.Y.Z
```

```go
import "github.com/zenta-dev/zever/adapters/cache/redis"

redis.Register()
```

### Single-process vs multi-instance

| Group | Single process | Multi-instance |
|---|---|---|
| cache, lock, ratelimit, idempotency, session, queue, eventbus | `memory` | `redis` (state must be shared) |
| db | `sqlite` | `postgres` |
| storage, media | `local` | `s3` / `r2` |
| auth | `jwt` (stateless) or `session` + shared store | `jwt`, or `session` only with shared store |
| search | `db` (legacy `sqlite`/`postgres` aliases) | `db` / `meilisearch` |
| vectorstore | `db` (legacy `sqlite`/`pgvector` aliases) | `db` / `qdrant` |
| mailer, notification, analytics | `log` (dev) | `smtp` / `twilio`+`fcm` / `posthog` |
| permission | `noop` (dev) / `rbac` | `rbac` / `casbin` |
| billing, payment | `stub` (dev) | `stripe` / `paddle` |

## Production notes

- `Close(ctx)` closes only resolved services, dependents first; see [API index](../api-index/) for order and close shapes.
- `grpc` has a lazy `*grpc.Server` singleton accessor (`GRPC(opts...)`) with no registry; `EventBus()` keeps an `Eventbus()` alias and `RateLimit()` a `Ratelimit()` alias.
- Do not add methods to public interfaces; prefer new interfaces so external implementers keep compiling.
- Shared redis/postgres endpoints become critical path: monitor, pool (`max_conns`), and bound timeouts per service.

## Troubleshooting

- **State differs per instance**: a `memory` adapter is still in the mix (cache, queue, session, lock). Move each shared-state service to `redis`.
- **Logins lost on restart**: `session` on `memory` does not survive restarts. Use a shared session store for anything beyond local dev.
- **Jobs run twice or not at all**: workers each resolved an isolated `memory` queue. Point all workers at the same shared queue (`redis`, or `db` on one database).
- **Swap did not take effect**: `_ADAPTER` env or file adapter misspelled, or an old binary without the adapter compiled in. Check `config show` output and rebuild.
