Rules for error messages, sentinels, wrapping, and branching. Enforced by `make err-lint` (`tools/errscan`). Additive, not a cleanup of existing code.

## Message format

Every message starts with `<package>: <message>`: colon-space prefix naming the emitter. No brackets, trailing period, or capitalization.

```go
// good
var ErrNotFound = errors.New("store: record not found")
return fmt.Errorf("store: get %q: %w", key, err)

// bad
var ErrNotFound = errors.New("record not found")         // unprefixed
var ErrNotFound = errors.New("[E404] record not found")  // bracket prefix
var ErrNotFound = errors.New("Store: record not found.") // capitalized, trailing period
```

## Sentinel errors

- Named `ErrXxx`, package-level, in `errors.go`.
- Doc comment required (exported convention).
- Public API: renames and removals break.

```go
// errors.go

// ErrNotFound is returned when a lookup matches no record.
var ErrNotFound = errors.New("store: record not found")
```

## Custom error types

- Named `FooError`, value receivers by default (comparable, safe to copy).
- `Unwrap() error` when wrapping another error.
- Structured data as fields. Extract with `errors.As`/`errors.AsType`.

```go
// ValidationError describes a single failed field check.
type ValidationError struct {
	Field  string
	Reason string
}

func (e ValidationError) Error() string {
	return fmt.Sprintf("validate: field %q: %s", e.Field, e.Reason)
}

func (e ValidationError) Unwrap() error { return ErrValidation }
```

## Wrapping

- Wrap with `%w` so `errors.Is`/`errors.As` keep working.
- Never put two `%w` in one `fmt.Errorf`. Combine sentinel plus cause with `errors.Join`.
- Use `%v` only to deliberately break the chain at a boundary (context callers must not match on).

```go
// good
return fmt.Errorf("store: get %q: %w", key, err)
return errors.Join(ErrNotFound, fmt.Errorf("store: get %q: %w", key, err))

// bad
return fmt.Errorf("store: %w: %w", ErrNotFound, err) // two %w verbs
```

## Multi-error

- Default: `errors.Join` in one `Unwrap() error` (e.g. `container.Close`).
- `Unwrap() []error` only for callers needing element-wise access.

## Branching

- Branch with `errors.Is`/`errors.AsType` only, never on strings.

```go
if errors.Is(err, ErrNotFound) { ... }

var target *ValidationError
if errors.AsType[*ValidationError](err, &target) { ... }
```

Go 1.26+ `errors.AsType[E]` is preferred. `errors.As` stays valid.

## Panics

- Panics only guard resolver invariants in `dsl/backend/gogen/render_validate.go`. The parser never panics.
- Everything else returns an error.

## Boundaries and security

- Translate errors at package/service boundaries: map internals to safe, stable messages before they leave the process (HTTP, CLI, RPC).
- Never leak internals (DSNs, SQL, stack, addresses) to external callers.
- Log once, structured, via `log/slog` or the repo logger. Redact secrets (`config.Redact`, `redis.RedactAddr`). Never log raw option maps.

```go
func (s *Service) Handle(w http.ResponseWriter, r *http.Request) {
	if err := s.do(r.Context()); err != nil {
		s.log.ErrorContext(r.Context(), "service: handle", "err", err)
		http.Error(w, "internal error", http.StatusInternalServerError)
		return
	}
}
```

## Guard

`make err-lint` (`tools/errscan`) fails on:

- `unprefixed`: `errors.New`/`fmt.Errorf` literal with no `:` in its first token (skipped: `shared/apperror`, `_test.go`).
- `bracket-prefix`: literal starting with `[...]` (outside `shared/apperror` `[CODE]` messages).
- `double-%w`: two or more `%w` in one `fmt.Errorf` format string.
- `panic`: `panic(...)` outside `dsl/backend/gogen/render_validate.go` and `_test.go` files.

Escape hatch: `// errscan:allow` on the line (or anywhere in the file for file-level).
