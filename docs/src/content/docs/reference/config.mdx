Zever config is one block per service, shaped `{ adapter, options }`. This page lists all 37 services and every option each one accepts.

## Layering and rules

| Rule | Behavior |
|---|---|
| Layers | `defaults < .env < .env.local < process env`. Later layers win. |
| Defaults | `config.Default()` selects zero-infrastructure adapters (memory, local, sqlite, log, noop). The only dev secret is the crypto key, which is deterministic and must never ship to production. |
| Env | `config.FromEnv()` reads `.env`, then `.env.local`, from the working directory and overlays the real process environment; `config.Resolve(env)` turns that map into the typed `Config`. `config.LoadEnv(files...)` parses explicit dotenv files only (no discovery, no process environment). Env names are uppercase and carry no prefix. The default instance is `<SERVICE>_<FIELD>` (e.g. `DB_MAXCONNS=20`); a named instance is `<SERVICE>__<NAME>__<FIELD>` (e.g. `DB__REPORTING__DSN=postgres://...`) and only reaches the container through a matching named Ref such as `db.Ref("reporting")`. `<SERVICE>_ADAPTER` and `<SERVICE>__<NAME>__ADAPTER` set the adapter. Matching ignores case and `_`, so `DB_MAXCONNS` and `DB_MAX_CONNS` both set `MaxConns`. No config file is read: `zever.yaml`, `zever.yml`, `zever.json`, and `zever.toml` are never looked for, so a stale one in the working directory contributes no keys. |
| Env strictness | The source of truth is `.env`, `.env.local`, and the process environment only; no config file is read, so every key that reaches `Resolve` comes from one of those three. Ambient-safe, and strict about the keys it understands. An unknown key under a wired service prefix fails `Resolve` with an `UnknownFieldError` and a did-you-mean hint **when it is close to a known field** (`DB_MAXCONN` → `did you mean "max_conns"?`); a key close to no known field is an unrelated ambient variable (`AI_AGENT`, `LOG_LEVEL`, `DB_URL`, `CACHE_DIR`) and is ignored, so a noisy process environment cannot break startup. An unknown service head (`PATH`, `FOO_BAR`) and a bare name (`DB`) are ignored too. Set `ZEVER_CONFIG_STRICT=1` to reject every unknown key under a wired prefix instead. A value that fails to parse for a resolved field returns `InvalidOptionsError` (the value is never echoed). |
| Durations | In env, a Go duration string such as `5s` or `5m`. |
| Options replace defaults | Env variables overlay one field at a time and do not replace the block. |
| Unset values | A zero value (`0`, `""`, `false`) means unset: the adapter applies its own default, shown in the Default column when known. |
| Redaction | Raw option maps can hold secrets. Log only through `RedactedServices` or `Redact`. Error text names services and fields, never values. |
| Plugins | A top-level `plugins` map holds third-party services as `{adapter, options}` envelopes. The envelope is strict, but the options pass through raw and the plugin validates them. Env can override only `<PLUGIN>__<NAME>__ADAPTER`. |
| Exceptions | The `secrets` env adapter reads secrets with a non-empty `prefix` (default `ZEVER`, so `ZEVER_FOO` is secret `FOO`). CLI switches use `ZEVER_INTERACTIVE` and `ZEVER_NO_HINT`. |

```sh
DB_ADAPTER=postgres
DB_DSN=postgres://app:secret@db:5432/app
DB_MAX_CONNS=20
LOG_ADAPTER=slog
```

A named instance uses the double-underscore form and needs a matching named
Ref (`db.Ref("reporting")`) wired through `container.Provide`:

```sh
DB__REPORTING__ADAPTER=postgres
DB__REPORTING__DSN=postgres://app:secret@db:5432/reporting
DB__REPORTING__MAX_CONNS=10
```

```sh
DB_MAXCONNS=20 DB_MAXCONNLIFETIME=5m AUTH_JWT_SECRET=prod-secret-at-least-32-bytes-long zever serve
```

## Unknown keys and ambient variables

The env namespace is flat (`<SERVICE>_<FIELD>`), so it shares the process
environment with every other program. An unknown key under a wired service
prefix has three outcomes:

| Key | Outcome |
|---|---|
| Resolves to a field | Applied. |
| Close to a field (a typo) | Fails with `config: unknown field "MAXCONN" for service "db" (did you mean "max_conns"?)`. |
| Close to no field | Ignored: an unrelated ambient variable (`AI_AGENT`, `LOG_LEVEL`, `DB_URL`, `CACHE_DIR`). It lands on no field. |

"Close" means edit distance ≤ 2 (≤ 3 for names longer than six characters),
the same threshold the did-you-mean hint uses.

To reject every unknown key under a wired prefix instead (the v0.8
behavior), set the strict switch:

```sh
ZEVER_CONFIG_STRICT=1 zever serve
```

The switch is read from the environment map `config.Resolve` and
`config.ApplyEnv` are given, so it needs no CLI flag. Keys whose head names
no service (`PATH`, `FOO_BAR`) stay ignored in every mode.

## Shared option groups

### Redis connection options

Services with a Redis adapter embed the same connection keys. Flat services (`cache`, `lock`, `queue`) take them directly. Services with a `redis` block (`eventbus`, `idempotency`, `ratelimit`, `resilience`, `session`) take them under `redis.`.

| Key | Type | Default | Description |
|---|---|---|---|
| `addr` | string | `localhost:6379` | Redis address as `host:port`, or a `redis://` or `rediss://` URL. |
| `password` | string | `""` | Redis password. Never logged. |
| `db` | integer | `0` | Redis database index. |
| `tls` | boolean | `false` | Enable TLS with a TLS 1.2 floor for plain addresses. Off means plaintext, including the password. |
| `require_tls` | boolean | `false` | Fail connection setup instead of connecting in plaintext when the address would not use TLS. |
| `pool_size` | integer | go-redis default | Base number of socket connections (10 per GOMAXPROCS when `<= 0`). |
| `min_idle_conns` | integer | `2` | Pre-warmed idle connections. |
| `pool_timeout` | duration | go-redis default | Wait for a pooled connection when exhausted. |
| `max_conn_idle_time` | duration | go-redis default | Idle time before a connection may close. |
| `max_conn_lifetime` | duration | unbounded | Maximum reuse time for a connection. |

`lock` and `queue` accept only `addr`, `password`, `db`, `tls`, and `require_tls` from this group. `cache` and `queue` also accept a top-level `url` that takes precedence over `addr`. Under `redis.`, `url` is reserved and ignored.

### Retry policy

`outbox` and `resilience` take a `retry` block. Its keys are snake_case, matched case-insensitively.

| Key | Type | Default | Description |
|---|---|---|---|
| `retry.base_delay` | duration | `0` | Delay before the first retry. `resilience` default is `50ms`. |
| `retry.max_delay` | duration | unbounded | Cap on the computed delay, before jitter. `resilience` default is `2s`. |
| `retry.multiplier` | number | `0` | Per-attempt growth factor. Values `<= 1` keep the delay flat. `resilience` default is `2`. |
| `retry.linear` | boolean | `false` | Grow linearly (`base_delay * attempt`) instead of exponentially. Ignores `multiplier`. |
| `retry.jitter` | number | `0` | Fraction of the delay to randomize, clamped to `[0, 1]`. `resilience` default is `0.1`. |
| `retry.jitter_mode` | integer | `0` | `0` symmetric (plus or minus), `1` additive (never shortens), `2` flat (adds up to `jitter_max`). |
| `retry.jitter_max` | duration | `0` | Upper bound of the flat jitter draw. Used only when `jitter_mode` is `2`. |
| `retry.max_attempts` | integer | `1` | Total attempts including the first. `<= 0` means 1. `resilience` default is `3`. |

### Pool sharing

DB-backed services (`db`, `cache`, `queue`, `search`, `session`, `idempotency`, `workflow`, `scheduler`, `vectorstore`, `outbox`) share one container pool per exact DSN by default. Matching is on the trimmed DSN string, so a URL with and without a query string are different pools. SQLite shares by cleaned file path, and `:memory:` never shares.

- The second service to open a DSN borrows the first pool and never closes it. The shared pool takes the first opener's pool settings, and a differing nonzero `max_conns` logs a warning without DSN content.
- Set `dedicated_pool: true` to open a private pool. Use it with a separate database for `queue`, `workflow`, and `scheduler` under sustained load.
- `dedicated_pool` is ignored on `db` itself, which owns the pool.
- Env: `SEARCH_DEDICATEDPOOL=true`, `QUEUE_DSN=...`, `SESSION_DSN=...`.
- Old binaries reject `dedicated_pool` and `dsn` under strict decoding, so remove those lines before a downgrade.

```sh
SEARCH_ADAPTER=db
SEARCH_DSN=postgres://app:secret@db:5432/app?sslmode=require
SEARCH_DEDICATED_POOL=false
```

| Guide | [Storage guide](../../guides/data/storage-media/) |

| Key | Type | Default | Description |
|---|---|---|---|
| `url_base` | string | `""` | Base URL minted presigned URLs build on |

**`policy`** is a flat map: the `Default` key is the fallback policy for unlisted buckets, and every other key is a bucket name. A nil policy means legacy private mode.

|---|---|---|---|
| `policy.<bucket>.version` | string | `"0"` | Policy schema version. |

`<op>` is one of `read` (downloads), `write` (new objects), `update` (overwrites), or `delete`.
