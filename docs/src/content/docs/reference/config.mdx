Zever config is one block per service, shaped `{ adapter, options }`. This page lists all 36 services and every option each one accepts.

## Layering and rules

| Rule | Behavior |
|---|---|
| Layers | `defaults < file < env`. Later layers win. |
| Defaults | `config.Default()` selects zero-infrastructure adapters (memory, local, sqlite, log, noop). The only dev secret is the crypto key, which is deterministic and must never ship to production. |
| File | `config.Load(path)` decodes `.yaml`, `.yml`, or `.json` strictly. Unknown services and unknown fields fail the load. `Load("")` probes `zever.yaml`, `zever.yml`, then `zever.json` in the working directory. Any other extension fails with `ErrUnsupportedFormat`. |
| File keys | snake_case, for example `max_conns`. The old flat spellings (`maxconns`) are rejected as unknown fields. |
| Env | `<SERVICE>_<FIELD>=value`, uppercase, no prefix: `DB_MAXCONNS=20`, `AUTH_JWT_SECRET=...`. Matching ignores case and `_`, so `DB_MAX_CONNS` also works. One nesting level splits at the first `_`. `<SERVICE>_ADAPTER` sets the adapter. |
| Env strictness | Best-effort. Unknown variables are ignored, so a noisy process environment cannot break startup. Only a value that fails to parse for a resolved field returns `InvalidOptionsError` (the value is never echoed). |
| Durations | In files, an integer count of nanoseconds (`5s` is `5000000000`). In env, a Go duration string such as `5s` or `5m`. |
| Options replace defaults | A non-empty `options` block in a file replaces the default options for that service wholesale: keys you leave out become zero, not their `config.Default()` value. Repeat any default you still need (for example `password` needs all five parameters, `mailer` needs `host` and `port`, `ratelimit` needs `rate` and `burst`). An empty or missing `options` keeps the defaults. Env variables overlay one field at a time and do not replace the block. |
| Unset values | A zero value (`0`, `""`, `false`) means unset: the adapter applies its own default, shown in the Default column when known. |
| Redaction | Raw option maps can hold secrets. Log only through `RedactedServices` or `Redact`. Error text names services and fields, never values. |
| Plugins | A top-level `plugins` map holds third-party services as `{adapter, options}` envelopes. The envelope is strict, but the options pass through raw and the plugin validates them. Env can override only `<PLUGIN>_ADAPTER`. |
| Exceptions | The `secrets` env adapter reads secrets with a non-empty `prefix` (default `ZEVER`, so `ZEVER_FOO` is secret `FOO`). CLI switches use `ZEVER_INTERACTIVE` and `ZEVER_NO_HINT`. |

```yaml title="zever.yaml"
db:
  adapter: postgres
  options:
    dsn: postgres://app:secret@db:5432/app
    max_conns: 20
log:
  adapter: slog
```

```sh
DB_MAXCONNS=20 DB_MAXCONNLIFETIME=5m AUTH_JWT_SECRET=prod-secret-at-least-32-bytes-long zever serve
```

A JSON Schema ships as `config/schema/zever.schema.json` for editor completion of `zever.yaml`, `zever.yml`, and `zever.json`. It currently lacks the `outbox` and `resilience` services and some adapter options, so this page, built from the Go option structs, is the authority.

## Shared option groups

### Redis connection options

Services with a Redis adapter embed the same connection keys. Flat services (`cache`, `lock`, `queue`) take them directly. Services with a `redis` block (`eventbus`, `idempotency`, `ratelimit`, `resilience`, `session`) take them under `redis.`.

| Key | Type | Default | Description |
|---|---|---|---|
| `addr` | string | `localhost:6379` | Redis address as `host:port`, or a `redis://` or `rediss://` URL. |
| `password` | string | `""` | Redis password. Never logged. |
| `db` | integer | `0` | Redis database index. |
| `tls` | boolean | `false` | Enable TLS with a TLS 1.2 floor for plain addresses. Off means plaintext, including the password. |
| `require_tls` | boolean | `false` | Fail connection setup instead of connecting in plaintext when the address would not use TLS. |
| `pool_size` | integer | go-redis default | Base number of socket connections (10 per GOMAXPROCS when `<= 0`). |
| `min_idle_conns` | integer | `2` | Pre-warmed idle connections. |
| `pool_timeout` | duration | go-redis default | Wait for a pooled connection when exhausted. |
| `max_conn_idle_time` | duration | go-redis default | Idle time before a connection may close. |
| `max_conn_lifetime` | duration | unbounded | Maximum reuse time for a connection. |

`lock` and `queue` accept only `addr`, `password`, `db`, `tls`, and `require_tls` from this group. `cache` and `queue` also accept a top-level `url` that takes precedence over `addr`. Under `redis.`, `url` is reserved and ignored.

### Retry policy

`outbox` and `resilience` take a `retry` block. Its keys are exported Go field names, matched case-insensitively.

| Key | Type | Default | Description |
|---|---|---|---|
| `retry.BaseDelay` | duration | `0` | Delay before the first retry. `resilience` default is `50ms`. |
| `retry.MaxDelay` | duration | unbounded | Cap on the computed delay, before jitter. `resilience` default is `2s`. |
| `retry.Multiplier` | number | `0` | Per-attempt growth factor. Values `<= 1` keep the delay flat. `resilience` default is `2`. |
| `retry.Linear` | boolean | `false` | Grow linearly (`BaseDelay * attempt`) instead of exponentially. Ignores `Multiplier`. |
| `retry.Jitter` | number | `0` | Fraction of the delay to randomize, clamped to `[0, 1]`. `resilience` default is `0.1`. |
| `retry.JitterMode` | integer | `0` | `0` symmetric (plus or minus), `1` additive (never shortens), `2` flat (adds up to `JitterMax`). |
| `retry.JitterMax` | duration | `0` | Upper bound of the flat jitter draw. Used only when `JitterMode` is `2`. |
| `retry.MaxAttempts` | integer | `1` | Total attempts including the first. `<= 0` means 1. `resilience` default is `3`. |

### Pool sharing

DB-backed services (`db`, `cache`, `queue`, `search`, `session`, `idempotency`, `workflow`, `scheduler`, `vectorstore`, `outbox`) share one container pool per exact DSN by default. Matching is on the trimmed DSN string, so a URL with and without a query string are different pools. SQLite shares by cleaned file path, and `:memory:` never shares.

- The second service to open a DSN borrows the first pool and never closes it. The shared pool takes the first opener's pool settings, and a differing nonzero `max_conns` logs a warning without DSN content.
- Set `dedicated_pool: true` to open a private pool. Use it with a separate database for `queue`, `workflow`, and `scheduler` under sustained load.
- `dedicated_pool` is ignored on `db` itself, which owns the pool.
- Env: `SEARCH_DEDICATEDPOOL=true`, `QUEUE_DSN=...`, `SESSION_DSN=...`.
- Old binaries reject `dedicated_pool` and `dsn` under strict decoding, so remove those lines before a downgrade.

```yaml title="zever.yaml"
search:
  adapter: db
  options:
    dsn: "postgres://app:secret@db:5432/app?sslmode=require"
    dedicated_pool: false
```

Each service lists its adapters, accessor, and every option key. Options form a union across adapters: an adapter reads only the keys it needs and ignores the rest. Keys such as `jwt.secret` are nested under `options`.

### `webhook`

Signed webhook delivery with retries, directly over HTTP or through the queue.

| | |
|---|---|
| Adapters | `http`, `queue` |
| Default adapter | `http` |
| Accessor | `c.Webhook()` |
| Guide | [Webhooks guide](../../guides/background/webhooks/) |

| Key | Type | Default | Description |
|---|---|---|---|
| `timeout` | duration | `10s` | Per-delivery operation timeout |
| `max_retries` | integer | `0` | Number of delivery retries after the initial attempt |
| `allow_private_targets` | boolean | `false` | Permits http(s) targets resolving to private addresses |
| `queue_adapter` | string | `""` | Names the queue adapter backing the queue adapter |
| `dead_letter_topic` | string | `""` | Queue topic for deliveries that exhaust retries |
| `replay_tolerance` | duration | `5m` | Bounds how far a signature's embedded timestamp may drift from the verifier's clock before verification rejects it as expired or replayed, on top of the HMAC check itself |
| `queue_opts` | object |  | Queue settings for the `queue` adapter. See below. |

**`queue_opts`** carries the queue settings for the `queue` adapter. It accepts every [queue](#queue) option (`visibility_timeout`, `poll_timeout`, `buffer`, `addr`, `url`, `prefix`, `dsn`, `table`, `dedicated_pool`, and the Redis connection keys) under the `queue_opts.` prefix.

`Logger` is injected from Go and is not a file option.

```yaml title="zever.yaml"
webhook:
  adapter: http
  options:
    timeout: 10000000000
    max_retries: 5
```

### `workflow`

Durable workflow runs. An empty DSN selects sqlite, a postgres URL selects postgres.

| | |
|---|---|
| Adapters | `memory`, `db`, `postgres` |
| Default adapter | `memory` |
| Accessor | `c.Workflow()` |
| Guide | [Workflows guide](../../guides/background/workflows/) |

| Key | Type | Default | Description |
|---|---|---|---|
| `host_port` | string | `""` | Workflow server address |
| `namespace` | string | `""` | Workflow namespace |
| `dsn` | string | `""` | Postgres connection string |
| `table` | string | `""` | Workflow-runs table name |
| `dedicated_pool` | boolean | `false` | Opts out of container-level pool sharing |

```yaml title="zever.yaml"
workflow:
  adapter: db
  options:
    dsn: postgres://app:secret@db:5432/app
    table: workflow_runs
```
