# Config

Zever reads all service configuration from environment variables. There is **no config file** (`zever.yaml`, `.yml`, `.json` are ignored).

## Resolution order

```
defaults < .env < .env.local < process environment
```

- **defaults**: `config.Default()` — zero-infra adapters (sqlite, slog, stdhttp, memory caches, etc.)
- **`.env`**: project-committed example + local overrides (gitignored)
- **`.env.local`**: machine-local overrides (gitignored, highest priority after process env)
- **process environment**: highest priority, no file I/O

## Env var format

| Instance | Format | Example |
|----------|--------|---------|
| Default | `SERVICE_FIELD` | `DB_ADAPTER=postgres`, `DB_DSN=...` |
| Named | `SERVICE__NAME__FIELD` | `DB__ANALYTICS__DSN=...`, `CACHE__SESSION__ADAPTER=redis` |

Field names are uppercase with underscores. Named instances use double-underscore separator.

## API

```go
// Read from .env + .env.local + process env (no file I/O)
func FromEnv() (Env, error)

// Read specific files (for tests or custom locations)
func LoadEnv(files ...string) (Env, error)

// Resolve env into typed Config
func Resolve(env Env) (*Config, error)

// Apply env to a specific service/instance (used by container wiring)
func ApplyEnv(env Env, service, name string, dst any) error

// List all named instances for a service in env
func InstanceNames(env Env, service string) []string

// Get default Options struct for a service/name (for env template generation)
func DefaultOptions(service, name string) any
```

## Default adapters (zero-infra)

| Service | Default Adapter |
|---------|-----------------|
| db | sqlite |
| cache | memory |
| queue | memory |
| log | slog |
| router | stdhttp |
| ... | (see config.Default()) |

## Migration from v0.7

| v0.7 | v0.8 |
|------|------|
| `zever.yaml` | `.env` + `wiring.go` |
| `config.Load("")` | `config.FromEnv()` |
| `ServiceConfig.Adapter` | wired in `wiring.go` via `container.Provide` |
| `DB_MAXCONNS` | `DB_MAXCONNS` (same) |
| `DB__ANALYTICS__DSN` | `DB__ANALYTICS__DSN` (same format) |
| `zever doctor --config` | `zever doctor` (no flag) |

## Legacy file warning

If `zever.yaml`/`.yml`/`.json` exists in the working directory, `config.FromEnv()` prints a one-line warning:

```
config: zever.yaml found in working directory: ignored; see migration guide in config/README.md
```

The file is **ignored entirely** — no values are read from it.

## Generated env template

`zever new` and `zever add` generate `.env.example` with every env key, default value, and comment. This is the authoritative source for what env vars each service accepts.
