---
title: Minimal runtime profile
description: What the db/orm/router/config/log floor costs versus the full CLI, and how to reproduce the numbers.
---

Minimal profile = smallest data-backed set (`config`, `core/db`, `orm`, `core/router`, `core/log`). Anything else leaves the binary. Not `zever new --profile minimal` (floor plus auth/observability/permission/ratelimit). Counts: [Customizing and leaving](../../guides/extend/customizing-and-leaving/).

## Numbers (2026-10-16)

| Profile | `go list -test -deps` packages | Third-party packages | Binary |
|---|---|---|---|
| Minimal (`config`, `orm`, `core/db`, `core/router`, `core/log`) | 419 | 185 | above 63.3 MB floor (sqlite driver) |
| Full CLI (`cmd/zever` module) | 1706 | 1396 | 309.7 MB |

Counts in this repo. Binaries from [Benchmarks](../benchmarks/) (2026-10-14): full CLI 309.7 MB, slim floor (`--adapters=log,router`) 63.3 MB. The floor (log+router only) lower-bounds the profile: sqlite-backed `db` plus `orm` add the embedded driver and query builder, landing between floor and full CLI. Full CLI is ~4x the package count, ~76% third-party. Savings are excluded transitive deps (pgx, go-redis, fasthttp, otel, cloud SDKs).

## Method

Counts include stdlib and test deps (`-test`):

```sh
# Minimal profile transitive closure (workspace root, sorts and dedups first)
go list -test -deps ./config/... ./orm/... ./core/db/... ./core/router/... ./core/log/... | sort -u | wc -l
# Third-party only: first path element containing a dot (excludes stdlib and the repo itself)
go list -test -deps ./config/... ./orm/... ./core/db/... ./core/router/... ./core/log/... | sort -u | awk -F/ '{print $1}' | grep "\." | wc -l
# Full CLI closure (cmd/zever is its own module)
go -C cmd/zever list -test -deps ./... | sort -u | wc -l
```

Binary sizes:

```sh
go build -o /tmp/zever-full ./cmd/zever && ls -lh /tmp/zever-full
/tmp/zever-full build --adapters=log,router --out /tmp/zever-slim && ls -lh /tmp/zever-slim
```

## Resolve only what you need

```go
import (
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
)

c := container.New(config.Default())
db, err := c.DB()
_ = db
_ = err
```

`container.New` is lazy: untouched services never open. `Close` drains only resolved services, dependents first.
