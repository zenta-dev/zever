---
title: Sessions
description: Server-side sessions over memory or Redis with secure cookies.
---

Sessions are server-side rows behind a cookie: the browser holds an opaque ID, the server holds the data. The facade swaps `memory` and `redis` adapters through configuration.

## Setup

```yaml
session:
  adapter: memory   # local dev: no infrastructure
```

```yaml
session:
  adapter: redis    # production: shared across instances
  options:
    redis:
      addr: redis:6379
```

```go
store, err := c.Session()
if err != nil {
    return err
}
```

`New(nil)` containers and `config.Default()` resolve the memory adapter, so session tests run hermetically with no server.

## The `Store` interface

```go
type Store interface {
    Create(ctx context.Context, ttl time.Duration) (Session, error)
    Get(ctx context.Context, id string) (Session, error)
    Save(ctx context.Context, sess Session) error
    Delete(ctx context.Context, id string) error
    Close() error
}
```

`Create` mints a fresh ID and expiry; a `ttl <= 0` means no expiry. `Get`
returns `ErrNotFound` on a miss or an expired session — the two are
indistinguishable by design. `Session.Data` is a plain `map[string]any` set
directly, not behind an accessor method.

## Reading and writing

```go
func login(ctx context.Context, store session.Store, w http.ResponseWriter) error {
    sess, err := store.Create(ctx, session.DefaultTTL)
    if err != nil {
        return err
    }

    sess.Data["user_id"] = "u_123"
    if err := store.Save(ctx, sess); err != nil {
        return err
    }

    cookie.Set(w, sess.ID, cookie.Options{})
    return nil
}

func loadSession(ctx context.Context, store session.Store, r *http.Request) (session.Session, error) {
    c, err := r.Cookie(cookie.DefaultName)
    if err != nil {
        return session.Session{}, err
    }
    return store.Get(ctx, c.Value)
}
```

| Operation | Purpose |
|---|---|
| `Create(ctx, ttl)` | mint a fresh session; `ttl <= 0` never expires |
| `Get(ctx, id)` | load session by ID; `ErrNotFound` on missing/expired |
| `sess.Data[key] = value` | stage values (user ID, CSRF token, flash) directly on the struct |
| `Save(ctx, sess)` | upsert the row and touch `UpdatedAt` |
| `Delete(ctx, id)` | remove the row; idempotent on missing IDs (logout) |

Keep session payloads small (IDs and flags, not full records) — every request loads the row.

## Cookies

`session.Store` has no knowledge of HTTP — cookie construction is a separate
helper, `session/cookie`, that builds a plain `*http.Cookie` from a session
ID:

```go
import "github.com/zenta-dev/zever/session/cookie"

c := cookie.New(sess.ID, cookie.Options{})
http.SetCookie(w, c)
// or, equivalently:
cookie.Set(w, sess.ID, cookie.Options{})
```

| Attribute | Default |
|---|---|
| `HttpOnly` | `true` (JS never reads the ID) |
| `Secure` | `true` (HTTPS only) |
| `SameSite` | `Lax`; set `Options.SameSite` to `http.SameSiteStrictMode` for high-risk apps |
| `MaxAge` | `0` — a session cookie with no `Max-Age`/`Expires` |

`Secure` and `HTTPOnly` are `*bool` so an explicit `false` (e.g. local HTTP
dev) can be distinguished from "unset, use the secure default."

Rotate the session ID at privilege changes (login, password reset) to block
fixation: `Delete` the old row and `Create` a fresh one.

## Auth vs. session

| Concern | Package | When |
|---|---|---|
| stateless tokens | `auth` (`jwt`, `oidc`) | APIs, mobile, service-to-service |
| server-side rows | `session` (`memory`, `redis`) | browser flows needing revocation |
| bridge | `authz` | verify via `auth`, decide via `permission` |

Use Redis-backed sessions when more than one app instance serves traffic — memory sessions pin users to a single process. Closing follows the container: session stores shut down with everything else in `c.Close(ctx)`.
