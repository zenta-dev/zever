Errors are typed values with stable codes. Handlers match the error, pick a status, and log once — see [Logging](logging/) for the structured-logging half of that pattern.

## Typed errors

`apperror` defines the shared vocabulary with gRPC codes and HTTP mappings, mirrored by the DSL's `ir.ErrorCode` table:

```go
if errors.Is(err, db.ErrNotFound) {
    writeError(w, http.StatusNotFound, "user not found")
    return
}
```

| Pattern | Use |
|---|---|
| sentinel + `errors.Is` | stable branches (`db.ErrNotFound`, `dialect.ErrUnsupportedByDialect`) |
| `%w` wrapping | add context without losing identity |
| `errors.As` for `ClosePanicError` / `CloseTimeoutError` (value types, not pointers) | shutdown diagnostics |
| `orm:` / `orm/render:` prefixes | ORM failures stay greppable and compatible |

`.zen` RPCs declare their error set (`errors: { already_exists }`), so generated OpenAPI and clients know which codes to expect. The `breaking` checker treats error-set changes as API changes.

## Error text never echoes secrets

Error text names services and fields only — values are never echoed, the
same rule [Logging](logging/) and
[Configuration](../getting-started/configuration/) apply to log lines
and displayed config. The CLI follows it too: `zever config show` prints
redacted config, and `migrate` screens mask `--dsn ***`.

Panics in handlers become `500`s via `middleware.Recover`; panics during
`Close` become `ClosePanicError` in the joined shutdown error. Log the
shutdown error once at exit — it already aggregates every service.
