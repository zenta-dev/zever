title: Secrets
description: Named secret storage, separate from layered config.
---

`config` answers "what value does this field have" - defaults, then a file,
then environment overrides, all fine to see in a diff. `secrets` answers a
narrower question: "give me this one named credential, on demand, without it
ever sitting in a YAML file or scrolling past in a log line." They are
deliberately separate services, not two halves of the same one.

## Purpose and when to use

Reach for `secrets` when a credential must not live in `zever.yaml`: API
keys, webhook signing secrets, provider tokens. `config` env overrides are
visible in process listings and dumps; `secrets` reads are scoped to one
name at a time and never logged. `secrets.Options` is already shaped for a
Vault backend (`addr`, `token`, `mount`), GCP Secret Manager
(`project_id`), and AWS (`region`) - but today only one adapter ships:
`env`, which reads `<PREFIX>_<NAME>` variables directly.

## Config

```yaml
secrets:
  adapter: env
  options:
    prefix: ZEVER
```

```sh
SECRETS_PREFIX=ZEVER
ZEVER_STRIPE_KEY=sk_live_...
ZEVER_WEBHOOK_SECRET=whsec_...
```

The `env` adapter requires a non-empty `prefix` (default `ZEVER`); unlike
the no-prefix `<SERVICE>_<FIELD>` service env rule, secret names always
carry the prefix. `prefix` must not contain `/`, `..`, or spaces.

## Resolve

```go
import (
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
)

c := container.New(config.Default())
s, err := c.Secrets()
if err != nil {
	// handle
}
_ = s
```

`Secrets()` resolves lazily like every other accessor. Note the close
shape: `Close(ctx)` takes a context, unlike most services in this table.

## Runnable example

```go
package main

import (
	"context"
	"fmt"
	"os"

	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
)

func main() {
	os.Setenv("ZEVER_DEMO_KEY", "s3cr3t")
	c := container.New(config.Default())
	defer c.Close(context.Background())

	s, err := c.Secrets()
	if err != nil {
		fmt.Println("resolve error:", err)
		return
	}
	ctx := context.Background()

	val, err := s.Get(ctx, "DEMO_KEY")
	if err != nil {
		fmt.Println("get error:", err)
		return
	}
	fmt.Println("bytes:", len(val))

	names, err := s.List(ctx)
	if err != nil {
		fmt.Println("list error:", err)
		return
	}
	fmt.Println("count:", len(names))
	if err := s.Close(ctx); err != nil {
		fmt.Println("close error:", err)
	}
}

// Expected output:
// bytes: 6
// count: 1
```

The value length (not the value) is what you assert on - secret bytes never
belong in stdout. With prefix `ZEVER`, secret `DEMO_KEY` maps to the
`ZEVER_DEMO_KEY` variable exactly.

## Adapters

| Adapter | Package | Notes |
|---|---|---|
| `env` | `secrets/env` | Only adapter shipped today; reads `<PREFIX>_<NAME>` |

## Production notes

- Calling `Set` or `Delete` against the `env` adapter always returns
  `secrets.ErrNotSupported` - it cannot write back to the process
  environment, so it does not pretend to. Runtime rotation needs a future
  Vault or cloud-manager adapter; `Options` unused fields are the seam it
  plugs into without breaking `Options`.
- `ValidateName` rejects names containing `/` or `..`, so a secret name can
  never be used for path traversal against a hierarchical backend (a Vault
  KV mount, for instance) - even though `env` itself has no hierarchy.
- Values never appear in errors; only service and field names do, same
  redaction discipline as `config.RedactedServices`.
- Prefer `secrets` over config env for anything that signs money or auth:
  `payment` `webhook_secret`, `auth` JWT secret, provider keys.

## Troubleshooting

**`Secrets()` fails at startup with a prefix error.**
`prefix` is empty or contains `/`, `..`, or a space. Set `SECRETS_PREFIX`
to a plain namespace like `ZEVER`.

**`Get` reports "not found" for a variable you exported.**
The lookup is `<PREFIX>_<NAME>` exactly. With prefix `ZEVER`, name
`DEMO_KEY` needs `ZEVER_DEMO_KEY` - check the prefix matches and the name
case matches.

**`Set` always fails.**
That is the contract for `env`: read-only by design. Store the value in
the environment (or a process manager) instead of writing at runtime.
