---
title: Resilience
description: Circuit breaker, bulkhead, timeout, and retry composed per dependency, in-process or distributed over Redis.
---

## Purpose

Use `resilience` to stop a failing dependency from taking down your process.
A `Manager` hands out named per-dependency `Guard` values; each guard wraps
every call in a fixed policy chain so one bad dependency gets a timeout, a
bounded retry budget, a circuit that opens under sustained failure, and a
bulkhead that caps how many calls run at once. The bookings payment path
uses this shape: one guard per external dependency (`payments`, `fraud`),
so a slow fraud check trips its own breaker instead of exhausting the HTTP
server's goroutines.

## When to use

Stay on `memory` (the default) for a single instance: every policy is
process-local and needs no infrastructure. Switch to `redis` the moment
more than one replica calls the same dependency, because only the
circuit-breaker state is meaningful to share, replicas that see the same
failure ratio should trip together instead of each burning its own retry
budget. Timeout, retry, and bulkhead stay process-local in both adapters.

Compose policies in the fixed order `Timeout -> Retry -> Breaker ->
Bulkhead -> fn`, outermost to innermost. The timeout therefore governs the
whole operation including retries: a 5s timeout with 3 attempts bounds the
entire call, not each attempt.

Error classification is caller-aware: `context.Canceled` and
`context.DeadlineExceeded` are excluded from breaker counts and never
retried, so a client hanging up does not count against the circuit. Business
errors that should not trip the breaker (a validation rejection, say) are
classified as success through `BreakerOptions.IsSuccessful`.

## Config

File decoding is strict snake_case; durations in files are integer
nanoseconds. `retry` is an untagged `retry.Policy`, so its file keys are
case-insensitive Go field names (`maxattempts`), not snake_case, prefer
setting it in Go via `resilience.Default()`.

```yaml
resilience:
  adapter: memory
  options:
    timeout: 5000000000 # 5s default, bounds the whole operation
    breaker:
      enabled: true
      max_requests: 1 # half-open probe allowance
      interval: 30000000000 # closed-state counting window
      bucket_period: 10000000000 # rolling-window bucket width
      timeout: 30000000000 # open-state duration before a probe
      min_requests: 10 # minimum requests before the ratio trip applies
      failure_ratio: 0.5 # failure ratio in [0,1] that trips
      consecutive_failures: 5 # consecutive-failure trip threshold
    bulkhead:
      max_concurrent: 100 # <= 0 disables the bulkhead
      max_queue: 100 # waiter bound; <= 0 unbounded
      max_wait: 1000000000 # admission wait budget; <= 0 waits for ctx
```

Distributed breaker state across replicas:

```yaml
resilience:
  adapter: redis
  options:
    breaker:
      enabled: true
    redis:
      addr: 127.0.0.1:6379
      prefix: resilience # key namespace; default "resilience"
      pool_size: 20
      min_idle_conns: 2
      pool_timeout: 5000000000
```

Env (no prefix, `<SERVICE>_<FIELD>`):

```sh
RESILIENCE_ADAPTER=redis
RESILIENCE_TIMEOUT=5000000000
RESILIENCE_BREAKER_ENABLED=true
RESILIENCE_BULKHEAD_MAXCONCURRENT=100
```

`Validate` rejects negative timeouts and bulkhead budgets, retry jitter
outside `[0, 1]`, breaker ratios outside `[0, 1]`, and a bad Redis prefix.
The redis adapter pings at construction (3s budget) and fails closed when
Redis is unreachable.

## Resolve via container

```go
import (
    "github.com/zenta-dev/zever/adapters/resilience/inproc"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
)

func openManager() error {
    inproc.Register()

    c := container.New(config.Default())
    m, err := c.Resilience()
    if err != nil {
        return err
    }
    defer m.Close()
    _ = m
    return nil
}
```

`Resilience()` resolves lazily on first use and caches the manager. On
error the cached state clears so the next call retries. `Guard(name)`
lazily creates each named guard from the template `Options`; the same name
always returns the same guard. `Guard.Close` and `Manager.Close` are
idempotent; the container closes only resolved services.

## Runnable example

```go
package main

import (
    "context"
    "fmt"

    "github.com/zenta-dev/zever/adapters/resilience/inproc"
    "github.com/zenta-dev/zever/config"
    "github.com/zenta-dev/zever/container"
    "github.com/zenta-dev/zever/core/resilience"
)

func main() {
    inproc.Register()

    c := container.New(config.Default())
    m, err := c.Resilience()
    if err != nil {
        panic(err)
    }
    defer m.Close()

    g, err := m.Guard("payments")
    if err != nil {
        panic(err)
    }

    v, err := resilience.Do(context.Background(), g, func(context.Context) (string, error) {
        return "ok", nil
    })
    fmt.Println(v, err)
}
```

Expected output (default zero-infra config is the process-local adapter):

```text
ok <nil>
```

`resilience.Do` is the typed helper over `Guard.Execute`: it runs `fn`
under the guard and returns its result, so callers avoid the error-only
closure `Execute` requires. Branch on the sentinels with `errors.Is`:
`ErrOpenState` (breaker open), `ErrTooManyRequests` (half-open probe
limit), `ErrBulkheadFull` (no slot within the wait budget), `ErrTimeout`
(overall budget exceeded), `ErrClosed` (guard or manager closed).

## Adapters

| Adapter | Package | Notes |
|---|---|---|
| `memory` | `adapters/resilience/inproc` | Default; every policy process-local |
| `redis` | `adapters/resilience/redis` | Distributed breaker state via Redis; timeout/retry/bulkhead stay process-local |

Both serve the same `resilience.Manager` interface. The redis adapter
shares breaker state under `redis.prefix` so independent replicas trip
together; `ErrNoSharedState` reports missing or unreadable shared state.
Live redis behavior is covered by tests gated behind `REDIS_ADDR`.

## Production notes

- Close semantics: `Manager.Close() error` with no context (instant-close
  shape). Container closes only resolved services and joins errors via
  `errors.Join`; panics become `*ClosePanicError`.
- Multi-instance behavior: `memory` breakers do not coordinate, so each
  replica trips on its own view of the dependency. Move to `redis` when
  replicas must share one circuit per dependency.
- Redaction: guard names and options carry no credentials, but never log
  raw option maps; use `config.RedactedServices`.
- Tune per dependency, not globally: the template `Options` apply to every
  guard the manager creates, so open one manager per dependency class (or
  accept that a fast local cache and a slow remote API share thresholds).
- `Default()` enables every policy with bounded values (5s timeout, 3
  attempts, 100 concurrent, 1s admission wait), a safe starting point,
  not a tuning endpoint.

## Troubleshooting

1. Breaker never opens under load: `failure_ratio`/`min_requests` assume a
   meaningful request volume. Low-traffic dependencies trip on
   `consecutive_failures` instead; lower it for fast-failing dependencies.
2. Calls fail with `ErrTimeout` before the dependency's own deadline: the
   guard timeout wraps retries, so `timeout` must exceed
   `base_delay * attempts` plus the dependency's latency, or lower
   `max_attempts`.
3. `ErrBulkheadFull` under burst: `max_concurrent` is too low for the
   replica's capacity, or `max_wait` is shorter than a slot frees up.
   Raise `max_concurrent` before raising `max_queue`, an unbounded queue
   turns a burst into a latency bomb.
4. Redis adapter fails to open: the constructor pings Redis with a 3s
   budget and fails closed. Check `addr` and that the prefix is unique per
   environment; shared prefixes share breaker state across environments.
