Every battery has a runnable, zero-infrastructure example under `examples/`. Most run with `go test ./examples/...`. The larger apps (`showcase`, `todo`, `bookings`, `demoapp`, `external-sms`) are separate Go modules, so build and test them from their own directory or by path.

New to Zever? Do [Build a booking API](../build-a-booking-api/) first for one realistic flow, then [Explore the showcase app](../explore-the-showcase-app/) for DSL breadth. Then pick focused ORM ports by the query problem you have.

## Full apps

| App | What it proves |
|---|---|
| `examples/bookings` | Marketplace domain (hosts list spaces, guests book them), walked through in [Build a booking API](../build-a-booking-api/). `payment` stub charges, `billing`, `geo`, `media`, `search`, and `vectorstore` compose in one realistic request flow, with worker jobs and a cron schedule. |
| `examples/showcase` | DSL depth: every schema feature in one shop schema, HTTP and gRPC parity, walked through in [Explore the showcase app](../explore-the-showcase-app/). One `Service` implementation backs two transports with identical auth. |
| `examples/demoapp` | Battery breadth: every service battery behind one HTTP API. The container resolves the full service set in one process, and adapter swaps stay config-only. |
| `examples/todo` | Auth-gated notes app with HTTP and gRPC parity tests. JWT auth is enforced identically on both transports, and parity tests catch drift. |

## Focused ORM ports

Each app proves one ORM feature end to end against sqlite.

| App | What it proves |
|---|---|
| `examples/transactions` | `orm.WithNestedTx` savepoint-nested transfers: a failed inner transfer rolls back to its savepoint without aborting the outer transaction. |
| `examples/bulk_upsert` | Multi-row `Insert`, `OnConflict(...).DoUpdate/DoNothing`, `Returning().ExecReturning`: bulk writes stay one round trip and conflicts resolve per row. |
| `examples/pagination` | Offset paging (`Limit`/`Offset`/`Count`) and keyset paging (`AfterTuple`, cursor encode/decode): stable traversal with and without concurrent inserts. |
| `examples/recursive_cte` | `orm.WithRecursive`: an org chart in one query, with no N+1. |
| `examples/json_query` | `orm/json/sqlite` nested-key, key-exists, and array-membership filters with typed predicates. |
| `examples/fts` | `orm/fts/sqlite` full-text `MATCH` with rank-ordered search on the zero-infra adapter. |
| `examples/ormdrill` | Cursors, preload, joins, subqueries, and expressions without codegen (the raw builder), for queries too dynamic for generated code. |

Every service battery (`cache`, `queue`, `db`, `payment`, `ai`, `vectorstore`, and the rest listed in the [Config reference](../../reference/config/)) also has at least one `ExampleXxx` test against its zero-infra adapter, showing one happy path and one error path through `// Output:` comments. Browse them under `examples/<battery>/`. The test is the documentation.

## Run the examples

```sh
# examples that live in the `examples` module
go test ./examples/...        # zero infra, no setup needed
go test -race ./examples/...  # with the race detector

# the separate full-app modules, from the repo root (workspace-aware)
go test ./examples/showcase/...
go test ./examples/todo/...
go test ./examples/bookings/...

# one focused port
go test ./examples/pagination/... -v
```

Expected output:

```text
ok  github.com/zenta-dev/zever/examples/pagination  0.05s
ok  github.com/zenta-dev/zever/examples/fts         0.03s
ok  github.com/zenta-dev/zever/examples/transactions 0.04s
...
```

Names and times vary. The signal is `ok` on every line and no `FAIL`.

To see an adapter swap, opt into postgres:

```sh
DB_ADAPTER=postgres DB_DSN=postgres://user:pass@localhost:5432/test?sslmode=disable go test ./examples/pagination/...
```

The queries pass unchanged against a second dialect. Where a feature has no postgres mapping, assertions fail closed with `dialect.ErrUnsupportedByDialect`: a documented boundary, not a broken test. Unset, every example uses the [`config.Default()`](../../guides/operate/configuration/) zero-infra defaults.

## Set up the full apps

Both seeds are idempotent: re-running prints the same lines without duplicating rows.

```sh
cd examples/bookings
zever db migrate --adapter=sqlite --dsn=data/bookings.db schema/bookings.zen
go run ./db/seed
```

```text
applied 4 tables to data/bookings.db
seeded host host@example.com
seeded guest guest@example.com
```

```sh
cd ../showcase
zever db migrate --adapter=sqlite --dsn=data/showcase.db schema/shop/shop.zen
go run ./db/seed
```

```text
applied 8 tables to data/showcase.db
seeded demo shop data
```

<Aside type="caution" title="JWT secret required">
Both servers require `AUTH_JWT_SECRET` of at least 32 bytes and fail closed without it.
</Aside>

## How an example is laid out

<Steps>

1. `schema/*.zen` (full apps only) holds the domain. Never hand-edit `generated/` next to it.
2. `zever.yaml` lists explicit zero-infra adapters. Its diff against `config.Default()` is the deploy surface.
3. `db/seed` holds idempotent demo data.
4. `cmd/server` and `cmd/worker` are entrypoints mirroring `zever generate server` / `zever generate worker`.
5. Tests sit next to the code they cover. The `// Output:` comments are runnable claims, not prose.

</Steps>

## Troubleshooting

<details>
<summary>`go test ./examples/...` fails on a clean clone</summary>

Cause: a half-downloaded module cache, which all modules share. Fix: run `go mod download`, then re-run.
</details>

<details>
<summary>A postgres-backed run fails to connect</summary>

Cause: the server is down, the database is missing, or the DSN is wrong. Fix: use the form `postgres://user:pass@localhost:5432/test?sslmode=disable`, confirm the server and database, or unset the vars to fall back to sqlite.
</details>

<details>
<summary>Tests drifted after a schema edit</summary>

Cause: generated code is stale. Fix: regenerate with `zever compile` (see the showcase tutorial) and re-run `zever db migrate --dry-run` for fresh DDL. Never hand-edit `generated/`.
</details>
