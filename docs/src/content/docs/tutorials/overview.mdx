`examples/` holds runnable, zero-infrastructure apps. Most run with `go test ./examples/...`. Larger apps (`showcase`, `todo`, `bookings`, `demoapp`, `external-sms`) are separate modules. Build and test them by path.

New? Do [Build a booking API](../build-a-booking-api/) first, then [Explore the showcase app](../explore-the-showcase-app/).

## Full apps

| App | What it proves |
|---|---|
| `examples/bookings` | Marketplace (hosts list spaces, guests book them). See [Build a booking API](../build-a-booking-api/). `payment` stub, `billing`, `ratelimit`, `idempotency`, `lock`, `queue` in one request. |
| `examples/showcase` | DSL depth in one shop schema, HTTP and gRPC parity. See [Explore the showcase app](../explore-the-showcase-app/). |
| `examples/demoapp` | Every service battery behind one HTTP API. Adapter swaps stay config-only. |
| `examples/todo` | Auth-gated notes app with HTTP and gRPC parity. JWT enforced identically on both. |

## Focused ORM ports

Each proves one ORM feature end to end against sqlite.

| App | What it proves |
|---|---|
| `examples/transactions` | `orm.WithNestedTx` savepoints: failed inner transfer rolls back to its savepoint. |
| `examples/bulk_upsert` | Multi-row `Insert`, `OnConflict(...).DoUpdate/DoNothing`, `Returning().ExecReturning` in one round trip. |
| `examples/pagination` | Offset (`Limit`/`Offset`/`Count`) and keyset (`AfterTuple`, cursors) paging with concurrent inserts. |
| `examples/recursive_cte` | `orm.WithRecursive`: org chart in one query, no N+1. |
| `examples/json_query` | `orm/json/sqlite` nested-key, key-exists, array-membership filters. |
| `examples/fts` | `orm/fts/sqlite` full-text `MATCH` with rank-ordered search. |
| `examples/ormdrill` | Cursors, preload, joins, subqueries, expressions without codegen. |

Every service battery (`cache`, `queue`, `db`, `payment`, `ai`, `vectorstore`, rest in [Config reference](../../reference/config/)) has `ExampleXxx` tests against its zero-infra adapter (happy + error path in `// Output:`). See `core/<battery>/example_test.go`.

## Run the examples

```sh
# examples that live in the `examples` module
go test ./examples/...        # zero infra, no setup needed
go test -race ./examples/...  # with the race detector

# the separate full-app modules, from the repo root (workspace-aware)
go test ./examples/showcase/...
go test ./examples/todo/...
go test ./examples/bookings/...

# one focused port
go test ./examples/pagination/... -v
```

Expected output:

```text
ok  	github.com/zenta-dev/zever/examples/pagination/cmd/app	0.008s
ok  	github.com/zenta-dev/zever/examples/fts/cmd/app	0.010s
ok  	github.com/zenta-dev/zever/examples/transactions/cmd/app	0.004s
...
```

Signal: `ok` on every line, no `FAIL`. Focused ports open sqlite directly, no adapter key needed. For postgres: `POSTGRES_DSN='postgres://user:pass@localhost:5432/test?sslmode=disable' go test ./orm/...`. Missing dialect features fail closed with `dialect.ErrUnsupportedByDialect`.

## Set up the full apps

```sh
cd examples/bookings
zever db migrate --adapter=sqlite --dsn=data/bookings.db schema/bookings.zen
go run ./db/seed
```

```text
OK applied 8 statement(s) via sqlite
{"time":"...","level":"INFO","msg":"seed complete"}
```

```sh
cd ../showcase
zever db migrate --adapter=sqlite --dsn=data/showcase.db schema/shop/shop.zen
go run ./db/seed
```

```text
OK applied 16 statement(s) via sqlite
{"time":"...","level":"INFO","msg":"seed complete"}
```

<Aside type="caution" title="JWT secret required">
Both servers require `AUTH_JWT_SECRET` (≥32 bytes) and fail closed without it. Seed/worker output is JSON log lines (the `slog` adapter).
</Aside>

## How an example is laid out

<Steps>

1. `schema/*.zen` (full apps only): the domain. Never hand-edit `generated/`.
2. `wiring.go`: explicit typed providers.
3. `db/seed`: idempotent demo data. `cmd/server`/`cmd/worker` mirror `zever generate server` / `zever generate worker`.
4. Tests sit next to covered code. `// Output:` comments are runnable claims.

</Steps>

## Troubleshooting

<details>
<summary>`go test ./examples/...` fails on a clean clone</summary>

Half-downloaded module cache. Fix: `go mod download`, then re-run.
</details>

<details>
<summary>A postgres-backed run fails to connect</summary>

Server down, database missing, or wrong DSN. Fix: confirm server/database, or unset vars to fall back to sqlite.
</details>

<details>
<summary>Tests drifted after a schema edit</summary>

Generated code is stale. Fix: `zever compile` (see showcase tutorial), `zever db migrate --dry-run` for fresh DDL. Never hand-edit `generated/`.
</details>
