Every battery in this framework has a runnable example under `examples/` in
the repository — no separate module, no extra setup: `go test
./examples/...` covers all of them with zero infrastructure. Two tutorials
in this section walk you through the two most complete apps step by step;
this page is the map of everything else.

There is deliberately no separate Go module under `examples/`: they live in
the main module so `internal/` packages stay importable and the whole tree
builds and tests as one unit. If you need a heavier dependency for your own
experiment, isolate it behind its own `go.mod` the way a real add-on would.

## Per-battery examples (Stage 1)

Every service battery — `cache`, `queue`, `db`, `payment`, `ai`,
`vectorstore`, and every other one listed in [Config
Reference](/zever/reference/config-reference/) — has at least one
`ExampleXxx` test against its zero-infra adapter, each showing one happy
path and one error path via `// Output:` comments. Browse them under
`examples/<battery>/` in the repository; the test itself is the
documentation, so `go doc` or reading the source is the fastest way in.

## Running the examples

```sh
go test ./examples/...        # everything, zero infra, no setup needed
go test -race ./examples/...  # with the race detector
```

Some examples opt into a real backend via environment variables when you
want to see the adapter swap in action, for example:

```sh
DB_ADAPTER=postgres DB_DSN=postgres://... go test ./examples/...
```

Unset, every example runs against the zero-infra defaults from
[`config.Default()`](/zever/getting-started/configuration/) — no database,
no Redis, no external service required.
