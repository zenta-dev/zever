Runtime never imports `dsl`: the compiler emits Go source once. Services import only generated output, the container, adapters. Linking the frontend would bloat every binary and let request-time code special-case schema logic.

## The compile-time pipeline

```text
source text -> lexer -> parser -> ast -> resolver -> ir.Schema
                                     -> compile -> backend outputs
```

Compile-time above. Runtime takes only its output (typed ORM, routes, gRPC stubs). The compiler reads schema files and backend flags, never env config.

- **Syntax** `diag`, `token`, `lexer`, `ast`, `parser`: bytes -> tree (never panics, depth guard, recovery).
- **Resolve** `naming`, `resolver`, `ir`: `[]*ast.File` -> `*ir.Schema` (keep-going diagnostics).
- **Emit** `format`, `breaking`, `compile`, `backend`: formatter, `Change` taxonomy, sorted build, `Backend` interface.
- **Grammars** `dsl/gengrammar` via `tools/gengrammar`: renders `editors/{nvim,vscode}`.
- **Runtime** `container`, `config`, `orm`, adapters: load, resolve, query, close.
- **Tooling** `cmd/zever`, `tools/zever-lsp`: CLI and editor support (LSP own module).

## Compile, then run

```sh
zever check schema/todo.zen
zever fmt -l schema/todo.zen
zever compile schema/todo.zen --backend=zenorm,openapi,atlas --out generated
zever db migrate --dry-run --adapter=sqlite schema/todo.zen
go run ./examples/todo/cmd/server -addr :8080
```

The server imports `generated/` and resolves via the container, never `dsl` ([Container](../container/)). `check` validates, `fmt -l` lists unformatted files, `compile` emits there, `migrate --dry-run` previews SQL.

Entry points: `parser.New(file, src).ParseFile()` then `resolver.Resolve(files)`, or `compile.Compile(files, backends...)`. Canonical fixture `compile/testdata/app.zen`. Never hand-edit `generated/`. After touching `token.Keywords` or `resolver.ScalarTypeNames`, run `make generate` (`go run ./tools/gengrammar`).

## Design decisions

Top-level `dsl` escapes Go's `internal/` visibility. Accidental imports fail review.

## Troubleshooting

<details>
<summary>`go build` fails importing `dsl`</summary>

Runtime package reached the compiler. Drop the import. Use `generated/`.
</details>

<details>
<summary>cross-module references in `check-boundaries`</summary>

A relation, RPC return type, or permission resource crosses `.zen` module dirs. The resolver rejects it. Move it inside one module ([Zen syntax](../../reference/zen-syntax/)).
</details>

<details>
<summary>`compile` prints diagnostics but writes no output</summary>

Resolve errors block backends (schema errors from `.zen`, service errors from `config.FromEnv`). Fix the `.zen` position. Run `zever check`.
</details>

<details>
<summary>Editor misses new keywords after grammar change</summary>

`token.Keywords` or `resolver.ScalarTypeNames` changed. Run `make generate`. Commit `editors/`.
</details>

<details>
<summary>Edits in `generated/` vanish</summary>

Compile overwrites `generated/`. Edit the `.zen` source.
</details>
