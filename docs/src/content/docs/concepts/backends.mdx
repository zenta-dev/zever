Backends are the codegen extension point: each turns a resolved `*ir.Schema` into files (bindings, protobuf, OpenAPI, migration HCL). They emit scaffolding, not behavior. Business logic and adapter wiring stay hand-written.

## The mental model

The `backend` package holds only the interface. `compile.Compile` parses filename-sorted inputs, resolves once, then calls each `Generate` in order.

```go
type Backend interface {
    Name() string
    Generate(schema *ir.Schema) (map[string][]byte, error)
}
```

Backends read only `*ir.Schema` and take no config struct. `--backend` filters which `Generate` runs. The default is `gogen, zenorm, atlas, openapi`, with `proto` and `protogogen` auto-added only when services exist, and `mcp` stays opt-in.

## Run the backends

```sh
zever compile --out ./generated
zever compile --backend=atlas,gogen,mcp,openapi,proto,protogogen,zenorm --out ./generated
ls ./generated
```

One subtree per backend under `./generated`. Run `zever check schema/` first because backends assume a resolved schema.

## The seven backends

| Backend | Reads | Emits |
|---|---|---|
| `zenorm` | `schema.Modules[*].Entities` only | Typed table and column bindings |
| `gogen` | Modules and services | Application layer (handlers, wiring) |
| `proto` | Modules, enums, RPCs | Protobuf descriptors |
| `protogogen` | Modules, enums, RPCs | `zever.app.v1` protobuf and `gen/zever/app` Go |
| `openapi` | Services and HTTP bindings | OpenAPI document |
| `atlas` | Modules and entities | Atlas HCL migrations, one per module |
| `mcp` | Services | MCP tool manifests (JSON Schema in/out) plus a runnable stdio server with handler stubs |

The canonical `app.zen` fixture exercises the first six: both entities compile under the virtual path `schema/app/app.zen` (module `app`), so `User <-> Order` needs no import and services never affect zenorm output.

`dsl/naming` converts names per target (`APIKey` to `api_key` in Postgres and SQLite table names, acronym runs stay one word). SQL binds args and quotes identifiers. Dialect gates live with the ORM.

## API documents and client SDKs

The `openapi` backend emits an OpenAPI 3.0.3 document. `proto` plus `protogogen` emit the protobuf contract for gRPC. Zever ships no client-SDK generator: feed those artifacts to your language's generator (`openapi-generator`, `oapi-codegen`, or `openapi-typescript` over `generated/openapi`. `buf generate` or `protoc` with the language plugin over `generated/proto`). Both regenerate and drift-check via `zever compile --check`, keeping clients in step.

## Keep output deterministic

| Rule | Why |
|---|---|
| Sort map keys before rendering | Go map order is random per run |
| Pin timestamps (no clock reads) | Same bytes every run |
| Repo-relative output paths | Outputs diff cleanly across machines |
| One subtree per backend | `--backend=` filtering stays trivial |
| No network or unseeded randomness | Hermetic codegen |

## Write a backend

1. Implement `Backend` with a stable `Name()`.
2. Read only `*ir.Schema`, never re-parse source.
3. Return a path-to-bytes map (repo-relative paths, deterministic rendering). Implement `ContextBackend` (`GenerateContext`) only for cancellable I/O.
4. Add a golden test in `dsl/backend/<name>/` with committed output.

Golden workflow: edit `.zen`, `zever check`, `compile`, then review the full golden diff as the executable spec. Accept with `-update` only after review:

```sh
go test ./dsl/backend/gogen/ -run TestGoldenFiles -update
```

Unrelated golden churn means a backend leaks non-determinism.

## Design decisions and trade-offs

- Never hand-edit `generated/`: the next compile overwrites it. Fix the `.zen` source.
- Pin `--backend=...` in CI so a new backend cannot change outputs silently.
- Keep backends pure: environment specifics belong in adapter options.

## Troubleshooting

<details>
<summary>Generated output changed unexpectedly</summary>

A schema edit or keyword change. Diff the committed goldens, then revert or accept with `-update` after review.
</details>

<details>
<summary>A backend is missing from the output</summary>

A misspelled `--backend=` filter. Use lowercase: `atlas`, `gogen`, `mcp`, `openapi`, `proto`, `protogogen`, `zenorm`.
</details>

<details>
<summary>CI shows non-deterministic diffs</summary>

A backend iterates a map without sorting or embeds a timestamp. Sort keys and pin times.
</details>

<details>
<summary>`protogogen` fails running `protoc-gen-go-grpc`</summary>

It shells out to `go tool protoc-gen-go-grpc`, which needs working `go.mod` and `go.sum`. Run `go mod tidy`, then compile again.
</details>

<details>
<summary>`Generate` errors on an unknown type</summary>

The schema failed binding. Run `zever check` first.
</details>
