The frontend turns source text into a resolved `*ir.Schema` plus every diagnostic in one run: debug schema errors or feed a backend here. Runtime packages never import `dsl`.

## The pipeline

```text
source text → lexer → parser → ast → resolver → ir.Schema
                                    ↘ compile → backend outputs
```

Inputs are `[]*ast.File` plus a backend list with deterministic filename-sorted output. No config file.

Package roles live in the [compiler boundary](../compiler-boundary/#the-compile-time-pipeline) table. Notes: `lexer` never panics (fuzz-tested), `parser` recovers per declaration (depth guard), `format` refuses lex-dirty input (idempotent), `ir` carries the gRPC-canonical `ErrorCode` table.

## Parse and resolve a schema

Parse first, or run the full path:

```go
f, parseDiags := parser.New("schema/app/app.zen", src).ParseFile()
schema, diags := resolver.Resolve([]*ast.File{f})
```

```go
// files maps path to source; Result.Outputs maps backend name to files.
res, diags := compile.Compile(files, backends...)
```

The resolver runs ordered, keep-going passes:

1. **Modules and symbols.** Group files into modules by directory and index entities, enums, messages, services, jobs, schedules, sagas by name. Duplicates are diagnostics, not panics.
2. **Bind types.** Resolve enums, entities, message fields against scalars and declared types. Unknown names diagnose and continue.
3. **Relations and indexes.** Verify both sides of `has_many` / `belongs_to` agree on the foreign key. Resolve indexes.
4. **Services and RPCs.** Validate HTTP templates against params, `@validate` expressions, and the `ErrorCode` table.
5. **Jobs, schedules, sagas.** Bind them to their services and jobs.

Canonical fixture `compile/testdata/app.zen` with committed golden outputs. Regenerate explicitly (`-update` after review, taken by the gogen, atlas, proto, and zenorm tests). To see the pipeline end to end:

```sh
go test ./dsl/backend/gogen/ -run TestGoldenFiles -v
```

Expected output:

```text
--- PASS: TestGoldenFiles (0.00s)
PASS
ok  	github.com/zenta-dev/zever/dsl/backend/gogen
```

The test parses, resolves, runs `gogen`, and diffs goldens. `-update` only after deliberate fixture changes.

## Read the IR

`ir.Schema` is the backend contract: read `schema.Modules[*].Entities`, never re-parse source (`zenorm` ignores services entirely).

| IR element | Contents |
|---|---|
| `Schema.Modules` | Resolved modules keyed by directory-derived name |
| Module entities | Bound field types, primary/unique/default metadata |
| Module services | Bound RPC signatures with HTTP/auth bindings |
| `ErrorCode` table | gRPC-canonical codes shared by all backends |
| `Change` taxonomy | Additive vs breaking schema diffs |

## Catch breaking changes in CI

`breaking` diffs old vs new schemas. Wire into CI so removed fields or renamed RPCs fail builds before clients break:

```sh
zever breaking schema-old/*.zen -- schema/*.zen
```

The shape is `zever breaking <old-files...> -- <new-files...>`. Each side takes files, globs, or bare directories (`.zen` discovered recursively). Any breaking change exits non-zero and gates directly. `--json` emits `changes` plus a `breaking` count. Additions and new `@validate` rules are informational (exit zero).

| Change class | Examples | CI posture |
|---|---|---|
| Additive | New entity, field, RPC, `@validate`. `@renamed_from` renames | Pass (reported as informational) |
| Breaking | Removed entity, field, RPC (renaming an RPC counts as a removal). Changed field type, optionality, params, return type, HTTP method or path | Exit non-zero, fail the build |

GitHub workflow diffing the PR schema against `main`:

```yaml
- name: Check for breaking schema changes
  run: |
    mkdir -p /tmp/old-schema
    git fetch origin main --depth=1
    for f in schema/*.zen; do
      git show origin/main:"$f" > "/tmp/old-schema/$(basename "$f")" 2>/dev/null || true
    done
    zever breaking /tmp/old-schema -- schema
```

## Design decisions and trade-offs

- After touching `token.Keywords` or `resolver.ScalarTypeNames`, run `make generate`: editor grammars derive from those tables via `tools/gengrammar`, and a parity test fails the build on drift.
- Fuzz tests run seed corpora as unit tests. Add seeds for new syntax.

## Troubleshooting

<details>
<summary>Resolve reports an unknown type</summary>

No scalar or entity declares it in scope. Check module paths.
</details>

<details>
<summary>A relation mismatch diagnostic appears</summary>

The two sides disagree on the foreign key column. Align both `@foreign_key(...)` spellings.
</details>

<details>
<summary>A golden test fails after a grammar change</summary>

Keywords or scalars changed. Re-run with `-update`, review, then `make generate`.
</details>

<details>
<summary>The schema is empty with no diagnostics</summary>

Inputs were not parser-produced `[]*ast.File`, or nothing parsed.
</details>
