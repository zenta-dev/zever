The container is the only object that knows how adapters are constructed, cached, retried, and closed. One `container.New(cfg, providers...)` per process gives lazy first use and dependency-ordered close.

## The mental model

```text
New(cfg, providers...)  ->  accessor() or Get(c, ref)  ->  cached instance
one per process             lazy first use                                             retry on error
                                                           clear on failure
```

No globals and no `init()` wiring. `New(nil)` is valid; `Close(ctx)` never opens anything. Display config with `config.RedactedServices`, never raw option maps.

## Wire services with typed providers

Every service instance is one `Ref` bound to one adapter by one `container.Provide` call. `db.DefaultRef()` names the default instance, `db.Ref("analytics")` names a second one.

```go
import (
	dbsqlite "github.com/zenta-dev/zever/adapters/db/sqlite"
	"github.com/zenta-dev/zever/container"
	"github.com/zenta-dev/zever/core/db"
)

var DB = db.DefaultRef()

func Providers() []container.Provider {
	return []container.Provider{container.Provide(DB, dbsqlite.New)}
}

c := container.New(cfg, Providers())
```

`cfg` is the `*config.Config` you resolved from the environment; `nil` is valid too. `container.Get(c, DB)` resolves any wired ref. The accessors (`c.DB()`, `c.Cache()`) resolve the default instance when a provider covers it, and otherwise fall back to the config-based path. Graph validation runs at `New`: duplicate refs, missing non-`Optional` dependencies, and cycles surface from `Get` as `DuplicateRefError`, `NotWiredError`, and `DependencyCycleError`.

## Where the adapter and the options come from

The `Provide` call names the adapter: the factory it binds is the implementation that opens. The options come from the environment. `config.DefaultOptions(service, name)` seeds a fresh typed Options value, `<SERVICE>_<FIELD>` overlays one field at a time (a named instance reads `<SERVICE>__<NAME>__<FIELD>`), and `container.WithOptions` appliers run last, so explicit options win over env ([Config reference](../../reference/config/#db)).

A container built with a config and no providers takes the config-based path instead: every accessor resolves its service from the config and from the battery registry, and the adapter is the one `<SERVICE>_ADAPTER` names (`DB_ADAPTER=postgres`). Adapters register caller-side through each battery's core registry (`adapters/<battery>/<name>` calls `Register()`), and resolving an unregistered adapter fails with `UnknownAdapterError` naming the missing `Register` call. `cmd/zever` registers every adapter at startup, so CLI behavior is unchanged. Prefer `Provide` for new code.

## Resolve services

Call the accessors to resolve. Each returns one cached instance and retries after a failure.

- `DB()`: plus `Transactor()`
- `Cache()`, `Queue()`: leaves, closed after dependents and snapshots
- `Job()`: dispatcher over resolved `Queue`, no registry
- `Scheduler()`: shares `Queue` via `Job()`, closed first
- `EventBus()`: `Eventbus()` alias
- `RateLimit()`: `Ratelimit()` alias
- `GRPC(opts...)`: lazy `*grpc.Server`, no registry
- `GRPCClient(target, opts...)`: gRPC client connection
- `Router()`: `fiber` or `stdhttp` driver
- `Log()`: outermost middleware
- `AI()`: API key required, no keyless default
- `Agent()`, `RAG()`: over `AI` (and `VectorStore` for `RAG`)

The rest share the service name:

```text
Analytics() Auth() Billing() Crypto() Document() Flag() Geo() I18n()
Idempotency() Lock() Mailer() Media() Notification() Observability()
Outbox() Password() Payment() Permission() Resilience() Search()
Secrets() Session() Storage() Tenant() VectorStore() Webhook() Workflow()
```

## Share one queue across jobs and the scheduler

`Job()` builds a dispatcher over the already-resolved queue. `Scheduler()` injects that dispatcher, so no redundant connections open. Resolving `Scheduler()` resolves `Job()` and `Queue()` as a side effect.

## Close services in order

- **Wired instances** (every `Ref` passed to `Provide`): first, in reverse dependency order, so a dependent shuts down before the backend it borrowed.
- **Dependents** (`scheduler`, `job`, `agent`, `rag`; they hold backend refs): next.
- **Snapshots** (everything without explicit ordering): middle.
- **Leaves** (`cache`, `queue`): next.
- **Shared pools** (`db` and registry pools, after every borrower), then plugin services.
- **Independent** (`grpcServer` via `GracefulStop`, forced `Stop` when ctx ends; gRPC client connections): last.

The container probes each service's shutdown shape in order: `Close(context.Context) error`, `Close() error`, `Stop() error`, `Shutdown(context.Context) error`, then no-op (for example `*job.Dispatcher`).

- `Close(ctx) error`: pooled or blocking services (`db`, `cache`, `storage`, `lock`).
- `Close() error`: lightweight or in-memory adapters (`auth`, `queue`, `session`, `payment`).
- `Stop() error`: scheduler cron only.
- `Shutdown(ctx) error`: observability providers (flush spans and metrics).
- none: stateless adapters (`crypto`, `log`, `password`, `permission`, `router`).

## Design decisions and trade-offs

A 5s per-service bound applies without a parent deadline; shared instances close once (pointer-identity dedup), failures join with `errors.Join`, and error values name the service only.

## Troubleshooting

<details>
<summary>An accessor errors on the first call only</summary>

A transient failure cleared the cache. Retry; investigate only if it repeats.
</details>

<details>
<summary>`Close` reports a timeout for one service</summary>

That adapter exceeded its bound. Give the parent a deadline or fix its `Close`.
</details>

<details>
<summary>`errors.As` for `ClosePanicError` never fires</summary>

Both close error types are values. Declare `var pe container.ClosePanicError` and pass `&pe`.
</details>

<details>
<summary>A service seems to close twice</summary>

A shared instance reached through two paths. Dedup closes it once.
</details>

<details>
<summary>The leak checker fails after adding a service</summary>

An adapter goroutine outlives `Close` (`go test -tags=leak ./container/`). Stop it in `Close`.
</details>
