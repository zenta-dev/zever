The container owns adapter construction, caching, retry, and close: one `container.New(cfg, providers...)` per process, lazy first use, dependency-ordered close.

## The mental model

```text
New(cfg, providers...)  ->  accessor() or Get(c, ref)  ->  cached instance
one per process             lazy first use                                             retry on error
                                                           clear on failure
```

No globals or `init()`. `New(nil)` is valid, `Close(ctx)` opens nothing. Display config only via `config.RedactedServices`.

## Wire services with typed providers

Each instance is one `Ref` bound to one adapter by one `Provide` call: `db.DefaultRef()` the default, `db.Ref("analytics")` a second.

```go
import (
	dbsqlite "github.com/zenta-dev/zever/adapters/db/sqlite"
	"github.com/zenta-dev/zever/container"
	"github.com/zenta-dev/zever/core/db"
)

var DB = db.DefaultRef()

func Providers() []container.Provider {
	return []container.Provider{container.Provide(DB, dbsqlite.New)}
}

c := container.New(cfg, Providers())
```

`cfg` is the `*config.Config` resolved from the environment. `container.Get(c, DB)` resolves any wired ref. Accessors (`c.DB()`, `c.Cache()`) resolve the default instance when a provider covers it, else fail with `NotWiredError` naming the missing `container.Provide` entry. Graph validation at `New`: duplicate refs, missing non-`Optional` dependencies, and cycles surface from `Get` as `DuplicateRefError`, `NotWiredError`, and `DependencyCycleError`.

## Where the adapter and the options come from

The `Provide` factory picks the adapter. The environment picks the options. `config.DefaultOptions(service, name)` seeds typed `Options`, `<SERVICE>_<FIELD>` overlays fields (named instances read `<SERVICE>__<NAME>__<FIELD>`), `container.WithOptions` appliers run last ([Config reference](../../reference/config/#db)).

Config without providers resolves nothing: every accessor needs a `container.Provide` entry, else `NotWiredError` names the fix. Adapters are plain imports (`adapters/<battery>/<name>`), never registrations. `cmd/zever` wires every battery default, so CLI behavior works out of the box.

## Resolve services

Accessors return one cached instance and retry after failure.

- `DB()`: plus `Transactor()`
- `Cache()`, `Queue()`: leaves, closed after dependents and snapshots
- `Job()`: dispatcher over resolved `Queue`, no registry
- `Scheduler()`: shares `Queue` via `Job()`, closed first
- `EventBus()`: `Eventbus()` alias
- `RateLimit()`: `Ratelimit()` alias
- `GRPC(opts...)`: lazy `*grpc.Server`, no registry
- `GRPCClient(target, opts...)`: gRPC client connection
- `Router()`: `fiber` or `stdhttp` driver
- `Log()`: outermost middleware
- `AI()`: API key required, no keyless default
- `Agent()`, `RAG()`: over `AI` (and `VectorStore` for `RAG`)

The rest share the service name:

```text
Analytics() Auth() Billing() Crypto() Document() Flag() Geo() I18n()
Idempotency() Lock() Mailer() Media() Notification() Observability()
Outbox() Password() Payment() Permission() Resilience() Search()
Secrets() Session() Storage() Tenant() VectorStore() Webhook() Workflow()
```

## Share one queue across jobs and the scheduler

`Job()` builds a dispatcher over the already-resolved queue, so no redundant connections open. Resolving `Scheduler()` also resolves `Job()` and `Queue()`, so one connection serves both.

## Close services in order

- **Wired instances** (every `Ref` passed to `Provide`): first, in reverse dependency order, so a dependent shuts down before the backend it borrowed.
- **Dependents** (`scheduler`, `job`, `agent`, `rag`): next.
- **Snapshots** (everything without explicit ordering): middle.
- **Leaves** (`cache`, `queue`): next.
- **Shared pools** (`db` and registry pools, after every borrower), then plugin services.
- **Independent** (`grpcServer` via `GracefulStop`, forced `Stop` when ctx ends, gRPC client connections): last.

The container probes each shutdown shape in order: `Close(context.Context) error`, `Close() error`, `Stop() error`, `Shutdown(context.Context) error`, else no-op (for example `*job.Dispatcher`).

- `Close(ctx) error`: pooled or blocking services (`db`, `cache`, `storage`, `lock`).
- `Close() error`: lightweight or in-memory (`auth`, `queue`, `session`, `payment`).
- `Stop() error`: scheduler cron only.
- `Shutdown(ctx) error`: observability providers (flush spans, metrics).
- none: stateless adapters (`crypto`, `log`, `password`, `permission`, `router`).

## Design decisions and trade-offs

No parent deadline means a 5s bound per service. Shared instances close once (pointer-identity dedup). Failures join via `errors.Join`. Errors name the service only.

## Troubleshooting

<details>
<summary>An accessor fails once, then succeeds</summary>

Transient failure cleared the cache. Retry. Investigate only on repeats.
</details>

<details>
<summary>`Close` reports a timeout for one service</summary>

That adapter exceeded its bound. Give the parent a deadline or fix its `Close`.
</details>

<details>
<summary>`errors.As` for `ClosePanicError` never fires</summary>

Both close error types are values. Declare `var pe container.ClosePanicError` and pass `&pe`.
</details>

<details>
<summary>A service seems to close twice</summary>

A shared instance reached through two paths. Dedup closes it once.
</details>

<details>
<summary>The leak checker fails after adding a service</summary>

An adapter goroutine outlives `Close` (`go test -tags=leak ./container/`). Stop it in `Close`.
</details>
