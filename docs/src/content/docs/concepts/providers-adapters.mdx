Every backend concern is one small interface with several adapters, resolved only by the container. Changing `sqlite` to `postgres` or `memory` to `redis` stays a wiring and env edit, never a handler rewrite.

## The mental model

| Role | Rule |
|---|---|
| Interface | Stays small. Never add methods (it breaks implementers); add a new interface instead. |
| Adapter | One subdirectory per backend, bound to a `Ref` by `container.Provide`. |
| Container | Sole resolver; owns construction, caching, retry, and close. |
| Config | Feeds the options (`DB_MAX_CONNS=20`), and names the adapter on the config-based path (`DB_ADAPTER=postgres`). |

Application code speaks the interface; the container speaks the typed providers:

```go
conn, err := c.DB() // the wired db instance, built once and cached
```

Each battery still keeps a `Register`/`Open` registry, which the config-based path resolves an adapter name against:

```go
// Package db: one small interface.
type DB interface {
	Query(ctx context.Context, query string, args ...any) (Rows, error)
	Exec(ctx context.Context, query string, args ...any) (int64, error)
	Ping(ctx context.Context) error
	Close(ctx context.Context) error
	Dialect() string
}

// Adapter sqlite registers itself; postgres registers itself elsewhere.
// Call Register once from main (no init magic); app code holds no globals.
func Register() { _ = db.Register(db.SQLite, New) }
```

## Swap an adapter

Development uses zero infrastructure; production changes the wiring and the env, never the call sites:

```sh
zever add cache/redis
```

That edits `internal/app/wiring.go`: the `cache` `Ref` binds the redis adapter now, and `.env.example` gains the keys the new adapter reads. The env then carries that adapter's options:

```sh
DB_DSN=postgres://app:secret@db:5432/app
DB_MAX_CONNS=20
CACHE_ADDR=redis:6379
```

Env names carry no prefix: the default instance reads `<SERVICE>_<FIELD>` (`DB_MAX_CONNS=20`), and a named instance reads `<SERVICE>__<NAME>__<FIELD>` (`DB__PRIMARY__MAX_CONNS=20`) but only reaches the container through a matching named Ref such as `db.Ref("primary")`. `<SERVICE>_ADAPTER` names the adapter on the config-based path, the one a container built with a config and no providers takes; a wired instance opens the adapter its `container.Provide` call binds. Handlers keep calling `c.DB()` and `c.Cache()`. `zever doctor` reports per-service health. Under zero-infra defaults, the bookings example documents expected FAILs (missing API key, JWT secret, cities file, embed FS): config gaps, not framework bugs.

Most swaps are invisible to handlers: placeholders stay `?` on both `db` drivers (postgres rewrites to `$n` before pgx) and route params read through `router.Param`. Where backends differ, the adapter fails fast or documents the gap. Two known gaps:

- `MinConns` is a pool minimum on postgres but `SetMaxIdleConns` on sqlite.
- Regex route constraints exist on fiber but not stdhttp.

## Pick from the adapter matrix

An excerpt follows. The full table covers all 37 services from `ai` to `workflow`, each with a default adapter (zero-infra except `ai`): see the [adapters matrix](../../reference/adapters-matrix/).

| Service | Adapters | Default |
|---|---|---|
| `db` | `sqlite`, `postgres` | `sqlite` |
| `cache` | `memory`, `redis`, `db` | `memory` |
| `queue` | `memory`, `redis`, `db` | `memory` |
| `router` | `fiber`, `stdhttp` | `stdhttp` |
| `auth` | `jwt`, `session`, `oidc` | `jwt` |
| `session` | `memory`, `redis`, `db` | `memory` |
| `storage` | `local`, `s3`, `r2` | `local` |
| `search` | `db`, `meilisearch` | `db` |
| `vectorstore` | `db`, `qdrant` | `db` |
| `payment` / `billing` | `stub`, `stripe`, `paddle` | `stub` |
| `log` | `noop`, `zerolog`, `slog`, `pretty` | `slog` |
| `secrets` | `env`, `vault` | `env` with `ZEVER` prefix |

The `search`, `vectorstore`, and `workflow` services take `db` as their DB-backed adapter: the DSN decides the backend, so an empty or sqlite DSN selects the embedded SQLite one and a postgres URL selects PostgreSQL. The older `postgres`, `sqlite`, and `pgvector` names for those services are gone.

## Add a new adapter

1. Implement the existing interface exactly: no extra exported methods on the facade.
2. Parse options with typed readers and return `InvalidOptionsError` on unparsable values.
3. Never log raw option maps; expose redaction through `Redact` / `RedactedServices`.
4. Make shutdown cheap and idempotent: implement `Close(ctx)`, `Close()`, or `Stop()` so the container's probing finds it.
5. Keep tests hermetic (sqlite `:memory:`, in-memory fakes) and gate live tests behind env such as `POSTGRES_DSN`.

Unexported adapter structs are named `driver` with receiver `d`; timeouts are `time.Duration` with `Default*Timeout` constants.

## Design decisions and trade-offs

- **Close shape is a provider contract.** See [Container](../container/#close-services-in-order) for which signature each adapter takes.
- **Fail closed.** Unsupported ORM features return `dialect.ErrUnsupportedByDialect` (prefixed `orm:`) instead of wrong SQL, strict config rejects unknown keys at load, and redaction masks secrets everywhere.

## Troubleshooting

<details>
<summary>The swap changes nothing at runtime</summary>

Cause: the wiring still binds the old adapter, or an env override (`CACHE_ADAPTER`) beats the default on the config-based path. Fix: check the `container.Provide` line in `internal/app/wiring.go`, then unset or correct the env variable.
</details>

<details>
<summary>An accessor fails with `UnknownAdapterError`</summary>

Cause: on the config-based path, a typo in the adapter name (config accepts any non-empty name), or its `Register()` was never called. Fix: match the matrix spelling (`postgres`, not `postgresql`) and register the adapter module before resolving.
</details>

<details>
<summary>A handler sees different SQL on postgres</summary>

Cause: a misunderstanding of the placeholder rewrite. Fix: keep writing `?`; the postgres driver rewrites to `$n` before pgx.
</details>

<details>
<summary>A fiber-only route constraint breaks stdhttp</summary>

Cause: regex constraints exist on fiber only. Fix: restructure the route using constructs both drivers share, or pin `fiber`.
</details>

<details>
<summary>A live adapter test fails in CI</summary>

Cause: the test needs a real backend but no DSN is set. Fix: gate it behind env (`POSTGRES_DSN='postgres://user:pass@localhost:5432/test?sslmode=disable'`).
</details>
