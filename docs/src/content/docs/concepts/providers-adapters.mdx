Every backend concern is one small interface with several adapters, resolved only by the container. Changing `sqlite` to `postgres` or `memory` to `redis` stays a config edit, never a handler rewrite.

## The mental model

| Role | Rule |
|---|---|
| Interface | Stays small. Never add methods (it breaks implementers); add a new interface instead. |
| Adapter | Self-registers; one subdirectory per backend. |
| Container | Sole resolver; owns construction, caching, retry, and close. |
| Config | Selects the adapter (`DB_ADAPTER=postgres`) plus options. |

Application code speaks the interface; the container speaks the registry:

```go
conn, err := db.Open(db.SQLite, db.Options{Path: ":memory:"})
```

Each package follows one pattern:

```go
// Package db: one small interface.
type DB interface {
	Query(ctx context.Context, sql string, args ...any) (Rows, error)
	Exec(ctx context.Context, sql string, args ...any) (Result, error)
	Dialect() string
}

// Adapter sqlite registers itself; postgres registers itself elsewhere.
// Call Register once from main (no init magic); app code holds no globals.
func Register() { _ = db.Register(db.SQLite, New) }
```

## Swap an adapter with config

Development uses zero infrastructure; production changes names only:

```yaml title="zever.yaml"
# dev: zero infra
db:
  adapter: sqlite
  options:
    path: data/app.db
cache:
  adapter: memory
queue:
  adapter: memory
```

```yaml title="zever.yaml"
# prod: same code, real backends
db:
  adapter: postgres
  options:
    dsn: postgres://app:secret@db:5432/app
    max_conns: 20
cache:
  adapter: redis
  options:
    addr: redis:6379
```

Env equivalents use `<SERVICE>_<FIELD>` with no prefix: `DB_ADAPTER=postgres`, `DB_MAXCONNS=20`, `CACHE_ADAPTER=redis`. Handlers keep calling `c.DB()` and `c.Cache()`; register the adapter module for the name you choose. `zever doctor --config zever.yaml` reports per-service health. Under zero-infra defaults, the bookings example documents expected FAILs (missing API key, JWT secret, cities file, embed FS): config gaps, not framework bugs.

Most swaps are invisible to handlers: placeholders stay `?` on both `db` drivers (postgres rewrites to `$n` before pgx) and route params read through `router.Param`. Where backends differ, the adapter fails fast or documents the gap. Two known gaps:

- `MinConns` is a pool minimum on postgres but `SetMaxIdleConns` on sqlite.
- Regex route constraints exist on fiber but not stdhttp.

## Add a new adapter

1. Implement the existing interface exactly: no extra exported methods on the facade.
2. Parse options with typed readers and return `InvalidOptionsError` on unparsable values.
3. Never log raw option maps; expose redaction through `Redact` / `RedactedServices`.
4. Make shutdown cheap and idempotent: implement `Close(ctx)`, `Close()`, or `Stop()` so the container's probing finds it.
5. Keep tests hermetic (sqlite `:memory:`, in-memory fakes) and gate live tests behind env such as `POSTGRES_DSN`.

Unexported adapter structs are named `driver` with receiver `d`; timeouts are `time.Duration` with `Default*Timeout` constants.

## Design decisions and trade-offs

- **Close shape is a provider contract.** See [Container](../container/#close-services-in-order) for which signature each adapter takes.
- **Fail closed.** Unsupported ORM features return `dialect.ErrUnsupportedByDialect` (prefixed `orm:`) instead of wrong SQL, strict config rejects typos at load, and redaction masks secrets everywhere.

## Troubleshooting

<details>
<summary>The swap changes nothing at runtime</summary>

Cause: an env override (`CACHE_ADAPTER`) beats the file. Fix: unset or correct the env variable.
</details>

<details>
<summary>`Load` rejects a known adapter name</summary>

Cause: a typo, or the adapter is not registered. Fix: match the matrix spelling (`postgres`, not `postgresql`).
</details>

<details>
<summary>A handler sees different SQL on postgres</summary>

Cause: a misunderstanding of the placeholder rewrite. Fix: keep writing `?`; the postgres driver rewrites to `$n` before pgx.
</details>

<details>
<summary>A fiber-only route constraint breaks stdhttp</summary>

Cause: regex constraints exist on fiber only. Fix: restructure the route using constructs both drivers share, or pin `fiber`.
</details>

<details>
<summary>A live adapter test fails in CI</summary>

Cause: the test needs a real backend but no DSN is set. Fix: gate it behind env (`POSTGRES_DSN='postgres://user:pass@localhost:5432/test?sslmode=disable'`).
</details>
