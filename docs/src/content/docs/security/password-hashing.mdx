## Purpose

Hashing a password wrong builds a real vulnerability: a weak cost
parameter, a non-constant-time comparison, a missing salt. `password`
exists so the decision is made once per framework, not per project: it
hashes, verifies, and reports whether a stored hash needs rehashing, all
through Argon2id with safe out-of-box parameters.

When to use: store and check user credentials at register/login. When not
to use: token issuance is `auth`, encryption is `crypto`; `password`
issues nothing and stores nothing.

## Prerequisites

- `argon2id` is the only adapter, so no adapter-choice call; the choice is
  whether to touch tuning parameters (mostly, do not).
- Benchmarks on production-class hardware before any retune.
- Rate limiting on login endpoints (hashing cost is not attempt limiting).

## Config

```yaml
password:
  adapter: argon2id
  options:
    time: 1
    memory: 65536
    threads: 4
```

```sh
PASSWORD_ADAPTER=argon2id
```

Defaults come from the package tuned constants: `Time` 3 iterations,
`Memory` 65536 KiB (64 MiB), `Threads` 4, `SaltLen` 16 bytes, `KeyLen` 32
bytes.

## Resolve

```go
c := container.New(config.Default())
pw, err := c.Password()
if err != nil {
    // handle: config invalid or adapter unavailable
}
```

## Runnable example

Hash at register, verify at login, rehash when parameters moved on:

```go
hash, err := pw.Hash(ctx, "correct horse battery staple")
if err != nil {
    return err
}
ok, err := pw.Verify(ctx, hash, "correct horse battery staple")
if err != nil {
    return err
}
_ = ok
rehash, err := pw.NeedsRehash(ctx, hash)
if err != nil {
    return err
}
_ = rehash
```

Expected output:

```text
hash: $argon2id$v=19$m=65536,t=3,p=4$<salt>$<key>
ok: true
rehash: false (true after a cost-parameter bump; re-hash on next login)
```

Stored form is PHC: `$argon2id$v=19$m=MEMORY,t=TIME,p=THREADS$SALT$HASH`.
Salts come from `crypto/rand` and comparisons run constant-time by
construction. Passwords over 1024 bytes are rejected outright rather than
hashed; a malformed stored hash returns the `ErrInvalidHash` sentinel,
checked with `errors.Is`, not string comparison.

Retune procedure when costs must change:

1. Benchmark candidate params on production-class hardware.
2. Deploy the new params; old hashes keep verifying untouched.
3. On each successful login, `NeedsRehash` flags stale hashes.
4. Re-hash the presented plaintext with new params and persist.
5. Track the stale-hash ratio until it reaches zero, then decommission.

| Verify outcome | Meaning | Action |
|---|---|---|
| `true, nil` | match | proceed; rehash if flagged |
| `false, nil` | mismatch | reject login, generic error |
| `_, ErrInvalidHash` | stored value corrupt | force password reset |

## Reference

| Adapter | Package | Notes |
|---|---|---|
| `argon2id` | `password/argon2` | default; sole hasher |

| Method | Role |
|---|---|
| `Hash` | salt + hash a plaintext password |
| `Verify` | constant-time check of plaintext vs. stored hash |
| `NeedsRehash` | true when stored params lag current tuning |

| Constant | Value |
|---|---|
| `Time` | 3 iterations |
| `Memory` | 65536 KiB (64 MiB) |
| `Threads` | 4 |
| `SaltLen` | 16 bytes |
| `KeyLen` | 32 bytes |
| Max plaintext | 1024 bytes, rejected above |

## Production notes

- Hashing cost makes each guess expensive; it does not shrink the
  attacker's guessing budget. Rate-limit login separately.
- Retune only against benchmarks on production-class hardware; a number
  picked on a laptop can land too cheap against real attacker economics.
- On a cost bump, re-hash transparently: when `NeedsRehash` returns true
  at a successful login, hash the presented plaintext with new params and
  persist.
- Never log plaintext passwords or hashes; error text names the failure,
  never the value.

## Troubleshooting

- **`ErrInvalidHash` on a known account**: the stored value is truncated
  or corrupted. Check with `errors.Is`, then force a password reset.
- **Logins slow to a crawl**: cost parameters exceed what the fleet
  sustains. Benchmark and lower toward defaults; scale horizontally first.
- **`NeedsRehash` true for every user**: parameters changed since hashes
  were minted. Re-hash on next successful login per account.
- **Password rejected over length**: plaintext exceeds 1024 bytes. Reject
  at the boundary with a clear validation error before hashing.
