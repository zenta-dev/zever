---
title: Password Hashing
description: Argon2id hashing with tuned defaults for secure credential storage.
---

Hashing a password wrong is a surprisingly easy way to build a real
vulnerability — a weak cost parameter, a non-constant-time comparison, a
missing salt. `password` exists so you never make that decision per project:
it hashes, verifies, and checks whether a stored hash needs rehashing, all
through Argon2id, with parameters tuned to safe values out of the box. `auth`
calls it on the verification path; `password` itself issues nothing and
doesn't store anything — it's pure hashing, not a user store.

`argon2id` is the only adapter, so there's no adapter-choice call to make here
— the choice that matters is whether to touch the tuning parameters at all
(mostly, don't).

## Config

```yaml
password:
  adapter: argon2id
  options:
    time: 1
    memory: 65536
    threads: 4
```

```sh
PASSWORD_ADAPTER=argon2id
```

Defaults come straight from the package's tuned constants: `Time` 3
iterations, `Memory` 65536 KiB (64 MiB), `Threads` 4, `SaltLen` 16 bytes,
`KeyLen` 32 bytes.

## Resolve

```go
c := container.New(config.Default())
pw, err := c.Password()
if err != nil {
	// handle
}
_ = pw
```

## Hashing cost isn't rate-limiting, and retuning needs real benchmarks

Argon2id's memory/time cost makes each individual guess expensive — it does
not make an attacker's overall guessing budget small. Without a rate limit on
your login endpoint, someone can still throw thousands of attempts at it over
time; hashing cost and rate-limiting are two separate defenses, not
substitutes for each other. Salts come from `crypto/rand` and comparisons run
constant-time, both by construction — don't hand-roll either. Passwords over
1024 bytes are rejected outright rather than hashed, and a malformed or
corrupted stored hash returns the bare `ErrInvalidHash` sentinel — check for it
with `errors.Is`, not a string comparison. If you do retune the cost
parameters, do it against benchmarks on production-class hardware, not a
laptop — the whole point of Argon2id's cost is calibrated to real attacker
economics, and a number picked without measurement can land too cheap.
