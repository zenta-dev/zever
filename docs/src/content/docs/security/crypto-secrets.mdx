## Purpose

Services that store something sensitive - a session token, a webhook
payload, a field unreadable straight out of the database - need one place
to encrypt and sign that is not hand-rolled per call site. `crypto.Crypto`
is that place, and because `config.Default()` ships a deterministic dev
key, tests exercise real encryption with no setup.

When to use: encrypt/sign payloads and fields at rest or in transit. When
not to use: password storage is `password` (one-way hashing), and named
credentials (API keys, connection strings) are `secrets` - resolved
independently.

## Prerequisites

- A real key for any non-dev environment (file or env); the default key is
  dev-only and public by construction.
- `secrets` env prefix understood (`ZEVER` default) for named credentials.
- Redaction discipline: raw option maps never reach logs.

## Config

```yaml
crypto:
  adapter: local
  options:
    key: MDEyMzQ1Njc4OTAxMjM0NTY3ODkwMTIzNDU2Nzg5MDE=
```

```sh
CRYPTO_KEY=prod-base64-key-here
```

`local` is the only adapter today, so no adapter choice exists; the key is
the decision. Named secrets use the `env` adapter with a required
non-empty prefix (default `ZEVER`):

```yaml
secrets:
  adapter: env
  options:
    prefix: ZEVER
```

```sh
export ZEVER_STRIPE_KEY=sk_test_example
export ZEVER_DB_PASSWORD=example-only
```

`ZEVER_STRIPE_KEY` maps to secret `STRIPE_KEY`; the prefix requires a
trailing-underscore boundary and rejects empty, slash, `..`, or spaced
values at `Open`.

## Resolve

```go
c := container.New(config.Default())
cr, err := c.Crypto()
if err != nil {
    // handle: key missing or malformed
}
sec, err := c.Secrets()
if err != nil {
    // handle: prefix invalid
}
```

## Runnable example

Set a prod key, resolve, and read a named secret:

```sh
export CRYPTO_KEY=prod-base64-key-here
export ZEVER_STRIPE_KEY=sk_test_example
go run ./cmd/myapp
echo exit:$?
```

Expected output:

```text
crypto: resolved with the env key (no key material in logs)
secrets: STRIPE_KEY resolves to the exported value
exit:0
```

With `config.Default()` and no env, resolution still succeeds but uses the
deterministic dev key: correct for tests, never for prod. `CRYPTO_KEY`
never appears in logs or errors once set.

Key rotation procedure for stored fields:

1. Generate the new key from a CSPRNG; inject via env at deploy.
2. Dual-read: decrypt with old key, re-encrypt with new key, persist.
3. Track the old-key row count until it reaches zero.
4. Remove the old key from config; verify decrypts still succeed.

Audit note: list which fields are encrypted and under which key generation
in one place (migration runbook, not code comments). A field nobody can
name is a field nobody rotates.

## Reference

| Service | Adapter | Package | Notes |
|---|---|---|---|
| `crypto` | `local` | `crypto/local` | only adapter; dev key built in |
| `secrets` | `env` | `secrets/env` | only adapter; prefix `ZEVER` default |

| Prefix rule | Behavior |
|---|---|
| `ZEVER_FOO` | maps to secret `FOO` |
| Empty prefix | rejected at `Open` |
| Slash / `..` / spaces | rejected at `Open` |
| Trailing `_` | boundary separator, added if missing |

## Production notes

- The default key is the same for everyone who has ever run
  `config.Default()`, which makes it as public as this page. Supply a real
  key via file or environment before deploying; anything encrypted under
  the dev key is recoverable by anyone who read these docs.
- Generate keys from a CSPRNG, store them in a secret manager, inject via
  env at deploy. Rotate by re-encrypting stored fields under the new key.
- `crypto` and `secrets` solve different problems: opaque payload crypto
  vs. named credential lookup. Resolve and audit both.
- Never log raw option maps; display via `RedactedServices` / `Redact`.
  Error text names services and fields only, values never echoed.

## Troubleshooting

- **Prod resolves but decrypts old rows to garbage**: rows were encrypted
  under a different key (often the dev key). Re-encrypt under the prod key
  during migration.
- **Secrets lookup misses**: the env name lacks the prefix or the boundary
  underscore (`STRIPE_KEY` vs `ZEVER_STRIPE_KEY`). Export with the full
  prefixed name.
- **`Open` rejects the secrets prefix**: empty, or contains slash, `..`,
  or spaces. Set a simple alphanumeric prefix such as `ZEVER`.
- **Key material in logs**: some path logs raw options. Route all display
  through `RedactedServices` / `Redact` and remove the direct log call.
