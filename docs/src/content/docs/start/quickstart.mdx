Then run `zever --version`.

## Scaffold

```sh
zever new hello
cd hello
```

Writes `schema/app.zen`, `cmd/server/main.go`, `internal/app/wiring.go`, sample `internal/service/hello`, `.env`, `.env.example`, `.gitignore`, `README.md`. Runs `go mod tidy`, builds as-is.

Expected output (abridged):

```text
✔ scaffolded "hello" into hello
  wrote hello/internal/app/wiring.go
  wrote hello/cmd/server/main.go
  wrote hello/internal/service/hello/service.go
```

Add services via `--with` (comma list, optional pins): `zever new hello --with cache,queue=redis,auth` (`--interactive` prompts). See [Customizing and leaving Zever](../../guides/extend/customizing-and-leaving/).

## Serve

```sh
zever dev
```

```text
{"time":"...","level":"INFO","msg":"http server listening","addr":":8080"}
```

`zever dev` watches and restarts. `zever serve` runs once. Second terminal:

```sh
curl -i localhost:8080/hello
```

```text
HTTP/1.1 200 OK
Content-Type: application/json

{"hello":"world"}
```

Registers `GET /hello`, logger from container. `GET /healthz` → 200. `GET /readyz` → 200 after DB ping.

## What you built

Typed wiring: one `Ref` + one `container.Provide` per service in `internal/app/wiring.go`. `cmd/server/main.go` passes providers + modules to `serve.Main`. Add later:

```sh
zever add cache/redis
zever add db --name analytics
```
