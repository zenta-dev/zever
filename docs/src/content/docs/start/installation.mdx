## Install CLI

<Steps>
1. Check tools: `go version && git --version`
2. Install `zever` + `zever-lsp` (pinned):

   <Tabs syncKey="os">
   <TabItem label="Linux">
   ```sh
   curl -fsSL https://raw.githubusercontent.com/zenta-dev/zever/main/install.sh | sh
   ```
   </TabItem>
   <TabItem label="macOS">
   ```sh
   curl -fsSL https://raw.githubusercontent.com/zenta-dev/zever/main/install.sh | sh
   ```
   </TabItem>
   <TabItem label="Windows">
   ```powershell
   irm https://raw.githubusercontent.com/zenta-dev/zever/main/install.ps1 | iex
   ```
   </TabItem>
   </Tabs>

   Binaries: `~/.local/bin`. Add to `PATH` if missing.
   <Aside type="caution" title="Windows execution policy">`Unblock-File install.ps1` or `-ExecutionPolicy Bypass`.</Aside>
3. Run `zever --help`.
</Steps>

<details>
<summary>Installer notes</summary>

Re-running the installer upgrades in place. An older install asks for confirmation before it moves forward. Re-running the same version skips with no changes. A downgrade from a newer install asks for confirmation too. Non-interactive shells need `--yes`.

Output has colour on a terminal. Pass `--quiet` (`-Quiet` on Windows) for errors only. Pass `--no-color` (`-NoColor`) or set `NO_COLOR` to turn colour off. `TERM=dumb` turns colour off as well. `zever-lsp` always matches the CLI version because it has no version flag of its own.

Every binary is checked against the release `SHA256SUMS.txt`. When no SHA-256 tool (`sha256sum` or `shasum`) is present, or hashing fails, the installer aborts instead of installing unverified binaries. To proceed unverified, pass `--insecure-skip-verify` (`-InsecureSkipVerify` on Windows) or set `ZEVER_INSTALL_INSECURE=1`.
</details>

## Add modules

```sh
go mod init example.com/myapp
go get github.com/zenta-dev/zever/config@v0.8.0 github.com/zenta-dev/zever/container@v0.8.0 github.com/zenta-dev/zever/adapters/db/sqlite@v0.8.0
```

<details>
<summary>`go install` for CLI</summary>

v0.7.2+ only: `go install github.com/zenta-dev/zever/cmd/zever@vX.Y.Z`. Earlier needs `replace`/installer. `cmd/zever` only.
</details>

## Smoke test

```go title="main.go" check
package main

import (
	"fmt"

	dbsqlite "github.com/zenta-dev/zever/adapters/db/sqlite"
	"github.com/zenta-dev/zever/config"
	"github.com/zenta-dev/zever/container"
	"github.com/zenta-dev/zever/core/db"
)

func main() {
	c := container.New(config.Default(), container.Provide(db.DefaultRef(), dbsqlite.New))
	db, err := c.DB()
	if err != nil {
		panic(err)
	}
	fmt.Println("db resolved:", db != nil)
}
```

```sh
go build ./... && go test ./... && go run .
```

Expect `db resolved: true`. The three commands prove fetch, build, and default resolution work. `container.New(nil)` stays valid ([configuration](../../guides/operate/configuration/)).

## Upgrade / Uninstall

```sh
zever upgrade        # or --check, --version vX.Y.Z
zever uninstall      # or --keep-lsp, --dry-run
```

## Production notes

- Pin CLI to modules.
- Never log raw maps. Use `config.RedactedServices(cfg)`.
- `config.Default()` uses a dev crypto key. Use env secrets.
- Close via `c.Close(ctx)` + timeout.

## Troubleshooting

<details>
<summary>`go version` < 1.27.3</summary>
Install from [go.dev/dl](https://go.dev/dl/).
</details>
<details>
<summary>`go get` fails</summary>
Check `GOPROXY`. `go mod download`. Retry.
</details>
<details>
<summary>`make setup` fails</summary>
Re-run `make setup`, check the tools are on `PATH`, then run `make build`.
</details>
<details>
<summary>`zever` not found</summary>
Add `~/.local/bin` to `PATH` or re-run installer.
</details>
<details>
<summary>`go install` replace error</summary>
Use v0.7.2+ or installer/release binary.
</details>
<details>
<summary>Smoke test panics on `DB()`</summary>
Clear `.env`/`.env.local` and env overrides.
</details>
